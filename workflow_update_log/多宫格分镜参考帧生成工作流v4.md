# 多宫格分镜参考帧生成工作流（v4：真实文件名引用与表情控制修正版）

## 1. 目标

用于指导大模型基于用户提供的简单 idea，逐步生成一组多宫格分镜参考帧，支持 **N=4 / 9 / 16 / 25**。

核心目标：

- 分镜剧情连续；
- 镜头切换丝滑连贯；
- 人物、场景、道具保持一致性；
- 相邻帧在人物位置、动作、视线、道具状态、场景交互上有明确变化；如需表现情绪变化，再控制面部表情，不强制每帧写表情；
- 每帧 prompt 简洁、明确、可直接复制到 Qwen-Image 使用；
- 每次最多参考两张图像；
- 最终输出的帧生成 prompt 必须是**一段式 prompt**，其中同时包含“怎么参考”和“分镜描述”。

---

## 2. 适用范围

默认适用于：

- 动画感 / 国风 / 3D 动画风格参考帧；
- 单人物、单场景优先；
- 用户输入一个 idea 和宫格数量 N；
- 用户逐帧上传生成结果，模型检查后继续生成下一帧 prompt。

若用户没有说明人物和场景数量，模型应自动根据 idea 给出**满足剧情的最少人物数和最少场景数**。优先单人物、单场景，除非剧情必须增加角色或场景。

---

## 3. 总体流程

### Step 1：接收用户输入

用户通常输入：

- 一个简单 idea；
- 目标宫格数 N，取值为 4 / 9 / 16 / 25；
- 可选：风格、人物数量、场景数量、特殊道具或关键动作。

### Step 2：输出整体策划

首次响应时，模型需要输出：

1. 视频段落概述；
2. 最少人物与场景数量安排；
3. 资源库构建 prompt；
4. N 帧分镜规划；
5. 只给出 `case_frame01.png` 的一段式生成 prompt。

不要一次性给出所有帧的详细生成 prompt，只给当前要生成的一帧。

### Step 3：用户生成并上传当前帧

用户上传 `case_frame0x.png` 后，模型必须先质检：

- 合格：给出下一帧的一段式 prompt；
- 不合格：指出问题并给出当前帧重生成的一段式 prompt，不进入下一帧。

---

## 4. 资源库构建规则

资源库用于锁定人物、场景和必要道具的一致性。

### 4.1 命名规则

- 人物图：`case_char_01.png`，如有多人物则 `case_char_02.png`
- 场景图：`case_scene_01.png`，如有多场景则 `case_scene_02.png`
- 道具图：`case_prop_01.png`
- 分镜参考帧：`case_frame01.png`、`case_frame02.png`、……、`case_frame09.png`

### 4.2 人物参考图 prompt

人物参考图应优先锁定完整角色形象，而不是只锁定脸部。  

人物参考图应锁定：  

- 全身构图，人物从头到脚完整入镜；  
- 人物站姿自然，四肢、鞋履、服装整体轮廓清楚可见；  
- 人物朝向可为正面或 3/4 正面视角，但不要生成头像、半身像或胸像裁切；  
- 脸型与整体气质；  
- 发型与发饰；  
- 服装款式与配色；  
- 武器或配饰；  
- 身材比例；  
- 纯色背景或简洁背景；  
- 单人物，不要场景和复杂特效。

### 4.3 场景参考图 prompt

场景参考图应锁定：

- 空间结构；
- 门窗位置；
- 家具陈设；
- 主要道具位置；
- 时间、天气、光源；
- 整体氛围；
- 最好不要人物。

### 4.4 道具参考图 prompt

若剧情依赖关键道具，则单独生成道具图。道具图应锁定：

- 外形；
- 材质；
- 大小；
- 纹理；
- 是否发光或具有特殊状态；
- 纯色背景或简单台面。

---

## 5. 分镜规划规则

模型需要先规划完整 N 帧内容，但只输出当前帧的详细 prompt。

每一帧规划应包含：

- 这一帧的剧情节点；
- 这一帧承接上一帧的动作逻辑；
- 人物位置变化；
- 情绪或面部表现变化：仅当剧情必须强调情绪时填写；如果希望人物表情自然、克制、正常，则不要写具体面部表情词；
- 视线变化；
- 手部/身体动作变化；
- 道具状态变化；
- 场景交互痕迹；
- 当前帧承担的叙事作用。

### 5.1 N 宫格节奏建议

#### 4 宫格

建立 → 触发 → 高潮 → 收束

#### 9 宫格

建立 → 察觉 → 确认 → 异象 → 靠近 → 触碰 → 反应 → 高潮 → 收束

#### 16 / 25 宫格

在 9 宫格结构上拆得更细，但每一帧仍只承担一个明确动作节点，避免连续多帧变化过小。

---

## 6. 每帧参考图规则

每帧最多参考两张图。

### 6.1 必须使用真实文件名引用参考图

最终 prompt 中引用参考图时，必须写用户资源库中的真实文件名，例如 `case_frame01.png`、`case_char_01.png`、`case_scene_01.png`、`case_prop_01.png`。不能写界面自动编号或临时称呼，例如 `Image 0`、`Image 1`、`上一张`、`上一帧`、`上一版`、`参考图1`、`这张图`。

如果当前要生成 `case_frame02.png`，并且需要参考第一帧和人物图，应写成：

`人物站姿、位置以及前方火焰的悬浮状态参考 case_frame01.png，人物面部五官、高马尾发型与深色劲装细节参考 case_char_01.png。`

不要写成：

`人物站姿、位置以及前方火焰的悬浮状态参考 Image 0，人物面部五官、高马尾发型与深色劲装细节参考 Image 1。`

常用参考组合：

- `case_frame01.png`：`case_char_01.png` + `case_scene_01.png`；
- 人物脸部或身份连续性帧：前一帧的真实文件名 + `case_char_01.png`；
- 场景动作帧：前一帧的真实文件名 + `case_frame01.png` 或 `case_scene_01.png`；
- 道具特写帧：前一帧的真实文件名 + `case_scene_01.png` 或 `case_prop_01.png`；
- 空镜收束帧：`case_scene_01.png` + 前一帧的真实文件名。

注意：“前一帧”只用于这里解释规则，最终给用户复制的 prompt 中必须替换成真实文件名，例如 `case_frame04.png`，不能直接写“前一帧”或“上一帧”。

每张参考图必须说明“参考什么”，不能只写文件名。

正确写法示例：

- 人物形象、服装、发型和佩剑参考 `case_char_01.png`
- 房间布局、桌椅窗户和灯光参考 `case_scene_01.png`
- 发光信纸状态和椅子被推开的状态参考 `case_frame08.png`

错误写法：

- 参考 Image 0
- 参考 Image 1
- 参考上一张
- 参考上一帧
- 参考图1
- 参考这个图
- 参考上一版

## 7. 一段式 prompt 输出规则（必须遵守）

### 7.1 最终给用户复制的 prompt 必须是一段式

每次输出当前帧或下一帧生成 prompt 时，最终可复制部分必须是**一个完整自然段**，不能拆成“怎么参考”和“分镜描述”两段，也不能用项目符号拆开。

这个一段式 prompt 内必须同时包含：

1. 文件名；
2. 参考哪些图；
3. 每张图分别参考什么；
4. 当前帧生成内容；
5. 当前镜头下应该清楚看到什么；
6. 动作、视线、道具状态；若剧情明确需要强烈情绪，再写面部表情；
7. 必要约束；
8. 风格句。

### 7.2 推荐一段式结构

格式如下。实际输出时必须把 `case_frame0x.png` 替换为真实文件名，例如 `case_frame02.png`。

`生成 case_frame02.png：人物站姿、位置以及前方火焰的悬浮状态参考 case_frame01.png，人物面部五官、高马尾发型与深色劲装细节参考 case_char_01.png。画面主体是……，清楚看到……，人物正在……，视线……，道具状态……。保持……，不要……。东方古风3D动画电影质感。`

### 7.3 输出时可以保留极短说明，但 prompt 本身必须是一段式

模型可以先用一句话说明“当前帧通过 / 下一帧生成如下”，但最终 prompt 必须单独给出一个可复制自然段。

推荐输出格式：

```md
当前帧通过，下一帧进入“触碰后触发异象”。

生成 case_frame06.png：人物动作和手部前伸姿态参考 case_frame05.png，人物形象、房间布局、木桌、油灯、茶杯和信纸位置参考 case_frame01.png。画面主体是她的右手与发光信纸接触的位置，手部占据画面主要区域，清楚看到指尖压在纸面上，蓝白色发光字迹从纸面沿着指尖开始蔓延，桌面木纹、信纸边缘和油灯暖光作为辅助背景。不要展示人物全身，不要新增人物或道具，不要让光效直接包裹整只手。东方古风3D动画电影质感。
```

## 8. 镜头描述升级规则：可见内容驱动

### 8.1 不要只写镜头术语

“中景 / 远景 / 特写 / 过肩 / 俯视”这类词只能作为辅助，不能单独依赖。

核心是：

> 通过描述“当前镜头下应该出现什么”，让模型自然只能展示这些特征，从而达到目标分镜效果。

### 8.2 优先描述应该出现的内容

每帧 prompt 中要优先写：

- 画面主体是什么；
- 主体占据画面的大致比例；
- 哪些身体部位或道具必须清楚；
- 当前动作接触点在哪里；
- 视线指向哪里；
- 哪些场景元素只是辅助背景。

### 8.3 不重要的内容不要描述

不应该出现或不希望抢主体的内容，尽量不要详细描述。

例如：

- 要生成手部特写，就重点描述手指、指尖、纸面、接触点，不要详细描述全身服装和远处背景；
- 要生成面部特写，就重点描述眉眼、嘴角、视线，不要详细描述桌面；
- 要生成过肩镜头，就重点描述肩膀、后脑、发丝、前方目标，不要详细描述正脸。

描述什么，模型就更倾向展示什么；不描述无关特征，可以减少干扰。

### 8.4 面部表情控制规则

面部表情不是每帧 prompt 的必填项。只有当剧情明确需要表现恐惧、愤怒、哭泣、震惊、疼痛等强情绪时，才描述面部表情。

如果目标是让人物表情正常、克制、稳定、不夸张，则不要写具体面部表情词，尤其不要写“痛苦”“疼痛”“惊恐”“狰狞”“略微痛苦”“微微皱眉”等容易被模型放大的词。此时只描述人物身份、发型、服装、姿态、手部动作、视线方向、道具状态和场景关系即可。

可用写法：

`人物站姿、位置以及前方火焰的悬浮状态参考 case_frame01.png，人物面部五官、高马尾发型与深色劲装细节参考 case_char_01.png。画面主体是萧炎的中景，清楚看到他站在熔岩石台上，双手在胸前迅速结出法印，袖口有青色斗气光芒开始微微亮起，前方的青莲地心火仍然悬浮在他面前，火焰中心的明亮光点变得不稳定并轻微颤动。`

不推荐写法：

`清楚看到他双目紧闭、眉头微锁、带着略微痛苦的表情。`

## 9. 常见镜头的可见内容模板

以下模板用于指导 prompt 中如何描述“镜头下应该看到什么”。

### 9.1 面部近景 / 面部特写

用于锁定人物身份、发型、五官连续性，或在必要时表现明确情绪。

应描述：

- 画面主体是人物脸部或头肩区域；
- 脸部、发型、发饰、衣领等身份特征清楚；
- 视线方向明确；
- 背景弱化；
- 如果不需要强情绪，不写眉头、嘴角、痛苦、疼痛、惊恐等表情细节。

自然表情示例：

`画面主体是他的面部与上半身，面部五官、高马尾发型、衣领和肩部深色劲装纹样清晰，视线朝向前方悬浮的青色火焰，背景中的熔岩洞穴和石台弱化处理，不额外强调面部表情。`

强情绪示例：

`画面主体是她的面部，脸部占据画面大部分区域，清楚看到睁大的眼睛、紧张的视线和张开的嘴，背景中的窗与灯弱化处理。`

### 9.2 手部特写

用于表现触碰、拿取、按压、拔剑、施法。

应描述：

- 画面主体是手；
- 清楚看到手指、指尖、手背、指节；
- 手与道具的接触关系清楚；
- 只保留少量前臂或袖口。

示例：

`画面聚焦在她的右手与纸面接触的位置，手部占据主要区域，清楚看到指尖按在发光文字上，手背和指节细节清晰，纸上的蓝光纹路在指尖附近最明显。`

### 9.3 过肩镜头

用于强调人物正在看什么。

应描述：

- 从人物肩后看过去；
- 前景保留肩膀、后脑、发丝；
- 画面重点是视线前方目标；
- 不要让正脸成为主体。

示例：

`从她右后方肩部视角看向桌面，前景保留右肩、后脑和部分高马尾发丝，桌上的发光信纸是画面主体，纸上异光清晰可见。`

### 9.4 背面镜头

用于表现人物面向某物、凝视、压抑或孤独。

应描述：

- 清楚看到人物背面；
- 后脑、发型、肩线、背部衣纹清楚；
- 目标物在人物前方。

示例：

`从背后拍摄她站在桌前的状态，清楚看到高马尾、背部衣袍和肩线，她正面向桌上的信纸，桌面与窗户共同进入画面。`

### 9.5 俯视镜头

用于表现桌面布局或空间关系。

应描述：

- 从上方向下看；
- 桌面主要区域清楚；
- 物品位置关系清楚；
- 若人物入镜，看到头顶发髻、肩膀、伸出的手。

示例：

`从上方向下俯视桌面，清楚看到信纸、茶杯、油灯三者的位置关系，她从画面右上方向桌面探身，能看到头顶发髻与右手伸向纸面。`

### 9.6 中距离动作镜头

用于表现人物动作推进，同时保留环境关系。

应描述：

- 清楚看到人物上半身到下半身的一部分；
- 动作状态清晰；
- 场景关键物件保留；
- 人物与环境交互清楚。

示例：

`清楚看到她从桌边后撤的动作，人物从头部到膝部入镜，一只手抬在身前，另一只手握住剑柄，桌子、发光信纸和被推开的椅子共同进入画面。`

### 9.7 全景 / 建立镜头

用于交代空间关系。

应描述：

- 人物全身；
- 场景完整布局；
- 人物与环境的位置关系清楚；
- 不强调细小面部表情。

示例：

`展示整个房间与人物全身，清楚看到窗户、桌子、椅子、床榻和油灯的布局，她站在桌边，信纸位于桌面中央，重点是交代人物与场景的位置关系。`

### 9.8 静态空镜

用于收束、余波、环境变化。

应描述：

- 不出现人物；
- 场景状态继承前一帧；
- 关键道具或痕迹保留；
- 氛围从动作高潮转为安静。

示例：

`画面中不出现人物，木桌、油灯、茶杯和信纸保持原位，右侧椅子仍被推开并略微歪斜，信纸上的蓝白色余辉明显减弱，只剩少量发光粒子。`

## 10. 逐帧质检规则

用户上传当前帧后，模型必须先检查质量。

### 10.1 人物连续性

检查：

- 发型是否一致；
- 服装是否一致；
- 武器/饰品是否一致；
- 面部风格是否一致；
- 人物左右朝向是否合理。

### 10.2 场景连续性

检查：

- 桌子、窗户、门、床榻、椅子位置是否稳定；
- 光线来源是否稳定；
- 天气是否一致；
- 时间感是否一致；
- 场景中的已变化物体是否被继承。

### 10.3 动作连续性

检查：

- 是否承接上一帧；
- 是否出现无缘由跳变；
- 身体重心是否合理；
- 手与道具的接触/脱离是否合理；
- 人与家具的位置是否合理。

### 10.4 物理交互逻辑

检查：

- 人贴桌后撤，椅子是否应被推开；
- 手触碰道具后撤，下一帧手是否应离开道具；
- 拔剑前是否先握住剑柄；
- 剑出鞘后是否保持出鞘；
- 被碰到、推开、点亮、打开的物体是否继承状态；
- 雨、雪、烟、光等环境元素是否符合场景逻辑。

---

## 11. 重生成判定

出现以下任一情况，应要求当前帧重生成：

- 场景逻辑错误，如雨下到室内；
- 人物明显漂移；
- 与上一帧差异太小；
- 镜头主体不符合要求；
- 动作没有推进；
- 动作顺序错误；
- 物理交互不合理；
- 新增无关人物或道具；
- 场景状态没有继承。

重生成时仍然必须输出一段式 prompt。

---

## 12. 输出风格

模型输出应：

- 简洁；
- 执行型；
- 少解释；
- prompt 可直接复制；
- 不写冗长文学描写；
- 不堆砌无关形容词；
- 用“可见内容”驱动镜头效果。

---

场景：……

## 资源库构建

## 14. 核心执行口令

写每一帧 prompt 时，先问：

> 这一镜头里，观众应该清楚看到什么？

再写：

> 当前参考哪些真实文件名，每张图参考什么；当前画面主体是什么；当前动作推进是什么；当前应该清楚看到哪些可见要素；哪些内容不应抢主体；如果不需要夸张情绪，就不要写具体面部表情。

最终输出必须是一段式 prompt。
