# 多宫格分镜参考帧生成工作流（v6.6：拓扑规则 + 视角连续性 + 精简 Prompt）

## 0. 版本定位

v6.6 在 v6.5 的基础上继续升级，重点解决以下问题：

1. 第一阶段基础帧虽然开始受资源图约束，但仍可能出现 **人物朝向切换过快** 的问题，例如第一帧正面开场，第二帧和第三帧突然切成背影。
2. 人物位置虽然基于真实场景锚点，但仍可能 **遮挡场景核心**，导致桌子、玉简、窗户等关键信息没有被有效展示。
3. 经过多轮规则追加后，生成 prompt 有越来越长的趋势，需要明确加入 **Prompt 精简原则**，避免把规划文本直接堆到最终 prompt 中。

因此，v6.6 的核心升级为：

```text
在保留任意帧数、全帧再编辑、资源图约束剧情规划等能力的基础上，新增：
1) Scene Core / Character / Camera Topology Rule（场景核心—人物—镜头拓扑规则）；
2) Camera-Side Continuity Track（相机侧连续轨）；
3) Anchor Visibility Budget（关键锚点可见性预算）；
4) Image Generation Prompt Compression Rule（图像生成 Prompt 精简原则）。
```

一句话概括：

```text
Base frames must not only follow real resource images, but also keep key scene-core information visible, preserve camera-side continuity between adjacent frames, and use compact prompts instead of increasingly verbose instructions.
```

---

## 1. 核心目标

用于指导大模型基于用户 idea 生成 **任意数量 N 的多帧参考图**，并在第二阶段对所有基础帧进行再编辑。

v6.6 保留以下能力：

- **9 宫格核心保底模式**：N=9 时沿用成熟逻辑；
- **任意帧数衍生模式**：N=4/5/6/7/8/10+ 时由 9 beat 骨架压缩或扩展；
- **全帧再编辑**：所有 base frames 都进入第二阶段；
- **资源图约束剧情规划**：base frame 规划必须参考已选中的人物图、场景图、道具图；
- **禁止发明场景锚点**：不能在 prompt 中凭空加入 scene reference 中不存在的入口、门框、台阶、石柱等结构。

v6.6 的新增重点是：

- **基础帧不仅要用真实锚点，还要让核心锚点被看见；**
- **基础帧之间不仅要剧情连续，还要镜头侧连续；**
- **用于生成图像的最终英文 prompt 必须足够短，只保留真正影响图像生成结果的约束。规划、质检和候选选择说明可以详细，但不要把这些分析文字堆进图像生成 prompt。**

## 2. 总体流程

```text
Step 1  接收用户输入（idea、帧数需求、风格、角色数、场景数、是否全帧再编辑等）
Step 2  构建资源库（人物图、场景图、道具图）
Step 3  资源图审查（确认可用锚点、不可用锚点、场景核心）
Step 4  确定帧数 N（默认 9；用户指定优先；短视频可用 5/6 帧）
Step 5  规划基础帧（只输出当前帧 prompt）
Step 6  生成 case_base_frame01.png 到 case_base_frameNN.png
Step 7  整体质检（剧情、角色、场景、视角连续性、锚点可见性）
Step 8  规划第二阶段全帧再编辑
Step 9  生成 case_edit_frame01.png 到 case_edit_frameNN.png
Step 10 输出最终分镜（默认使用 edited frames）
```

## 3. 帧数模式

### 3.1 默认规则

- 用户未指定帧数：默认 N=9。
- 用户明确指定 N：严格使用用户指定的 N。
- 用户只说“短一点”“不要太长”：优先建议 N=5 或 N=6。

### 3.2 9 宫格核心保底原则

当 N=9 时：

```text
必须沿用标准 9 宫格节奏，不启用压缩逻辑，保证原有效果不受升级影响。
```

### 3.3 任意帧数衍生原则

当 N≠9 时：

```text
先在内部建立标准 9 beat 骨架，再对 beat 进行合并、压缩或扩展。
```

标准 9 beat：

| Beat | 功能 |
|---|---|
| B1 | 开场：人物与场景关系 |
| B2 | 到达行动位置 |
| B3 | 开始动作 |
| B4 | 接近/接触目标 |
| B5 | 首次变化 |
| B6 | 变化升级 |
| B7 | 结果显现 |
| B8 | 处理结果/离开 |
| B9 | 收束/余波 |

短帧数推荐：

- N=5：B1 / B2+B3 / B4+B5 / B6+B7 / B8+B9
- N=6：B1 / B2 / B3+B4 / B5+B6 / B7 / B8+B9

## 4. 资源图约束剧情规划

### 4.1 资源图先于剧情落点

在正式写 base frame prompt 前，必须先审查：

1. `case_char_01.png` 可继承哪些身份信息；
2. `case_scene_01.png` 真实存在哪些空间锚点；
3. `case_prop_01.png` 或其他道具图的状态、朝向、大小；
4. 哪些锚点 **不存在**，因此不得写入 prompt。

核心原则：

```text
Story planning must be conditioned on selected resource images.
```

### 4.2 Scene-First Composition Lock

对于单场景连续剧情：

```text
case_scene_01.png 必须作为空间构图主参考，尤其是 case_base_frame01.png。
```

第一帧先锁场景构图，再放人物。

### 4.3 No Invented Scene Anchors

如果 scene reference 中没有以下结构，则 prompt 禁止提及：

- 入口门槛 / 大门框
- 石柱 / 祭坛
- 楼梯 / 二层结构
- 额外家具
- 新窗户 / 新桌子 / 新平台

如果剧情确实需要这些元素，应先 **重生成场景参考图**，而不是让 base frame 临时发明。

## 5. Scene Core / Character / Camera Topology Rule

这是 v6.6 的核心新增规则。

### 5.1 先定义场景核心（Scene Core）

每一帧都必须先确定当前帧最重要的信息中心是什么。

常见 Scene Core：

- 开场帧：中央木桌、破窗月光、书架
- 观察帧：木桌 + 玉简
- 接触帧：玉简 + 手部接触点
- 爆发帧：玉简发光区 + 飞舞纸页 + 尘埃
- 结果帧：山河地图 + 结印手势
- 收束帧：桌面光痕 + 离开人物

### 5.2 根据朝向确定拓扑关系

#### A. 正面向 / 三分之二正面帧

当当前帧是 `front view` 或 `three-quarter front view`：

```text
Camera → Scene Core → Character
```

含义：

- 场景核心优先位于人物与镜头之间；
- 人物站在场景核心的远侧、侧后方或靠窗一侧；
- 避免人物主体直接挡住木桌、玉简等核心信息。

#### B. 背面向 / 三分之二背面帧

当当前帧是 `back view` 或 `three-quarter back view`：

```text
Camera → Character → Scene Core
```

含义：

- 人物位于镜头和场景核心之间；
- 适合表现人物观察、接近、操作桌子/玉简。

#### C. 侧面 / 三分之二侧面帧

当当前帧是 `side view` 或 `three-quarter side view`：

```text
Character beside Scene Core, both visible
```

含义：

- 人物站在场景核心一侧；
- 人物与场景核心同时清晰可见；
- 特别适合“走近桌子”“伸手触碰”这类过渡帧。

### 5.3 关键提醒

```text
人物面向目标物 ≠ 人物必须背对镜头。
```

人物面对桌子时，也可以：

- 站在桌子远侧而面向镜头；
- 站在桌子侧面同时面向桌子与镜头；
- 站在靠窗一侧，让桌子位于前景。

## 6. Camera-Side Continuity Track

这是 v6.6 的第二个核心新增规则。

### 6.1 基础帧阶段优先保持同侧拍摄

如果 `case_base_frame01.png` 选择了某一相机侧（例如人物的正面左侧 / 正面右侧），那么后续相邻基础帧应优先沿用同一相机侧。

除非满足以下情况之一，才允许明显切侧：

1. 人物剧情上发生了转身；
2. 当前帧的镜头意图明确需要换侧；
3. 当前 Scene Core 发生改变，必须重新组织拓扑；
4. 进入收束帧或离开帧，需要改成背影。

### 6.2 不允许的情况

不允许出现：

- 第一帧正面开场；
- 第二帧无明确理由突然变正背影；
- 第三帧继续背影；
- 第五帧又突然转成正面；
- 这种“正面—背面—背面—正面—背面”的跳变链条。

### 6.3 推荐的朝向变化节奏

如果第一帧是正面开场，则 6 帧示例可优先采用：

| 帧 | 剧情节点 | 推荐朝向 |
|---|---|---|
| frame01 | 开场建立人物与场景 | three-quarter front |
| frame02 | 走近桌面观察 | three-quarter front / three-quarter side |
| frame03 | 伸手接触玉简 | three-quarter side |
| frame04 | 玉简发光爆发 | three-quarter side / three-quarter front |
| frame05 | 结印压制，地图出现 | front / three-quarter front |
| frame06 | 收束离开 | back / three-quarter back |

核心原则：

```text
基础帧先求稳定，再求变化；朝向变化应由剧情驱动，而不是由模型随意跳变。
```

## 7. Anchor Visibility Budget

这是 v6.6 的第三个核心新增规则。

### 7.1 不仅要使用锚点，还要让锚点被看见

基础帧不能只“理论上使用了真实锚点”，还必须保证当前帧最重要的锚点在画面中充分可见。

### 7.2 对开场帧的最低要求

如果 Scene Core 是“中央木桌 + 玉简 + 窗户月光”，则开场帧至少应满足：

- 大部分桌面可见；
- 至少一个前侧桌腿或桌角可见；
- 窗户与月光方向可见；
- 左右书架或主要书架可见；
- 人物不能完全挡住木桌。

### 7.3 对背影帧的最低要求

如果是背影观察帧，则至少应满足：

- 人物在前景或中景；
- 桌面核心区域仍可见；
- 玉简或目标物不被身体完全挡住；
- 场景核心与人物关系清楚。

核心原则：

```text
真实锚点必须同时满足“存在”与“可见”。
```

## 8. 第一阶段：基础帧规划规则

基础帧是 **剧情状态集合**，不是最终电影镜头集合。

每一帧在规划时，至少回答以下问题：

1. 当前剧情节点是什么？
2. 对应哪些标准 beat？
3. 当前 Scene Core 是什么？
4. 当前镜头是 `wide shot` 还是 `medium shot`？
5. 当前人物与目标物关系是什么？
6. 当前人物与镜头关系是什么？
7. 当前相机侧是否延续上一帧？
8. 当前拓扑关系是什么？
9. 当前人物是否遮挡了 Scene Core？
10. 当前帧是否适合作为第二阶段再编辑输入？

### 8.1 开场朝向中立选择仍然保留

`case_base_frame01.png` 不默认背影。

开场可以根据叙事目的选择：

- `front view / three-quarter front`：介绍人物身份；
- `side view / three-quarter side`：表现进入动作或横向移动；
- `back view / three-quarter back`：强调探索未知空间。

### 8.2 基础帧最小参考原则仍然保留

- 第一帧通常参考：`case_scene_01.png` + `case_char_01.png`
- 后续同镜头、同可见面帧：优先只参考上一张基础帧
- 仅当人物可见面或镜头尺度显著变化时，才重新引用 `case_char_01.png`

## 9. 图像生成 Prompt 精简原则（Image Generation Prompt Compression Rule）

这是 v6.6 专门新增的约束，针对的是最终输入图像生成/图像编辑模型的英文 prompt，目的是避免图像生成 prompt 越来越长。

### 9.1 规划可以详细，最终 prompt 必须精简

允许在规划表、审查步骤、质检说明中写详细分析；
但最终传给图像生成/图像编辑模型的 **英文 prompt 必须是一段式、短而有效**。

### 9.2 最终 prompt 只保留 6 类信息

最终图像生成 prompt 只保留以下真正必要的信息：

1. **参考图及其作用**：最多 1–2 张；
2. **确定镜头**：如 `wide shot` / `medium shot`；
3. **人物位置与 Scene Core 关系**；
4. **人物与镜头关系**；
5. **当前剧情状态**；
6. **禁止项**：只写最重要的 3–6 条。

不要把以下内容完整堆进最终图像生成 prompt：

- 资源图审查全文；
- 长段规划理由；
- 候选图选择分析；
- 版本说明；
- 过多重复约束。

### 9.3 精简建议

- 参考图说明：一句话完成；
- 镜头层：一句话完成；
- 主体位置与动作：一句话完成；
- 保持不变与禁止项：一句话完成；
- 风格句：一句话完成。

通常 5–7 句足够。

### 9.4 不建议的写法

不建议把：

```text
资源图审查、剧情落点调整、朝向选择理由、场景不可用锚点列表……
```

直接复制进 prompt。

### 9.5 推荐的基础帧精简模板

```text
Generate case_base_frame0x.png: Use [scene file] for the exact room layout, scene core position, lighting direction, and camera viewpoint, and use [character file or previous base frame] for the character identity and current shot continuity. Camera: [wide shot or medium shot], [viewpoint], [explicit subject-camera relation]. The character is [positioned relative to the scene core], with [subject-object relation]. Clearly show [core visible details]. Keep [2-4 key continuity items] unchanged. Do not [3-6 critical mistakes only]. Cinematic Chinese fantasy 3D animation style.
```

### 9.6 推荐的再编辑精简模板

```text
Generate case_edit_frame0x.png: Use case_base_frame0x.png as the primary reference for the exact story state, character position, object state, and scene layout. Edit goal: [cleanup / cinematic polish / moderate reframe / strong transformation]. Camera: [final shot type], [viewpoint], [explicit composition focus]. Re-edit the same moment without changing the story beat. Improve [1-3 weak points]. Keep [2-4 key elements] unchanged. Do not [3-6 critical mistakes only]. Cinematic Chinese fantasy 3D animation style.
```

## 10. 第一阶段 Prompt 规则

每一条基础帧 prompt 必须：

- 使用真实文件名；
- 只写一个确定的基础镜头：`wide shot` 或 `medium shot`；
- 明确 Subject–Object Relation；
- 明确 Subject–Camera Relation；
- 明确人物与 Scene Core 的拓扑关系；
- 保证关键 Scene Core 可见；
- 不要使用选择式镜头表达；
- 不要无理由切换相机侧；
- 使用精简版 prompt。

禁止：

```text
wide shot or medium shot
wide / medium shot
suitable camera distance
appropriate shot size
```

---

## 11. 第二阶段：全帧再编辑规则

第二阶段保持 v6.5 的核心逻辑：

```text
所有 base frames 都进入再编辑。
```

### 11.1 再编辑的目标

- 保持剧情连续性；
- 增加电影级镜头多样性；
- 修复 base frame 小瑕疵；
- 强化人物、道具、场景和光影一致性。

### 11.2 再编辑默认只参考对应 base frame

默认：

```text
case_base_frame0x.png → case_edit_frame0x.png
```

仅在以下情况额外引入参考图：

- 人物身份漂移：加 `case_char_01.png`
- 场景结构漂移：加 `case_scene_01.png`
- 道具形态漂移：加 `case_prop_01.png`

### 11.3 再编辑允许更丰富镜头，但不能破坏剧情

允许：

- close-up
- insert shot
- over-the-shoulder
- low-angle
- high-angle
- overhead

但必须遵守：

```text
镜头可以变，剧情状态不能变；相机位置可以变，人物与目标物关系不能乱变。
```

## 12. 候选选择优先级（更新版）

### 12.1 基础帧候选选择优先级

1. Frame Count Fit：是否符合当前剧情 beat
2. Story State Accuracy：是否准确表现当前状态
3. Base Camera Accuracy：是否符合 wide / medium 要求
4. Subject–Camera Accuracy：人物与镜头关系是否正确
5. **Camera-Side Continuity**：是否合理延续上一帧的相机侧
6. **Scene Core Topology Accuracy**：人物、场景核心、镜头的相对拓扑是否合理
7. **Anchor Visibility Accuracy**：关键锚点是否足够可见
8. Anchor Accuracy：人物是否落在正确锚点
9. Character Consistency：人物是否稳定
10. Scene Continuity：场景结构是否稳定
11. Editability：是否适合第二阶段再编辑
12. Visual Quality：是否清晰、无明显错误

### 12.2 再编辑候选选择优先级

1. 是否保持基础帧剧情状态
2. 是否实现规划中的编辑强度与镜头策略
3. 是否修复了基础帧问题
4. 是否保留关键锚点与人物一致性
5. 是否更适合作为最终分镜帧

## 13. 重生成判定（更新版）

### 13.1 基础帧需要重生成的情况

若出现以下任意情况，应重生成：

- 使用了 scene reference 中不存在的锚点；
- 开场帧选择正面，但人物直接挡住了 Scene Core；
- 当前帧关键锚点存在但不可见；
- 第一帧正面开场，后续相邻帧无明确理由突然切背影；
- 相机侧发生无理由跳变；
- prompt 过长，大量堆砌规划文字；
- prompt 中使用了不确定镜头表达；
- 当前帧不是指定的 wide shot / medium shot；
- 人物位置与场景核心关系错误；
- 道具状态不符合剧情；
- 人物面向目标物关系正确，但因为错误拓扑导致核心信息被遮挡。

### 13.2 编辑帧需要重生成的情况

若出现以下任意情况，应重生成：

- 再编辑破坏剧情状态；
- 人物位置被改掉；
- 道具状态被改掉；
- 场景变成另一个地方；
- 强行电影化导致前后不连续；
- 应该保留的 Scene Core 被裁掉或遮挡过多。

## 14. v6.6 执行口令

### 14.1 资源图审查前必须先问

1. What are the real visible anchors in the selected scene reference?
2. What anchors do not exist and therefore must not be written into prompts?
3. What is the scene core of the current frame?

### 14.2 每张基础帧生成前必须先问

1. What story beat does this frame represent?
2. What is the scene core?
3. Is this a wide shot or a medium shot?
4. What is the subject-object relation?
5. What is the subject-camera relation?
6. What is the camera-side track relative to the previous frame?
7. What topology should be used: Camera→Scene Core→Character, Camera→Character→Scene Core, or Character beside Scene Core?
8. Are the key anchors visible enough?
9. Can the final image-generation prompt be compressed without losing essential constraints?

### 14.3 第二阶段再编辑前必须先问

1. What exact story state must remain unchanged?
2. Which small defects should be fixed?
3. What camera strategy best improves this frame?
4. Which anchors must stay visible after re-editing?
5. Can the image-edit prompt stay short and focused?

## 15. 一句话总结

v6.6 的核心不是继续堆规则，而是让规则更有效、更短：

```text
Use selected resource images to ground the storyboard, identify the scene core of each frame, arrange character/core/camera topology explicitly, preserve camera-side continuity, keep key anchors visible, and compress the final prompt so it stays short but strong.
```

中文概括：

```text
先用资源图锁定剧情落点，再为每一帧明确场景核心，并根据人物朝向决定人物、场景核心与镜头的相对排布；相邻基础帧优先保持相机侧连续，同时保证关键锚点真正可见；最终图像生成 prompt 只保留必要约束，不再无上限变长。
```
