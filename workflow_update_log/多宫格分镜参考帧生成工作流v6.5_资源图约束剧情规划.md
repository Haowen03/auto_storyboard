# 多宫格分镜参考帧生成工作流（v6.5：任意帧数 + 9宫格核心保底 + 全帧再编辑 + 资源图约束剧情规划）

## 0. 版本定位

本版本是在 v6.4 的基础上继续升级第一阶段规划流程，用于解决“用户并不总是需要 9 张参考帧”“9 帧对应的视频时长偏长”“短剧情只需要 5–6 帧关键参考状态”，以及“分镜剧情没有严格受已生成资源图约束，导致基础帧临时发明场景锚点、没有真正继承场景参考图构图”等问题。

v6.3 的核心逻辑是：

```text
第一阶段：生成稳定 base frames，用来锁定剧情连续性、人物一致性、场景一致性和关键状态；
第二阶段：对所有 base frames 逐帧进行再编辑，每一帧都生成对应的 edited frame；
最终九宫格统一使用 edited frames。
```

v6.4 在不破坏 v6.3 核心机制的前提下，新增 **任意帧数参考帧模式**；v6.5 在此基础上新增 **资源图约束剧情规划** 与 **场景优先构图锁定**：

```text
用户可以指定任意参考帧数量 N；
模型根据 N 生成对应数量的 base frames；
第二阶段仍然对所有 base frames 逐帧再编辑；
最终输出 N 张 edited frames。
```

核心变化可以概括为：

```text
v6.3: 默认生成 9 张基础帧，再对 9 张基础帧全帧再编辑。
v6.4: 支持任意帧数 N；9 帧模式保持原逻辑不变，非 9 帧模式由 9 宫格叙事骨架压缩或扩展得到。
v6.5: 在规划 base frames 前，必须先读取已选人物、场景、道具参考图的具体内容；剧情落点必须使用资源图中真实可见的锚点，不能在 prompt 中临时发明场景结构。
```

v6.5 的重要原则是：

1. **9宫格核心保底原则**：当用户指定 N=9，或者没有指定帧数且剧情适合标准长度时，必须沿用 v6.3 的 9 宫格逻辑，不引入新的压缩规则，不改变已有 9 宫格效果。
2. **任意帧数衍生原则**：当用户指定 N≠9 时，不重新发明一套流程，而是从 9 宫格叙事节奏中压缩、合并或扩展得到 N 帧规划。
3. **用户指定优先原则**：如果用户明确说“5帧”“6帧”“4张参考帧”，必须直接按照用户给定的 N 规划，不要强行推荐 9 帧。
4. **全帧再编辑保留原则**：不论 N 是多少，第二阶段都必须对所有 base frames 进行再编辑，生成一一对应的 edited frames。
5. **实验兼容原则**：任意帧数模式是对 9 宫格核心工作流的扩展。如果任意帧效果不稳定，不影响 9 宫格模式继续按原方案运行。
6. **资源图约束剧情规划原则**：资源库候选图选定后，模型必须先分析 `case_char_01.png`、`case_scene_01.png`、`case_prop_01.png` 的真实可见内容，再规划 base frames。分镜剧情必须适配这些资源图，而不是只根据用户 idea 机械生成。
7. **场景优先构图锁定原则**：单场景工作流中，`case_scene_01.png` 是基础帧的空间主参考。尤其是 `case_base_frame01.png`，必须先锁定场景参考图的原始构图、主视角、桌子/窗户/书架/地面等锚点，再把人物放入该空间。
8. **禁止发明场景锚点原则**：base frame prompt 中不能出现 `case_scene_01.png` 中不存在的关键场景结构，例如不存在的入口、门槛、台阶、门框、石柱、桌子、窗户或平台。如果剧情必须依赖这些锚点，应先重生成场景参考图，而不是让 base frame 临时生成新场景。

## 1. 核心目标

用于指导大模型基于用户 idea 生成 **任意数量 N 的多帧参考图**。其中：

- **N=9**：标准核心模式，效果优先保证，沿用原 9 宫格逻辑；
- **N=5 / 6 / 7**：短视频常用模式，用于控制视频时长，保留主要剧情节点；
- **N=4**：极简剧情模式，适合单动作、单转折、单结果；
- **N=10–16**：长剧情或多阶段动作模式；
- **N=1 / 2 / 3**：只在用户明确要求时使用，适合单图、前后对比或极短转场。

推荐默认策略：

```text
用户未指定 N：优先使用 9 帧标准模式。
用户明确指定 N：严格使用用户指定的 N。
用户只说“短一点”或“视频别太长”：优先建议 5 或 6 帧。
用户剧情复杂但未指定 N：使用 9 帧，必要时说明原因。
```

### 1.1 第一阶段目标：稳定剧情骨架

第一阶段生成：

```text
case_base_frame01.png 到 case_base_frameNN.png
```

这一阶段的目标不是电影镜头，而是稳定剧情，并且必须先受已选资源图约束：

- 资源先行：资源库候选图选定后，先分析场景图中真实存在的空间锚点，再规划人物落点和剧情节点；
- 场景主导：单场景下，场景参考图是空间构图主参考，人物参考图只负责身份、服装、发型等角色信息；
- 锚点真实：base frame 只能使用场景图或前一张基础帧中可见的真实锚点，不能临时发明不存在的门口、台阶、柱子、窗户、桌子等结构；
- 剧情适配：如果用户 idea 中的“进入房间”“走到门口”等动作无法被当前场景参考图支持，应把剧情起点改到已有锚点附近，例如桌旁、窗边、书架之间、月光区域内，或者先重生成场景图；

- 剧情连续：每一帧是一个明确的剧情状态节点；
- 状态清楚：人物动作、视线、道具状态、场景变化有明确承接；
- 帧数合适：N 要符合用户指定或视频时长需求；
- 节奏合理：短帧数要压缩剧情但不能跳过关键因果；
- 角色稳定：人物身份、发型、服装、体型、配饰保持一致；
- 场景稳定：空间结构、光源、关键参考物、地面纹理保持一致；
- 位置稳定：人物和道具必须使用场景内可见锚点定位；
- 镜头稳定：每一帧只使用明确的 `wide shot` 或明确的 `medium shot`；
- 朝向稳定：每一帧必须明确人物与目标物关系，以及人物与镜头关系；
- 开场中立：`case_base_frame01.png` 不默认背影开局，必须根据开场镜头意图选择正面、背面、侧面或三分之二视角；
- 参考稳定：每张基础帧都应适合作为第二阶段再编辑的输入。

### 1.2 第二阶段目标：全帧再编辑

第二阶段对每一张基础帧都进行一次再编辑：

```text
case_base_frame01.png → case_edit_frame01.png
case_base_frame02.png → case_edit_frame02.png
...
case_base_frameNN.png → case_edit_frameNN.png
```

第二阶段目标包括：

- 在 base frame 的基础上保持剧情连续性；
- 对所有帧统一进行电影级视觉增强；
- 为每一帧选择合适的镜头策略；
- 增加最终多帧分镜的镜头多样性；
- 修复 base frame 中可通过编辑解决的小瑕疵；
- 统一角色、场景、光照、氛围和风格；
- 输出完整的 `case_edit_frame01.png` 到 `case_edit_frameNN.png`；
- 最终分镜默认使用 edited frames。

## 2. 总体流程

### Step 1：接收用户输入

用户通常输入：

- 一个简单 idea；
- 可选：参考帧数量 N；
- 可选：视频时长需求，例如“短一点”“5秒左右”“不要太长”；
- 可选：风格、人物数量、场景数量、关键道具、关键动作；
- 可选：每帧是否一次生成多张候选图；
- 可选：是否需要第二阶段全帧再编辑。

### Step 2：资源图内容审查与剧情落点校准

在资源库候选图选定之后、正式规划 base frames 之前，模型必须执行一次资源图内容审查。该步骤用于把用户 idea 落地到真实可见的资源图中。

必须输出或内部确认：

1. **人物参考可用信息**：人物正面/侧面/背面细节、服装、发型、配饰、哪些细节适合后续继承；
2. **场景参考可用锚点**：场景主视角、桌子位置、窗户位置、书架布局、地面纹理、门口/台阶/柱子是否真实存在；
3. **道具参考可用信息**：道具形状、大小、材质、发光状态、适合放置在哪类场景表面；
4. **不可用锚点清单**：用户 idea 中提到但当前场景图里并不存在、不能直接写进 base prompt 的元素；
5. **剧情落点调整**：根据真实锚点决定每一帧人物应该从哪里开始、到哪里去、与哪个物体交互。

如果用户 idea 与场景参考图冲突，应优先保持场景图一致，并在可见锚点内调整剧情。例如：用户说“进入藏书阁”，但 `case_scene_01.png` 是室内桌旁视角且没有入口门槛，则第一帧可以改为人物已经站在中央木桌旁、月光区域内或书架之间；不能凭空生成新的入口门槛。

### Step 3：决定帧数模式

模型首先判断帧数模式：

#### 情况 A：用户明确指定 N

直接使用用户指定的 N。

示例：

```text
用户：单人物单场景，6帧。
模型：使用 N=6，不再默认 9 宫格。
```

#### 情况 B：用户没有指定 N，但剧情是标准完整剧情

默认使用 N=9 标准模式。

```text
用户：一个年轻修士进入藏书阁，发现玉简，触发封印，地图浮现，最后离开。
模型：该剧情包含完整起承转合，默认使用 9 帧。
```

#### 情况 C：用户没有指定 N，但明确说视频短或参考帧少

模型主动建议 N=5 或 N=6，并说明理由。

```text
用户：这个视频不用太长，给几个关键帧就行。
模型：建议使用 N=6，保留开场、靠近、触碰、触发、结果、收束六个关键节点。
```

#### 情况 D：用户只给了极短动作

可以使用 N=4 或 N=5。

```text
用户：人物走到桌边拿起玉简然后离开。
模型：建议使用 N=5。
```

### Step 4：整体策划

首次响应时，模型输出：

1. 视频概述；
2. 帧数选择：`N=...`；
3. 帧数选择理由；
4. 最少人物、场景、道具数量；
5. 资源库构建 prompt；
6. 资源图内容审查结果：可用场景锚点、不可用锚点、剧情落点调整；
7. 第一阶段基础剧情帧规划；
8. `case_base_frame01.png` 的开场镜头意图与人物朝向选择理由；
9. 只给出 `case_base_frame01.png` 的英文一段式 prompt。

不要一次性给出所有基础帧的详细 prompt。只给当前要生成的一帧。

### Step 5：第一阶段逐帧生成基础帧

逐帧生成：

```text
case_base_frame01.png
case_base_frame02.png
...
case_base_frameNN.png
```

每一帧必须先确定唯一镜头类型：

```text
wide shot
```

或：

```text
medium shot
```

最终 prompt 里只能写一个确定镜头，不能写 `wide shot or medium shot`，不能写 `wide / medium shot`，不能写 `either wide shot or medium shot`，也不能使用任何含糊的选择式表达。

### Step 6：完成基础帧后进行整体质检

当 `case_base_frame01.png` 到 `case_base_frameNN.png` 全部完成后，模型需要进行整体检查：

- N 是否符合用户需求；
- N 帧是否能完整读出剧情；
- 是否因为帧数过少导致关键因果缺失；
- 人物是否一致；
- 场景是否一致；
- 关键道具是否连续；
- 位置推进是否清楚；
- 是否存在某张基础帧严重错误，不能作为再编辑输入；
- 哪些基础帧只有轻微瑕疵，可以通过第二阶段修复；
- 哪些基础帧需要在进入第二阶段前先重生成。

只有基础帧通过“基础可编辑性检查”后，才进入第二阶段。

### Step 7：第二阶段全帧再编辑规划

第二阶段必须查看完整基础帧集合，并为每一帧生成编辑计划。

不论 N 是多少，所有基础帧都必须进入再编辑：

```text
case_base_frame01.png → case_edit_frame01.png
case_base_frame02.png → case_edit_frame02.png
...
case_base_frameNN.png → case_edit_frameNN.png
```

### Step 8：逐帧生成 edited frames

对每一张基础帧生成再编辑版本：

```text
case_edit_frame01.png
case_edit_frame02.png
...
case_edit_frameNN.png
```

再编辑 prompt 必须以对应 `case_base_frame0x.png` 为主参考。

### Step 9：最终分镜整理

最终分镜默认使用：

```text
case_edit_frame01.png
case_edit_frame02.png
...
case_edit_frameNN.png
```

可以统一重命名为：

```text
case_final_frame01.png
case_final_frame02.png
...
case_final_frameNN.png
```

## 3. 帧数选择与 9 宫格衍生规则

### 3.1 9 宫格核心模式保持不变

当 N=9 时，使用标准 9 宫格节奏，不进行压缩：

| 帧 | 剧情功能 | 推荐基础镜头 | 说明 |
|---|---|---|---|
| case_base_frame01.png | 建立人物与场景 | wide shot | 显示人物、场景、主要锚点 |
| case_base_frame02.png | 人物进入行动位置 | wide shot | 显示人物新位置和落点 |
| case_base_frame03.png | 人物开始关键动作 | medium shot | 保留身体、手部、附近锚点 |
| case_base_frame04.png | 人物与道具或目标物接近 | medium shot | 显示接近后的最终状态 |
| case_base_frame05.png | 关键道具或环境发生变化 | medium shot | 显示人物、道具、变化状态 |
| case_base_frame06.png | 力量或剧情升级 | wide shot | 显示人物与环境变化关系 |
| case_base_frame07.png | 人物获得结果或完成动作 | medium shot | 显示人物和结果状态 |
| case_base_frame08.png | 人物离开或转向下一状态 | wide shot | 显示人物位置变化 |
| case_base_frame09.png | 收束或余波 | wide shot | 显示最终环境和人物状态 |

核心原则：

```text
N=9 时不启用压缩逻辑，直接沿用标准 9 宫格逻辑，保证原有效果不被升级影响。
```

### 3.2 任意帧模式由 9 宫格骨架压缩或扩展

对于 N≠9 的情况，模型不应随意规划，而应先在内部建立 9 宫格标准骨架，再根据 N 进行压缩、合并或扩展。

标准 9 beat 可以抽象为：

| 标准 beat | 功能 |
|---|---|
| B1 | 开场：人物与场景关系 |
| B2 | 进入行动位置 |
| B3 | 开始关键动作 |
| B4 | 接近或触碰关键目标 |
| B5 | 目标物或环境首次变化 |
| B6 | 冲突、力量或变化升级 |
| B7 | 结果出现或信息显现 |
| B8 | 人物处理结果、转身或离开 |
| B9 | 收束、余波或环境状态 |

任意 N 的规划就是在这 9 个 beat 中选择、合并或细分。

### 3.3 常用短帧数映射

#### N=4：极简起承转合

适合单动作、单转折、单结果。

| 帧 | 合并 beat | 剧情功能 |
|---|---|---|
| 01 | B1 | 开场，建立人物与目标 |
| 02 | B3+B4 | 人物开始并完成关键接触动作 |
| 03 | B5+B6+B7 | 变化发生并给出结果 |
| 04 | B8+B9 | 人物离开或环境收束 |

注意：N=4 不适合复杂动作链。若用户 idea 包含多个动作、多个道具状态或明显高潮，建议 N=5 或 N=6。

#### N=5：短视频推荐模式

适合 4–6 秒短视频或简单完整剧情。

| 帧 | 合并 beat | 剧情功能 |
|---|---|---|
| 01 | B1 | 开场，人物与场景 |
| 02 | B2+B3 | 人物到达行动位置并开始动作 |
| 03 | B4+B5 | 关键接触，目标物变化开始 |
| 04 | B6+B7 | 变化升级并出现结果 |
| 05 | B8+B9 | 人物处理结果或收束 |

#### N=6：短剧情稳定模式

适合用户想要“比 5 帧更稳，但不想 9 帧太长”的情况。

| 帧 | 合并 beat | 剧情功能 |
|---|---|---|
| 01 | B1 | 开场，人物与场景 |
| 02 | B2 | 人物到达行动位置 |
| 03 | B3+B4 | 开始关键动作并接触目标 |
| 04 | B5+B6 | 目标物变化并升级 |
| 05 | B7 | 结果显现 |
| 06 | B8+B9 | 人物处理结果或收束 |

#### N=7：保留更多动作过程

适合有明确动作过程，但仍希望少于 9 帧。

| 帧 | 合并 beat | 剧情功能 |
|---|---|---|
| 01 | B1 | 开场 |
| 02 | B2 | 到达行动位置 |
| 03 | B3 | 开始动作 |
| 04 | B4+B5 | 接触目标并触发变化 |
| 05 | B6 | 变化升级 |
| 06 | B7 | 结果显现 |
| 07 | B8+B9 | 收束 |

#### N=8：接近标准 9 宫格

适合剧情基本完整，但需要略微缩短。

建议合并 B8 与 B9，或者合并 B3 与 B4。

### 3.4 N 大于 9 的扩展规则

当 N>9 时，不要机械增加无意义帧，应优先细分以下位置：

- 人物进入过程；
- 接近目标物的过程；
- 手部与道具接触前后的状态；
- 目标物变化的不同阶段；
- 高潮帧中的力量变化；
- 结果显现后的反应；
- 离开与余波之间的过渡。

示例：N=12 时，可以在标准 B3、B4、B5、B6 中各拆出一个更细状态，而不是增加重复开场或重复收束。

### 3.5 帧数过少时的风险提示

当用户指定 N 很少但剧情复杂时，模型应保留用户需求，同时简短提醒：

```text
该剧情如果使用 5 帧，会压缩部分动作过程；我会保留最关键的因果节点，让视频生成模型补充中间运动。
```

不要强行改成 9 帧，除非用户允许。

## 4. 命名规则

### 4.1 资源库命名

- 人物参考图：`case_char_01.png`
- 多人物参考图：`case_char_02.png`、`case_char_03.png`
- 场景参考图：`case_scene_01.png`
- 多场景参考图：`case_scene_02.png`

## 5. 资源库构建规则

资源库构建规则与 v6.3 保持一致。

### 5.1 人物参考图

人物参考图用于锁定完整角色形象，不是只锁定脸部。

应包含：

- 全身入镜；
- 正面或 3/4 正面视角；
- 发型、发饰、脸型、服装轮廓、腰带、袖口、靴子、配饰清楚；
- 纯色或简洁背景；
- 不要场景、复杂特效、额外人物。

示例：

```text
Generate case_char_01.png: a full-body character reference sheet of Wang Lin, a young male Chinese fantasy cultivator with black hair tied in a high topknot, wearing a dark blue robe with silver embroidery, a waist belt, long sleeves, black boots, and small jade accessories, standing naturally from head to toe on a plain light background, front three-quarter view, clear facial structure, hairstyle, outfit silhouette, sleeve details, belt, boots, no scene, no magic effects, no extra characters, cinematic Chinese fantasy 3D animation style.
```

### 5.2 场景参考图

场景参考图不仅要锁定氛围，还要主动生成可复用视觉锚点。

应包含：

- 空间结构；
- 关键地标或家具；
- 地面纹理；
- 台阶、门框、窗户、石柱、桌角、桌面边缘、圆形纹路等可定位元素；
- 光源方向；
- 最好不要人物。

示例：

```text
Generate case_scene_01.png: an empty ancient lava cave interior, clearly showing the spatial layout with a central circular stone platform, multi-ringed circular texture on the platform surface, surrounding molten lava flows, platform edge stones, rocky walls, cave opening, stalactites, and dim orange ambient lighting from the lava, no characters, no props, pure environment reference, cinematic Chinese fantasy 3D animation style.
```

### 5.3 道具参考图

若剧情依赖关键道具，则单独生成道具图。

道具参考图应锁定：

- 外形；
- 材质；
- 大小比例；
- 纹理；
- 发光状态；
- 朝向；
- 纯色背景或简单台面。

## 6. 资源图约束剧情规划规则

这是 v6.5 的核心新增规则。资源图不是单纯的风格参考，而是后续分镜规划的硬约束。模型必须先看已选资源图的具体内容，再规划剧情节点和人物落点。

### 6.1 Resource-Conditioned Story Planning

用户 idea 只是剧情意图，不能直接等同于最终分镜落点。资源库生成并选定后，模型必须根据资源图重新校准剧情。

必须先列出或内部确认：

| 资源 | 必须检查的内容 | 作用 |
|---|---|---|
| `case_char_01.png` | 人物可见面、服装、发型、配饰、体型 | 锁定人物身份，不主导场景构图 |
| `case_scene_01.png` | 主视角、桌子/窗户/书架/门口/地面/光源等真实锚点 | 锁定空间结构与人物落点 |
| `case_prop_01.png` | 道具形状、材质、大小、发光状态 | 决定道具在场景中的放置方式与状态变化 |

如果用户 idea 与资源图不完全匹配，必须以资源图为准调整分镜。例如：用户说“人物进入藏书阁”，但场景图只展示室内中央木桌、破窗、书架和石地面，没有入口门槛，则第一帧可以改成“人物已经站在中央木桌旁观察玉简”，而不是发明一个新门口。

### 6.2 Scene-First Composition Lock

单场景工作流中，`case_scene_01.png` 必须作为空间构图主参考。尤其是 `case_base_frame01.png`，prompt 应优先写场景继承，再写人物身份继承。

推荐写法：

```text
Use case_scene_01.png as the primary composition reference for the exact abandoned library interior, including the central wooden table position, broken window position, left and right bookshelf rows, stone floor texture, moonlight direction, and original room viewpoint. Use case_char_01.png for the character identity, hairstyle, robe, belt, sleeves, and boots.
```

不推荐写法：

```text
Use case_char_01.png for the character identity, and use case_scene_01.png for the library atmosphere.
```

原因：后者会让角色参考图成为主导，场景图只被继承为“书架、月光、氛围”，容易导致人物正确但场景构图被重新生成。

### 6.3 禁止发明不存在的场景锚点

base frame prompt 中只能使用资源图中真实可见的场景锚点。

如果 `case_scene_01.png` 中没有明显入口、门槛、台阶、门框，则禁止写：

```text
entrance threshold
inner stone step
doorway opening
standing just inside the entrance
large doorframe
```

如果 `case_scene_01.png` 中没有中央石台、石柱、祭坛、窗户，也同样不能写这些结构。

如果剧情必须依赖缺失锚点，有两种处理方式：

1. **调整剧情落点**：把人物放到已有锚点附近，例如中央桌旁、书架之间、窗边月光区域、地面书本旁；
2. **重生成场景图**：让新的 `case_scene_01.png` 明确包含入口、门槛、台阶或其他剧情需要的锚点。

核心原则：

```text
不要用 base frame prompt 临时创造场景。场景锚点不存在，就先改场景参考图；不改场景图，就必须在已有锚点内安排剧情。
```

### 6.4 开场剧情落点必须适配场景图

`case_base_frame01.png` 的开场位置不由用户 idea 中的抽象动作直接决定，而由开场意图和场景图可见锚点共同决定。

以藏书阁为例：

| 场景图真实内容 | 合理开场 | 不合理开场 |
|---|---|---|
| 有门口、门槛、台阶 | 人物站在门槛内侧或跨入房间 | 无 |
| 无门口，但有中央桌子 | 人物站在桌前或桌侧，正面/三分之二正面观察桌面 | 人物站在不存在的入口门槛 |
| 有破窗与月光区域 | 人物站在月光照亮的地面上，面向桌子或书架 | 人物站在新生成的走廊门口 |
| 有书架通道 | 人物站在左右书架之间的通道里 | 人物站在不存在的石台或台阶上 |

### 6.5 正确示例：基于已有藏书阁室内场景的正面开场

当场景图是“中央木桌 + 破窗 + 书架 + 石地面”的室内视角，而用户希望正面开场时，推荐从桌旁展开：

```text
Generate case_base_frame01.png: Use case_scene_01.png as the primary composition reference for the exact abandoned library interior, including the central sturdy wooden table in the lower middle of the frame, the broken window on the back-right wall, the moonlight beam direction, the left and right bookshelf rows, scattered old books on the stone floor, cool blue ambient lighting, and the original room viewpoint. Use case_char_01.png for the young cultivator's identity, black high topknot with jade hairpin, dark blue robe with silver cloud embroidery, waist belt, long sleeves, and black boots. Camera: wide shot, eye-level view, stable establishing composition, full-body three-quarter front view of the cultivator beside the central wooden table. The main subject is the young cultivator standing on the open stone floor slightly to the left of the central table's front edge, with his body turned three-quarters toward the camera and his gaze directed toward the tabletop where the ancient jade slip will rest. Clearly show his full-body posture, facial structure, robe collar, silver embroidery, waist belt, boots on the stone floor, the central wooden table beside him, the broken window on the back-right wall, moonlight beams, bookshelf rows, scattered books, and floating dust in the air. Keep the original scene composition, table position, window position, bookshelf layout, moonlight direction, stone floor texture, and room viewpoint from case_scene_01.png unchanged. Do not create a new doorway, entrance threshold, stone steps, large doorframe, different room layout, extra characters, weapons, glowing effects, close-up framing, overhead view, or complex camera rotation. Cinematic Eastern fantasy 3D animation style.
```

## 7. 第一阶段：稳定基础帧规划规则

第一阶段的 base frames 不是电影镜头集合，而是剧情状态集合。

每一帧都要回答：

0. 当前剧情节点是否只使用了资源图或上一帧中真实存在的场景锚点？
1. 当前剧情节点是什么？
2. 该帧对应标准 9 beat 中的哪些 beat？
3. 这个 beat 是保留、合并还是扩展出来的？
4. 人物处于什么最终状态？
5. 人物和目标物的关系是什么？
6. 人物和镜头的关系是什么：正面、背面、侧面、三分之二正面还是三分之二背面？
7. 如果这是 `case_base_frame01.png`，开场镜头意图是什么：介绍人物、介绍空间、人物进入、道具引入还是悬念建立？
8. 如果这是 `case_base_frame01.png`，当前朝向选择是否服务于开场镜头意图，而不是默认背影？
9. 人物在场景中的落点是什么？
10. 关键道具处于什么状态？
11. 当前帧应该使用 `wide shot` 还是 `medium shot`？
12. 当前帧是否需要重新引用 `case_char_01.png`，还是只参考上一帧更稳定？
13. 这一帧是否适合作为第二阶段再编辑输入？
14. prompt 是否错误写入了场景图中不存在的入口、门槛、台阶、门框、柱子、窗户、桌子、石台等新锚点？

### 7.1 基础帧镜头硬性规则

基础帧阶段每一帧必须先在规划表中确定唯一镜头类型：

```text
Base camera: wide shot
```

或：

```text
Base camera: medium shot
```

最终 prompt 中必须写一个确定的 camera layer。

禁止写：

```text
Camera: wide shot or medium shot.
Camera: wide / medium shot.
Camera: either a wide shot or a medium shot.
Camera: use a suitable wide or medium view.
```

### 7.2 基础帧人物–镜头关系硬性规则

基础帧阶段不允许只通过剧情语义暗示人物朝向。每一帧 prompt 必须同时写明：

1. **Subject–Object Relation**：人物面向哪个目标物或正在与哪个目标物交互；
2. **Subject–Camera Relation**：镜头看到的是人物正面、背面、侧面、三分之二正面还是三分之二背面。

例如，人物站在桌前看玉简时，不能只写：

```text
facing the tabletop where the jade slip rests
```

应写成：

```text
facing the tabletop where the jade slip rests, with his back facing the camera
```

或：

```text
full-body back view of the cultivator; the table is directly in front of him and his back faces the camera
```

核心原则：

```text
人物面向目标物 ≠ 人物背对镜头。Subject–Object Relation 和 Subject–Camera Relation 必须分开判断，并且都写进 prompt。
```

### 7.3 开场朝向中立选择规则

`case_base_frame01.png` 没有默认朝向偏好。基础帧必须显式写明人物与镜头关系，但“显式写明”不等于“默认背影”。

- 开场重点是探索未知空间：可用 back view / three-quarter back view；
- 开场重点是介绍人物身份与状态：可用 front view / three-quarter front view；
- 开场重点是进入动作或横向移动：可用 side view / three-quarter side view。

核心原则：

```text
开场帧必须明确朝向，但朝向选择必须服务于开场叙事功能；背影只是可选方案，不是默认方案。
```

### 7.4 基础帧最小参考原则

第一阶段基础帧生成不应机械地使用“上一帧 + 角色参考图”的固定组合。基础帧的目标是稳定继承剧情、场景、镜头尺度和人物可见面，因此参考图应尽量少、尽量直接。

#### 优先只参考上一张基础帧的情况

如果当前帧只是以下变化，优先只参考上一张基础帧：

- 人物从一个位置移动到另一个位置；
- 人物仍然是同一种可见面；
- 镜头尺度没有显著变化；
- 场景、光源、人物服装、人物比例基本稳定；
- 当前目标是继承上一帧的构图距离和人物朝向，而不是重新展示角色细节。

推荐写法：

```text
Use case_base_frame01.png for the cultivator's character identity, current back-view robe silhouette, black high ponytail, library layout, moonlight direction, stone floor texture, bookshelf positions, central table outline, and the overall shot distance.
```

#### 需要重新引用 `case_char_01.png` 的情况

只有当当前帧发生以下变化时，才建议重新引入角色参考图：

- 从背影切到正面，或从正面切到背影；
- 人物可见面发生明显变化；
- 镜头从 wide shot 变为 medium shot，且人物细节明显放大；
- 上一帧人物身份、发型、服装已经漂移；
- 当前帧有显著姿态变化，上一帧不足以提供稳定人物信息；
- 当前帧需要清楚展示正脸、胸前服饰、手部细节或配饰。

## 9. 第一阶段候选选择规则

当用户上传同一基础帧的多个候选图时，模型必须先执行基础帧候选选择。

### 9.1 基础帧选择优先级

1. **Frame Count Fit**：是否符合当前 N 帧规划中的剧情节点；
2. **Scene Composition Accuracy**：是否继承 `case_scene_01.png` 的原始空间结构、主视角、关键物体位置、光源方向和真实锚点；
3. **No Invented Anchor**：是否没有生成场景图中不存在的入口、门槛、台阶、门框、石柱、窗户、桌子等新结构；
4. **Story State Accuracy**：是否准确表现当前剧情节点；
5. **Base Camera Accuracy**：是否符合指定的 `wide shot` 或 `medium shot`；
6. **Subject–Camera Accuracy**：人物相对镜头的正面、背面、侧面或三分之二视角是否正确；
7. **Opening Orientation Reasonableness**：如果是 `case_base_frame01.png`，朝向是否服务于开场镜头意图，而不是机械默认背影或正面；
8. **Subject–Object Accuracy**：人物是否正确面向、背向、侧对或接触目标物；
9. **Anchor Accuracy**：人物、道具是否落在指定真实场景锚点；
10. **Reference Stability**：候选图是否继承了上一帧的镜头尺度、人物比例和可见面；
11. **Character Consistency**：人物身份、发型、服装、体型是否稳定；
12. **Scene Continuity**：场景结构、光源、关键物体是否继承；
13. **Object State Continuity**：道具或环境状态是否正确；
14. **Editability**：是否适合作为第二阶段再编辑输入；
15. **Visual Quality**：是否清晰、无畸形、无错误元素。

## 10. 第二阶段：全帧再编辑规划规则

第二阶段不再选择“是否变换”，而是选择“如何编辑”。

所有基础帧都必须进入再编辑：

```text
case_base_frame01.png → case_edit_frame01.png
case_base_frame02.png → case_edit_frame02.png
...
case_base_frameNN.png → case_edit_frameNN.png
```

多模态大模型需要为每一帧决定：

- 编辑目标；
- 编辑强度；
- 镜头策略；
- 需要修复的瑕疵；
- 必须保持不变的剧情状态；
- 最终画面重点。

### 10.1 编辑强度分级

#### Level 1：Continuity-preserving cleanup

适合基础帧已经很稳定，只需要轻微修瑕和统一风格。

可做：

- 修正轻微手部、衣摆、发丝、道具边缘；
- 强化角色轮廓；
- 稳定光照和色调；
- 清理杂乱背景；
- 保持原镜头和构图。

不做：

- 改变人物位置；
- 改变人物朝向；
- 改变景别；
- 改变道具状态。

#### Level 2：Cinematic polish

适合基础帧构图正确但画面表现力不足。

可做：

- 调整构图重心；
- 增强前景、中景、背景层次；
- 强化光影和氛围；
- 让人物、道具或环境重点更清楚；
- 保持原来的 wide shot 或 medium shot。

#### Level 3：Moderate camera reframe

适合当前帧需要更强电影感，但仍要保留大部分空间关系。

可做：

- wide shot 改为 stronger wide shot；
- medium shot 改为 medium close-up；
- 改为三分之二侧面；
- 增加轻微低角度或高角度；
- 强化主体比例。

#### Level 4：Strong cinematic transformation

适合关键动作、关键道具、高潮或结果帧。

可做：

- close-up；
- insert shot；
- overhead view；
- low-angle view；
- over-the-shoulder view；
- foreground framing；
- dramatic but controlled camera composition。

注意：

- Level 4 只适合剧情关键帧；
- 不能所有帧都使用强变换；
- 强变换帧必须能从 base frame 继承核心剧情状态。

### 10.2 镜头多样性预算随 N 调整

虽然所有帧都要编辑，但不代表每一帧都要强行使用复杂镜头。

#### N=4

- 1–2 帧 wide shot；
- 1 帧 medium / medium close-up；
- 1 帧可使用 Level 4 强变换；
- 其余保持清晰连续。

#### N=5

- 2 帧 wide shot，用于开场和收束；
- 1–2 帧 medium / medium close-up；
- 1 帧 insert / close-up / low-angle / over-the-shoulder；
- 最多 2 帧 Level 4。

#### N=6

- 2 帧 wide shot；
- 2 帧 medium / medium close-up；
- 1 帧 insert / close-up；
- 1 帧 over-the-shoulder / overhead / low-angle；
- 最多 2–3 帧 Level 4。

#### N=9

保持 v6.3 的 9 宫格预算：

- 2–3 帧保留或强化 wide shot；
- 2–3 帧使用 medium / medium close-up；
- 1–2 帧使用 insert shot；
- 1 帧使用 overhead / high-angle；
- 1 帧使用 low-angle / over-the-shoulder。

核心原则：

```text
N 越少，越不能乱用复杂镜头；短帧数中每一帧都承担关键剧情功能，镜头变化必须服务于剧情阅读。
```

## 11. 第二阶段再编辑 Prompt 规则

再编辑 prompt 必须以对应基础帧为主参考。

每个再编辑 prompt 必须包含：

1. 文件名；
2. 参考哪个 `case_base_frame0x.png`；
3. 从基础帧继承哪些内容；
4. 本帧编辑目标；
5. 本帧编辑强度；
6. 明确的镜头策略；
7. 当前镜头下应该出现的可见内容；
8. 需要修复或优化的基础帧瑕疵；
9. 当前镜头下不应该出现的内容；
10. 保持剧情状态不变；
11. 风格句。

### 11.1 再编辑参考图原则

第二阶段默认只参考对应基础帧：

```text
Use case_base_frame04.png as the primary reference for the exact story state, character position, object state, scene layout, lighting direction, and visible spatial anchors.
```

只有在以下情况下，才额外引用 `case_char_01.png`：

- base frame 人物身份已经轻微漂移；
- edited frame 要展示正脸或更清楚的人物细节；
- 需要修复发型、服装、配饰；
- 基础帧中人物太小，无法提供足够身份细节。

只有在以下情况下，才额外引用 `case_scene_01.png`：

- base frame 场景结构轻微漂移；
- edited frame 需要恢复关键空间锚点；
- 基础帧背景细节不清，但剧情仍正确。

每个 prompt 仍建议最多参考两张图。

### 11.2 再编辑 Prompt 最小模板

```text

```

## 12. 位置锚点定位规则

位置锚点规则在两个阶段都必须使用。

### 12.1 必须使用场景内可见锚点

当 prompt 描述人物或道具位置时，优先使用场景图、基础帧或编辑帧中已经存在、视觉明确的锚点。

推荐：

```text
The figure stands at the center of the multi-ringed circular texture on the stone platform.
```

```text
The character stands just behind the front edge stones of the circular platform, aligned with the center ring pattern.
```

```text
The jade scroll lies on the empty wooden surface between the brush holder and the red seal, above the front edge of the table.
```

不推荐：

```text
The character stands in the center of the platform.
The object is on the right side of the table.
The figure stands near the pillar.
```

### 12.2 再编辑阶段也必须保留锚点

第二阶段不能因为镜头电影化而丢失关键锚点。即使是特写或插入镜头，也应保留足够的局部锚点，例如：

- 桌面木纹；
- 玉简与手指接触点；
- 袖口颜色；
- 地面纹理；
- 平台圆环纹理；
- 石柱底座边缘；
- 光纹扩散方向。

核心原则：

```text
基础帧用锚点锁剧情；编辑帧用锚点保连续。
```

### 12.3 不用 distance，用可见关系

控制人物与目标物远近时，禁止只写：

```text
closer to the pillar
farther from the pillar
reduced distance
near the object
move two steps forward
```

应写最终画面中的可见关系。

## 13. 朝向关系规则

写每一帧 prompt 前，必须先判断两个关系：

1. **Subject–Object Relation**：人物面向目标物、背向目标物、侧对目标物，还是正在接触目标物；
2. **Subject–Camera Relation**：人物面向镜头、背对镜头、侧对镜头，还是过肩、俯视或局部。

### 13.1 人物面向镜头时

可以描述：

- facial structure；
- eyes；
- gaze；
- front robe pattern；
- collar；
- chest；
- belt；
- sleeves；
- hands in front of the body。

### 13.2 人物背对镜头时

必须避免：

- facial structure；
- facial expression；
- calm face；
- eyes closed；
- focused expression；
- handsome face；
- looking at the camera。

应描述：

- back of hairstyle；
- back of head；
- shoulder line；
- back-view robe folds；
- waist belt from behind；
- sleeves from behind；
- boots；
- stable stance；
- target object in front of him。

### 13.3 再编辑阶段的朝向规则

第二阶段可以改变镜头角度，但不能随意改变人物与目标物关系。

例如：

- base frame 中人物面向桌面玉简，edited frame 可以从正面、侧面或过肩展示；
- 但不能让人物变成背向玉简；
- 不能让人物动作从“未触碰”变成“已经拿起”；
- 不能让人物从桌前移动到窗边；
- 不能让镜头重构改变剧情状态。

核心原则：

```text
镜头可以变，剧情状态不能变；相机位置可以变，人物与目标物的关系不能乱变。
```

## 14. Camera Layer 规则

每一帧 prompt 必须包含 camera layer。

### 14.1 第一阶段 Camera Layer

第一阶段只允许明确使用：

```text
Camera: wide shot, ...
```

或：

```text
Camera: medium shot, ...
```

第一阶段禁止使用不确定表达：

```text
wide shot or medium shot
wide / medium shot
suitable camera distance
appropriate shot size
```

### 14.2 第二阶段 Camera Layer

第二阶段允许使用：

```text
wide shot
medium shot
medium close-up
close-up
insert shot
eye-level view
low-angle view
high-angle view
overhead view
over-the-shoulder view
back view
side view
foreground framing
```

但不能只写镜头术语，必须写清楚当前镜头下的可见内容。

推荐：

```text
Camera: insert shot, slightly high-angle view, the fingertips, sleeve cuffs, and glowing object surface fill most of the frame.
```

不推荐：

```text
Camera: insert shot.
```

## 15. 禁止误导词规则

以下词在两个阶段都应尽量避免。

### 15.1 抽象距离词

不推荐：

```text
closer
farther
near
reduced distance
increased distance
```

推荐使用脚、手、道具与场景锚点之间的可见关系。

### 15.2 模糊程度词

不推荐：

```text
slightly
subtly
a little
partially visible
```

推荐：

```text
only the back of the head and right shoulder are visible
```

```text
the eyes, nose, mouth, and side face are not visible
```

### 15.3 第一阶段选择式镜头词

基础帧 prompt 中禁止：

```text
wide shot or medium shot
wide / medium shot
either wide shot or medium shot
a suitable full or medium view
```

必须改成：

```text
Camera: wide shot, ...
```

或：

```text
Camera: medium shot, ...
```

### 15.4 再编辑阶段禁止词

第二阶段再编辑 prompt 中应避免：

```text
redesign the whole scene
create a new version of the scene
change the story
make a new pose
move the character
different object state
new location
```

推荐使用：

```text
re-edit the same moment
preserve the exact story state
keep the character position unchanged
keep the object state unchanged
improve the cinematic composition
clean up minor defects
```

## 17. 两阶段质检规则

### 17.1 第一阶段基础帧质检

检查：

- N 是否符合用户指定或模型推荐；
- 如果 N=9，是否使用标准 9 宫格逻辑；
- 如果 N≠9，是否从 9 beat 骨架合理压缩或扩展；
- 是否因为压缩帧数导致关键因果缺失；
- 是否使用唯一确定的 `wide shot` 或 `medium shot`；
- prompt 是否出现 `or`、`either`、`/` 这类选择式镜头表达；
- prompt 是否显式写明人物与镜头关系；
- 如果是 `case_base_frame01.png`，是否写明开场镜头意图和朝向选择理由；
- 如果是 `case_base_frame01.png`，是否避免机械默认背影开场；
- 当前帧是否遵循最小参考原则；
- 当前帧是否遵循资源图约束剧情规划，没有使用资源图中不存在的场景锚点；
- `case_scene_01.png` 的主构图、主视角、关键物体位置和光源方向是否被继承；
- 人物是否落在指定真实场景锚点；
- 场景结构是否完整稳定；
- 角色身份是否一致；
- 道具状态是否承接；
- 当前帧是否适合作为第二阶段再编辑输入。

### 17.2 第二阶段编辑帧质检

检查：

- 是否从正确的 `case_base_frame0x.png` 再编辑；
- 是否保留基础帧的剧情状态；
- 是否保留人物身份、服装、发型；
- 是否保留道具状态和环境状态；
- 是否实现规划中的编辑策略；
- 是否修复或改善了基础帧中的轻微瑕疵；
- 镜头下应该可见的细节是否清楚；
- 镜头下不应该出现的结构是否没有出现；
- 是否与前后 edited frames 保持节奏和连续性；
- 是否比基础帧更适合作为最终电影镜头。

## 18. 重生成判定

### 18.1 基础帧需要重生成的情况

出现以下情况，应重生成基础帧：

- 用户指定 N，但规划帧数不一致；
- N≠9 时，压缩后缺失关键因果节点；
- N=9 时，错误使用了任意帧压缩逻辑；
- prompt 中使用了不确定镜头表达；
- prompt 没有显式写明人物与镜头关系；
- `case_base_frame01.png` 机械默认背影开场，且该 idea 更适合人物介绍、桌面线索展示或正面氛围开场；
- 候选图中人物应背对镜头却变成正对镜头，或应侧对镜头却变成正面展示；
- 当前帧只是连续移动，却不必要地引用 `case_char_01.png` 并导致镜头拉近、人物转正或构图改变；
- prompt 或候选图发明了 `case_scene_01.png` 中不存在的入口、门槛、台阶、门框、石柱、窗户、桌子、石台等关键场景锚点；
- 候选图只继承了场景氛围但没有继承场景参考图的原始构图、桌子位置、窗户位置、书架布局或光源方向；
- 画面不是指定的 `wide shot` 或 `medium shot`；
- 人物位置没有对齐场景锚点；
- 人物身份、服装、发型明显变化；
- 场景结构被错误改变；
- 道具状态不符合剧情；
- 人物朝向与目标物关系错误；
- 当前帧镜头过于复杂，不适合作为再编辑输入。

### 18.2 编辑帧需要重生成的情况

出现以下情况，应重生成编辑帧：

- 再编辑没有保留基础帧的剧情状态；
- 再编辑后人物位置变化；
- 再编辑后道具状态变化；
- 再编辑后角色身份不一致；
- 再编辑后场景变成另一个地点；
- 规划中的镜头策略没有实现；
- 特写或局部镜头没有展示该镜头应有的细节；
- 背面或过肩镜头错误露出正脸；
- 新增无关角色、武器、道具或环境效果；
- 为了电影感过度重构，导致与前后帧不连续。

### 18.3 允许保留 base frame 的异常情况

标准流程中最终帧应来自 `case_edit_frame0x.png`。只有在以下情况下，允许保留对应 base frame 作为最终帧：

- 多次再编辑均破坏剧情状态；
- base frame 本身已经视觉质量很高；
- edited frame 无法稳定保持人物、道具或场景；
- 用户明确要求保留 base frame。

此时必须在最终整理表中说明原因。

## 20. 一句话总结

v6.5 的核心不是替换 9 宫格，而是在保留 9 宫格核心效果和任意帧数能力的基础上，加入资源图约束剧情规划：

```text
Keep the 9-frame workflow as the stable core mode, derive arbitrary frame counts from the 9-beat story skeleton when shorter or longer reference sets are needed, condition storyboard planning on the selected character, scene, and prop references, then re-edit every base frame to preserve continuity, fix minor defects, and improve cinematic quality.
```

中文概括：

```text
9宫格仍然是核心保底模式；当用户需要更短或更长的视频时，再从9宫格叙事骨架压缩或扩展出任意帧数。所有分镜规划必须先受已选人物、场景、道具参考图约束，不能发明场景图中不存在的锚点，并继续执行全帧再编辑。
```
