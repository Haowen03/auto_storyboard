# 多宫格分镜参考帧生成工作流（v6.7：镜头再设计优先 + 单人物单视角资源图约束）

## 0. 版本定位

v6.7 在 v6.6 的基础上修正两个问题：

1. **第二阶段“全帧再编辑”容易退化成轻微修图。**  
   v6.6 虽然写了“全帧再编辑”，但实际执行时容易把重点放在补光、清理背景、修复衣摆、统一色调等弱编辑上，导致 `case_edit_frame0x.png` 与 `case_base_frame0x.png` 几乎一致。v6.7 将第二阶段明确改为 **全帧镜头再设计**：主要目标是镜头切换、景别变化、机位变化、构图重排和视觉重点变化；补光、修瑕、风格统一只是附带效果。

2. **人物参考图 prompt 容易被误写成多视角展示。**  
   如果 prompt 写成 `front view and three-quarter front view are clearly visible`，模型容易理解为“同一张图里同时展示正面和三分之二正面”，从而生成多个并排人物。v6.7 回退并加强 v6.1 的人物资源图规则：人物参考图必须是 **单人物、单姿势、单视角、全身图**。禁止多视图角色设定图、并排重复人物和多个姿势。

v6.7 的核心原则：

```text
Base frames lock story continuity. Edit frames must redesign the camera.
Character reference images must contain one character, one pose, and one view only.
```

---

## 1. 总体流程

```text
Step 1  接收用户 idea、帧数 N、风格和特殊要求
Step 2  生成资源图：人物、场景、道具
Step 3  审查资源图：可用锚点、不可用锚点、场景核心
Step 4  规划 N 张 base frames
Step 5  逐帧生成 case_base_frame01.png 到 case_base_frameNN.png
Step 6  基础帧质检：剧情、场景、角色、锚点、相机侧连续
Step 7  第二阶段全帧镜头再设计规划
Step 8  逐帧生成 case_edit_frame01.png 到 case_edit_frameNN.png
Step 9  最终分镜默认使用 edited frames
```

---

## 2. 帧数规则

- 用户未指定帧数：默认 N=9。
- 用户明确指定 N：严格使用用户指定的 N。
- 用户只说“短一点”“不要太长”：优先建议 N=5 或 N=6。
- N=9 时保持 9 宫格核心逻辑不变。
- N≠9 时，由标准 9 beat 骨架压缩或扩展得到。

标准 9 beat：

| Beat | 功能 |
|---|---|
| B1 | 开场：人物与场景关系 |
| B2 | 到达行动位置 |
| B3 | 开始动作 |
| B4 | 接近/接触目标 |
| B5 | 首次变化 |
| B6 | 变化升级 |
| B7 | 结果显现 |
| B8 | 处理结果/离开 |
| B9 | 收束/余波 |

短帧数推荐：

- N=5：B1 / B2+B3 / B4+B5 / B6+B7 / B8+B9
- N=6：B1 / B2 / B3+B4 / B5+B6 / B7 / B8+B9

## 3. 资源图生成规则

### 3.1 人物参考图：单人物、单姿势、单视角

人物参考图用于锁定角色身份，不是用于生成多视角设定图。

必须满足：

- 一张图中只有一个人物；
- 一个自然站姿；
- 一个确定视角；
- 全身入镜，从头到脚完整；
- 简洁白底或浅色背景；
- 不要场景、特效、额外人物；
- 不要把正面和三分之二正面同时写进同一句。

推荐视角写法：

```text
front three-quarter view only
```

或：

```text
front view only
```

禁止写法：

```text
front view and three-quarter front view are clearly visible
```

```text
front and side views
```

```text
multiple views
```

```text
character sheet showing several angles
```

推荐人物资源图模板：

```text
Generate case_char_01.png: A single full-body character reference image of [character name], [identity and age], with [hair], wearing [outfit details], standing in one natural pose on a plain white background. Use front three-quarter view only, showing the face, hairstyle, collar, outfit silhouette, belt, sleeves, boots, and key accessories clearly. No scene, no magic effects, no extra characters, no repeated character, no multi-view reference sheet. Cinematic Chinese fantasy 3D animation style.
```

如果角色携带武器，必须明确武器位置：

```text
The weapon is strapped diagonally across his back, with the handle visible near one shoulder.
```

不要只写：

```text
carrying a weapon
```

因为这容易生成“手持武器”或多个展示姿势。

### 3.2 场景参考图

场景参考图用于锁定空间结构和可复用锚点。

应包含：空间结构、关键地标或家具、地面纹理、窗户、桌角、桌腿、门框、平台纹理等可定位元素、光源方向，并且无人物。

场景图中的锚点必须是真实可见的。后续 base frame 不能发明 scene reference 中不存在的入口、台阶、门框、石柱、楼梯或额外家具。

### 3.3 道具参考图

道具参考图用于锁定关键物体的形状、材质、大小、纹理、发光状态和朝向。道具应单独展示，不加复杂背景。

---

## 4. 资源图约束剧情规划

在规划 base frames 前，必须先审查资源图：

1. `case_char_01.png` 可继承哪些身份信息；
2. `case_scene_01.png` 真实存在哪些场景锚点；
3. `case_prop_01.png` 有哪些形态和状态；
4. 哪些锚点不存在，后续 prompt 不得提及。

核心原则：

```text
Storyboard planning must follow selected resource images.
```

如果用户 idea 提到“门口”，但场景图中没有门口，就不能在 base frame 中临时生成门口。应把剧情落点调整到真实锚点附近，例如桌旁、窗边、书架通道、平台中心等。

---

## 5. Scene Core / Character / Camera Topology Rule

每帧先确定 **Scene Core**，即当前帧最重要的信息中心。

常见 Scene Core：

- 开场帧：场景核心家具、窗户光源、主要空间结构；
- 观察帧：目标物所在桌面或平台；
- 接触帧：手部与道具接触点；
- 爆发帧：发光道具、尘埃、纸页、能量区域；
- 结果帧：浮现地图、剑、卷轴、光阵等结果物；
- 收束帧：残留光痕、人物离开方向、空场景。

根据人物朝向确定三者拓扑：

| 人物朝向 | 推荐拓扑 | 用法 |
|---|---|---|
| front / three-quarter front | Camera → Scene Core → Character | 人物站在场景核心远侧或侧后方，场景核心位于人物与镜头之间 |
| back / three-quarter back | Camera → Character → Scene Core | 人物位于镜头与目标之间，适合观察或操作目标 |
| side / three-quarter side | Character beside Scene Core, both visible | 人物在目标侧边，适合走近、观察、伸手、触碰 |

核心提醒：

```text
人物面向目标物 ≠ 人物必须背对镜头。
```

人物面对桌子时，也可以站在桌子远侧或侧边，让镜头同时看到脸和桌面。

---

## 6. Camera-Side Continuity Track

基础帧阶段要优先保持相机侧连续。

如果第一帧采用三分之二正面开场，后续相邻帧不应无理由突然变成正背影。只有以下情况才允许明显切侧：

1. 人物剧情上发生转身；
2. 镜头意图明确需要换侧；
3. Scene Core 发生变化，必须重新组织构图；
4. 收束或离开帧需要背影。

推荐 N=6 朝向节奏：

| 帧 | 剧情节点 | 推荐朝向 |
|---|---|---|
| frame01 | 开场建立人物与场景 | three-quarter front |
| frame02 | 走近/观察目标 | three-quarter front / three-quarter side |
| frame03 | 伸手接触目标 | three-quarter side |
| frame04 | 目标触发变化 | three-quarter side / three-quarter front |
| frame05 | 结果显现或结印 | front / three-quarter front |
| frame06 | 离开或收束 | back / three-quarter back |

---

## 7. Anchor Visibility Budget

基础帧不仅要使用真实锚点，还要让关键锚点可见。

如果 Scene Core 是桌面和道具，则至少要看到：

- 大部分桌面或核心区域；
- 一个桌角、桌腿或桌面边缘；
- 目标道具；
- 与目标相关的人物手部或视线；
- 主要光源方向。

如果人物挡住 Scene Core，即使人物质量高，也不应选择为正式 base frame。

---

## 8. 第一阶段 Base Frame 规则

基础帧用于锁定剧情骨架，不追求复杂镜头。

基础帧只使用：

```text
wide shot
medium shot
```

禁止在基础帧阶段主动使用 close-up、insert shot、overhead、over-the-shoulder、extreme low-angle 或 complex camera rotation。

每个 base frame prompt 必须包含：真实参考文件名、一个确定的基础镜头、当前 Scene Core、人物与 Scene Core 的拓扑关系、Subject–Object Relation、Subject–Camera Relation、关键锚点可见性和简短禁止项。

基础帧 prompt 应控制在 5–7 句，避免复制资源审查全文。

---

## 9. 第二阶段：全帧镜头再设计

这是 v6.7 的核心修正。

第二阶段不是“轻微再编辑”，而是 **基于 base frame 的镜头再设计**。

### 9.1 主目标

第二阶段的主目标是：

- 景别变化；
- 机位变化；
- 镜头侧变化；
- 构图重点变化；
- 视觉叙事重点变化；
- 镜头节奏变化。

附带目标才是：补光、修手、修衣摆、清理背景、统一色调。

核心原则：

```text
Camera transformation is the primary goal. Cleanup is only secondary.
```

### 9.2 Camera Delta Requirement

每个 `case_edit_frame0x.png` 相比对应 `case_base_frame0x.png`，默认必须产生明确镜头差异。

至少满足以下一项：

1. **Shot scale delta**：wide → medium close-up / medium → close-up / medium → insert；
2. **Camera angle delta**：eye-level → high-angle / low-angle / overhead；
3. **Camera side delta**：front → side / side → over-the-shoulder / back-side view；
4. **Composition delta**：主体从居中变为前景遮挡、框景、桌面前景、人物后景；
5. **Focus delta**：从人物整体转为手部、道具、眼神、地图、能量中心；
6. **Depth delta**：加入明确前景、中景、背景层次。

如果 edited frame 与 base frame 只是补光、锐化、清理背景，判定为失败。

### 9.3 允许保留基础构图的例外

每组分镜最多允许 1 帧只做轻微重构或保持基础构图，通常用于开场全景、收束全景或需要完整空间关系的关键帧。

即使保留基础景别，也必须有轻微镜头设计变化，例如更低或更高的机位、前景桌面更明确、人物更偏画面一侧、纵深层次更强。

不推荐纯粹写：

```text
cinematic polish
cleanup
improve lighting
```

作为主要编辑策略。

## 10. 第二阶段镜头多样性预算

### N=5

至少 3 帧有明确 camera delta：

- 1 帧 wide / establishing reframe；
- 1 帧 medium close-up；
- 1 帧 insert / close-up / over-the-shoulder / low-angle。

### N=6

至少 4 帧有明确 camera delta：

- 1–2 帧 wide 或 stronger wide shot；
- 1–2 帧 medium / medium close-up；
- 1 帧 insert / close-up；
- 1 帧 overhead / over-the-shoulder / low-angle。

最多 1 帧仅做轻微 polish。

### N=9

至少 6 帧有明确 camera delta：

- 2–3 帧 wide / stronger wide；
- 2–3 帧 medium / medium close-up；
- 1–2 帧 insert / close-up；
- 1 帧 overhead / high-angle；
- 1 帧 low-angle / over-the-shoulder。

禁止：

- 全部 edited frames 与 base frames 基本一致；
- 全部只是补光或统一色调；
- 全部使用同一种镜头变换；
- 为了镜头多样性改变剧情状态。

## 12. 第二阶段图像生成 Prompt 模板

### 12.1 精简模板

```text
Generate case_edit_frame0x.png: Use case_base_frame0x.png as the source for the exact story state, character identity, object state, scene layout, and lighting direction. Camera transformation: change the base [base shot] into [new shot type], with [new viewpoint or composition focus]. Reframe the same moment without changing the character position, action result, object state, or environment layout. Clearly show [details required by the new camera]. Keep [2-4 key continuity elements] unchanged. Do not keep the same shot scale and composition as the base frame, do not change the story beat, and do not add extra characters or unrelated effects. Cinematic Chinese fantasy 3D animation style.
```

### 12.2 插入镜头示例

```text
Generate case_edit_frame03.png: Use case_base_frame03.png as the source for the exact story state, character sleeve color, hand position, jade slip position, tabletop texture, and moonlight direction. Camera transformation: change the base medium shot into an insert shot from a slightly high angle, focusing on the fingertips, sleeve cuffs, jade slip surface, and contact point on the wooden table. Reframe the same moment without changing the contact state or object position. Keep the sleeve color, jade texture, tabletop grain, and lighting direction consistent. Do not show the full body, do not move the jade slip, do not add new glow if the base frame has not triggered it yet, and do not add extra characters. Cinematic Chinese fantasy 3D animation style.
```

### 12.3 过肩镜头示例

```text
Generate case_edit_frame05.png: Use case_base_frame05.png as the source for the exact story state, character position, jade slip state, floating map position, table layout, and moonlit library background. Camera transformation: change the base medium shot into an over-the-shoulder view from behind the character's right shoulder, with the back of the head and shoulder in the foreground and the floating map as the focus. Reframe the same moment without changing the map, jade slip, table, or character position. Keep the hairstyle, robe color, map position, and moonlight direction consistent. Do not show the full front face, do not move the map, and do not add new characters or weapons. Cinematic Chinese fantasy 3D animation style.
```

### 12.4 高角度/俯视示例

```text
Generate case_edit_frame04.png: Use case_base_frame04.png as the source for the exact story state, glowing jade slip, table position, character position, floating dust, and scattered papers. Camera transformation: change the base medium shot into a high-angle shot looking down at the tabletop, with the jade slip, cyan light pattern, hands, and flying papers arranged clearly in the frame. Reframe the same moment without changing the glow state, hand position, or table layout. Keep the cyan light, tabletop texture, sleeve color, and library lighting consistent. Do not change the story beat, do not move the character away from the table, and do not add extra characters. Cinematic Chinese fantasy 3D animation style.
```

## 13. 再编辑候选选择优先级

选择 `case_edit_frame0x.png` 时，优先级调整为：

1. **Camera Transformation Accuracy**：是否相对 base frame 产生明确镜头变化；
2. **Story State Preservation**：是否保留基础帧剧情状态；
3. **Camera Diversity Value**：是否为最终分镜提供新的镜头类型或构图价值；
4. **Subject/Object Continuity**：人物、道具、场景是否保持一致；
5. **Visible Detail Quality**：新镜头要强调的细节是否清楚；
6. **Anchor Preservation**：关键锚点是否仍可识别；
7. **Visual Quality**：是否清晰、无明显畸形。

如果候选图与 base frame 基本一样，即使画面更干净，也不应优先选择。

## 14. 重生成判定

### 14.1 人物资源图需要重生成

出现以下情况，应重生成人物参考图：

- 一张图中出现多个同一人物；
- 出现多视角并排展示；
- 出现多个姿势；
- 出现背景场景或特效；
- 武器位置与设定不一致；
- prompt 中写了 `front view and three-quarter front view` 这类双视角表达。

### 14.2 基础帧需要重生成

出现以下情况，应重生成 base frame：

- 使用了 scene reference 中不存在的锚点；
- 人物遮挡 Scene Core；
- 相机侧无理由跳变；
- 道具状态提前或滞后；
- 人物与目标物关系错误；
- 镜头不是指定的 wide / medium。

### 14.3 编辑帧需要重生成

出现以下情况，应重生成 edit frame：

- 与 base frame 几乎同景别、同机位、同构图；
- 只做了补光、锐化、清理背景；
- 没有实现规划中的 camera delta；
- 改变了剧情状态；
- 改变了人物位置或道具状态；
- 场景变成另一个地方；
- 新增无关人物或道具。

## 15. 执行口令

### 15.1 生成人物参考图前

1. Is this a single character?
2. Is there only one pose?
3. Is there only one view?
4. Did the prompt avoid writing two views such as `front view and three-quarter front view`?
5. Are extra characters, duplicated bodies, multi-view layouts, and scene backgrounds explicitly forbidden?

### 15.2 生成基础帧前

1. What is the story beat?
2. What is the Scene Core?
3. What is the base camera: wide or medium?
4. What is the subject-object relation?
5. What is the subject-camera relation?
6. What is the camera-side track?
7. What topology is used?
8. Are key anchors visible?
9. Is the image-generation prompt compact?

### 15.3 生成编辑帧前

1. What is the base camera?
2. What is the new edit camera?
3. What is the required camera delta?
4. What story state must remain unchanged?
5. What details should the new camera emphasize?
6. Does the prompt explicitly avoid keeping the same shot scale and composition?

---

## 16. 一句话总结

```text
v6.7 keeps base frames stable, but forces edit frames to redesign the camera rather than merely polish the image; it also restores character resource prompts to single-character, single-pose, single-view generation.
```

中文概括：

```text
基础帧继续负责剧情连续性；编辑帧必须负责镜头切换和镜头多样性，不能只做补光修图；人物资源图必须是单人物、单姿势、单视角，禁止多视图并排生成。
```
