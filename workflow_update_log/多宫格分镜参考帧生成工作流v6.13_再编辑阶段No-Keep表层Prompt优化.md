# 多宫格分镜参考帧生成工作流（v6.13：资源依赖调度优先 + 再编辑表层 Prompt 简化 + No-Keep 输出优化）

## 0. 版本定位


> v6.9 增补定位：在 v6.8 的资源依赖调度基础上，进一步解决“编辑帧仍然像中景平淡叙事”的问题。基础帧仍允许使用中景或远景来锁定剧情连续性，但编辑帧必须承担电影镜头再设计职责。对于 9 宫格输出，编辑阶段不再允许默认回退到普通中景；回退逻辑必须优先尝试 close-up、insert、overhead、low-angle、over-the-shoulder、foreground-depth 等特殊镜头。


> v6.10 增补定位：在 v6.9 的镜头多样性强约束基础上，进一步抑制“特殊镜头被写成微观细节清单”的问题。局部描述仍然用于引导视觉焦点，但不再鼓励堆叠纹理、火花、触点、背景虚化等过多细节。编辑帧必须同时满足两个条件：一是相对 base frame 形成明确电影镜头变化；二是保持剧情节点、主体关系和场景锚点的可读性。特殊镜头不能以牺牲叙事连续性为代价。


> v6.11 增补定位：在 v6.10 的基础上，针对再编辑阶段 prompt 进一步修正。实测表明，编辑阶段如果同时输入 base frame、人物资源图、道具资源图，反而容易干扰模型对当前画面状态的继承，导致身份、道具和构图被重新解释。因此 v6.11 将“资源依赖调度”和“最终表层 prompt”解耦：资源图仍用于 base frame 生成、内部审查和必要纠偏，但编辑阶段默认只把对应 `case_base_frame0x.png` 作为实际图像参考；最终 prompt 只描述当前画面想展示的内容、视觉焦点和镜头类型，不再堆叠人物资源、道具资源和过多约束。对于能力较弱的大模型，约束应放在结构化规划层和 prompt compiler 中，而不是全部塞进最终生成 prompt。


> v6.12 增补定位：在 v6.11 的基础上，进一步修正再编辑阶段表层 prompt 内部的职责重叠问题。再编辑 prompt 虽然应先描述画面、再描述镜头，但画面描述块只能说明当前剧情状态和画面中存在的关键元素，不能提前描述特写、焦点、近距离、前后景、景深、光影细节或镜头情绪。所有取景、焦点、构图、前后景关系和局部细节都必须集中到 `Camera transformation` 块中，由镜头块作为唯一的视觉焦点入口。这样可以避免同一视觉重点在画面块和镜头块中被重复强化，减少手部、道具、局部纹理或前景物体被模型过度放大的风险。


> v6.13 增补定位：在 v6.12 的 Prompt 分层解耦基础上，继续修正表层 prompt 中的显式保持句问题。实测发现，`Keep ... present in the frame`、`preserve ...`、`Reframe the same moment without altering ...`、`Clearly show ...` 这类句子虽然看似只是在保留元素，但会把内部审查项重新推回生成 prompt，导致模型过度维护局部元素、强行塞入所有被点名对象，进而干扰镜头再设计。v6.13 将 `keep` 信息彻底下沉到规划层和候选评估层：最终 edit prompt 不再输出独立的 Keep 句，不再罗列可见元素清单，只通过一句 story state 继承当前画面状态，再由 `Camera transformation` 描述镜头如何观看该状态。


v6.8 在 v6.7 的基础上修正一个更底层的问题：

**基础帧生成不应默认只参考上一帧。**

v6.7 已经明确：基础帧负责剧情连续性，编辑帧必须负责镜头再设计，人物资源图必须是单人物、单姿势、单视角。但是在实际执行中，如果当前帧只参考上一帧，那么上一帧中不存在的新人物、新道具、核心商品就会被文本描述随机生成，导致人物身份漂移、商品道具形状错误、关键视觉锚点不稳定。

v6.8 的核心修正是引入 **资源依赖调度**。每一帧生成前，不再直接写 prompt，而是先判断当前帧需要哪些资源图：上一帧用于空间和剧情连续性；新出现的人物或道具必须引用对应资源图；核心商品道具只要清晰可见，就必须持续引用标准道具图或已验证稳定的组合资源图。

v6.8 的核心原则：

```text
Base frames lock story continuity.
Edit frames redesign the camera.
Reference selection must be resource-aware.
New entities and hero products cannot be generated from text only.
```

中文概括：

```text
基础帧继续负责剧情连续性；编辑帧继续负责镜头切换和镜头多样性；但每帧生成前必须先做资源依赖调度。新人物、新道具、核心商品不能只靠文字生成，必须显式引用对应资源图。
```

## 1. 总体流程

v6.8 的流程从“生成资源图”升级为“构建并解析资源库”。资源可以是模型从零生成的，也可以是用户直接上传的。无论资源来自哪里，都必须先进入资源库扫描和资源卡片解析流程。

```text
Step 1   接收用户 idea、帧数 N、风格和特殊要求
Step 2   构建资源库：接收或生成角色、场景、道具、风格参考图
Step 3   扫描资源库并解析资源卡片：人物、场景、道具、核心商品、组合状态
Step 4   审查资源图：可用身份信息、可用场景锚点、可用道具形态、不可用锚点
Step 5   规划 N 张 base frames，并为每帧标注可见实体、首次出现实体、核心商品状态
Step 6   对每帧运行 Reference Resolver，生成 reference_images 列表
Step 7   逐帧生成 case_base_frame01.png 到 case_base_frameNN.png
Step 8   基础帧质检：剧情、场景、角色、锚点、相机侧连续、资源依赖是否正确
Step 9   第二阶段全帧镜头再设计规划
Step 10  对每张 edit frame 运行 Edit Prompt Compiler：默认只使用对应 base frame 作为实际参考图，资源约束、Keep 信息和候选评估项仅作为内部审查依据；同时执行 v6.13 No-Keep Surface Prompt 规则，最终 prompt 不输出独立 Keep 句、不罗列可见元素清单
Step 11  逐帧生成 case_edit_frame01.png 到 case_edit_frameNN.png
Step 12  最终分镜默认使用 edited frames
```

核心变化：

```text
v6.7: previous frame -> prompt -> image
v6.8: resource registry + frame entity plan -> reference resolver -> prompt -> image
```

## 2. 帧数规则

- 用户未指定帧数：默认 N=9。
- 用户明确指定 N：严格使用用户指定的 N。
- 用户只说“短一点”“不要太长”：优先建议 N=5 或 N=6。
- N=9 时保持 9 宫格核心逻辑不变。
- N≠9 时，由标准 9 beat 骨架压缩或扩展得到。

标准 9 beat：

| Beat | 功能 |
|---|---|
| B1 | 开场：人物与场景关系 |
| B2 | 到达行动位置或新角色进入 |
| B3 | 开始动作或关键道具出现 |
| B4 | 接近目标或动作发起 |
| B5 | 首次变化或首次冲突 |
| B6 | 变化升级或反应增强 |
| B7 | 结果显现 |
| B8 | 处理结果、互动升级或离开 |
| B9 | 收束、余波或商品记忆点 |

短帧数推荐：

- N=5：B1 / B2+B3 / B4+B5 / B6+B7 / B8+B9
- N=6：B1 / B2 / B3+B4 / B5+B6 / B7 / B8+B9

## 3. 资源库扫描与资源卡片解析

### 3.1 资源来源

资源可以来自三种方式：

1. 用户直接上传；
2. 工作流从零生成；
3. 从已有 base frame 或 edit frame 中裁剪、编辑、提取得到。

无论来源如何，资源都必须被解析为结构化资源卡片。不能因为图片是用户上传的，就跳过资源审查和资源登记。

### 3.2 文件命名建议

推荐命名：

```text
case_char_01.png                 单人物角色资源图
case_char_01_clean.png           不携带关键道具的人物干净版本
case_char_01_with_prop_01.png    人物携带关键道具的组合资源图
case_char_02.png                 第二个人物资源图
case_scene_01.png                场景资源图
case_prop_01.png                 道具资源图
case_style_01.png                风格参考图
case_base_frame01.png            第一阶段基础帧
case_edit_frame01.png            第二阶段镜头再设计帧
```

### 3.3 资源卡片字段

资源库扫描后，每个资源图都应解析为 Resource Card。

```json
{
  "file": "case_prop_01.png",
  "resource_type": "prop",
  "entity_id": "shark_water_gun",
  "display_name": "blue shark-shaped water gun",
  "identity_sensitive": true,
  "hero_product": true,
  "visual_traits": [
    "blue toy body",
    "shark-shaped silhouette",
    "white shark belly",
    "orange nozzle",
    "yellow circular side detail",
    "shark eye graphic"
  ],
  "usable_for": [
    "first appearance",
    "product shot",
    "action shot",
    "water spray shot"
  ],
  "risk_notes": [
    "do not morph into a generic toy gun",
    "do not remove the shark silhouette",
    "do not change the orange nozzle"
  ],
  "must_reference_when_first_appears": true,
  "must_reference_when_visible": true
}
```

人物资源卡片示例：

```json
{
  "file": "case_char_01_clean.png",
  "resource_type": "character",
  "entity_id": "boy",
  "display_name": "young boy",
  "identity_sensitive": true,
  "hero_product": false,
  "visual_traits": [
    "young boy",
    "yellow T-shirt",
    "blue shorts",
    "short hair",
    "child body proportions"
  ],
  "state_tags": ["clean", "no prop"],
  "usable_for": [
    "first character appearance without prop",
    "background appearance",
    "identity lock"
  ],
  "forbidden_leakage": [
    "do not show the water gun when this clean resource is used"
  ],
  "must_reference_when_first_appears": true,
  "must_reference_when_focus": true
}
```

场景资源卡片示例：

```json
{
  "file": "case_scene_01.png",
  "resource_type": "scene",
  "entity_id": "backyard_deck",
  "display_name": "sunny backyard deck",
  "visual_traits": [
    "wooden deck",
    "round patio table",
    "drink glass",
    "lounge chair",
    "grass lawn",
    "house wall on the left",
    "sunlit trees"
  ],
  "scene_anchors": [
    "wooden deck texture",
    "round table position",
    "deck edge",
    "lawn boundary",
    "house wall",
    "sunlight direction"
  ],
  "forbidden_inventions": [
    "do not add unrelated furniture",
    "do not invent a different patio layout"
  ]
}
```

### 3.4 组合资源图

当角色与核心道具需要同时稳定出现时，推荐建立组合资源图。

典型组合：

```text
case_char_01_clean.png
case_char_01_with_prop_01.png
case_prop_01.png
```

使用原则：

- 不需要道具的帧，用 `case_char_01_clean.png`。
- 道具首次进入人物手中时，优先用 `case_char_01_with_prop_01.png` 或 `case_prop_01.png`。
- 如果参考图数量受限，同时需要新人物和新道具，优先生成或使用组合资源图。
- 如果人物资源图本身带有道具，但剧情早期不应出现道具，则必须额外准备 clean 版本，否则容易发生道具提前泄漏。

## 4. 资源图生成规则

### 4.1 人物参考图：单人物、单姿势、单视角

人物参考图用于锁定角色身份，不是用于生成多视角设定图。

必须满足：

- 一张图中只有一个人物；
- 一个自然站姿；
- 一个确定视角；
- 全身入镜，从头到脚完整；
- 简洁白底或浅色背景；
- 不要场景、特效、额外人物；
- 不要把正面和三分之二正面同时写进同一句。

推荐视角写法：

```text
front three-quarter view only
```

或：

```text
front view only
```

禁止写法：

```text
front view and three-quarter front view are clearly visible
```

```text
front and side views
```

```text
multiple views
```

```text
character sheet showing several angles
```

推荐人物资源图模板：

```text
Generate case_char_01.png: A single full-body character reference image of [character name], [identity and age], with [hair], wearing [outfit details], standing in one natural pose on a plain white background. Use front three-quarter view only, showing the face, hairstyle, collar, outfit silhouette, sleeves, shoes, and key accessories clearly. No scene, no special effects, no extra characters, no repeated character, no multi-view reference sheet. [Target visual style].
```

### 4.2 人物干净版本与携带道具版本

如果角色在剧情中有“未携带道具”和“携带道具”两个状态，必须拆分资源。

```text
case_char_01_clean.png: boy without water gun
case_char_01_with_prop_01.png: boy holding the blue shark water gun
```

禁止用一张带道具的人物图去生成不应出现道具的早期帧，否则模型可能提前把道具带入画面。

### 4.3 场景参考图

场景参考图用于锁定空间结构和可复用锚点。

应包含：空间结构、关键地标或家具、地面纹理、窗户、桌角、桌腿、门框、平台纹理、光源方向，并且尽量无人物。

场景图中的锚点必须是真实可见的。后续 base frame 不能发明 scene reference 中不存在的入口、台阶、门框、石柱、楼梯或额外家具。

### 4.4 道具参考图

道具参考图用于锁定关键物体的形状、材质、大小、纹理、发光状态和朝向。道具应单独展示，不加复杂背景。

如果该道具是商品广告中的核心商品，则必须标记为 `hero_product: true`。

## 5. 资源图约束剧情规划

在规划 base frames 前，必须先审查资源图：

1. 每个 `case_char_xx.png` 可继承哪些身份信息；
2. 是否存在 clean 版本和 with prop 版本；
3. `case_scene_xx.png` 真实存在哪些场景锚点；
4. `case_prop_xx.png` 有哪些形态、颜色、结构和关键识别点；
5. 哪些锚点不存在，后续 prompt 不得提及；
6. 哪些道具属于 hero product，必须持续约束。

核心原则：

```text
Storyboard planning must follow selected resource images.
```

如果用户 idea 提到“门口”，但场景图中没有门口，就不能在 base frame 中临时生成门口。应把剧情落点调整到真实锚点附近，例如桌旁、窗边、书架通道、平台中心等。

## 6. Frame Entity Plan：每帧实体状态表

v6.8 要求在写每帧 prompt 前，先生成实体状态表。

每帧至少标注：

- 当前帧可见人物；
- 当前帧可见道具；
- 当前帧 Scene Core；
- 是否有新人物首次出现；
- 是否有新道具首次出现；
- 是否有核心商品可见；
- 当前视觉焦点人物；
- 当前视觉焦点道具；
- 当前帧禁止出现的实体。

示例：

| Frame | Story State | Visible Characters | Visible Props | New Entities | Hero Product Visible | Focus | Forbidden |
|---|---|---|---|---|---|---|---|
| frame01 | 父亲在后院休息 | father | drink | father | no | father + scene | boy, water gun |
| frame02 | 男孩偷偷出现 | father, boy | drink | boy | no | boy entering | water gun |
| frame03 | 男孩举起水枪 | father, boy | shark water gun, drink | shark water gun | yes | boy + water gun | water spray |
| frame04 | 水枪喷水 | father, boy | shark water gun, water stream, drink | none | yes | water gun + trajectory | extra gun |
| frame05 | 父亲被水击中 | father, boy | shark water gun, water stream, drink | none | yes | father reaction + product | different boy, different gun |

## 7. Reference Resolver：参考图调度器

### 7.1 核心目标

Reference Resolver 的目标是为每一帧自动选择 reference images。

不要默认：

```text
current frame = previous frame only
```

而要默认：

```text
current frame = previous frame + required resource references for current visible entities
```

### 7.2 首现资源强制引用规则

```text
If a character, prop, creature, vehicle, weapon, product, or other identity-sensitive entity appears in the current frame but is absent from the immediate previous source frame, its resource image must be included as a reference image.
```

中文规则：

```text
如果某个人物、道具、产品、武器、动物、载具等身份敏感实体在当前帧首次出现，而上一帧中不存在，那么当前帧必须显式参考对应资源图，不能只用文字描述生成。
```

### 7.3 核心道具持续约束规则

```text
Hero Prop Persistence Rule:
If a prop is the product being advertised, it must be treated as an identity-sensitive subject. Whenever the prop is clearly visible, especially in product shots, action shots, impact shots, and reaction shots, the canonical prop reference must be used or inherited from a verified stable previous frame.
```

中文规则：

```text
如果某个道具是广告中的核心商品，那么它不是普通背景道具，而是身份敏感主体。只要该道具清晰可见，尤其是产品展示帧、发射帧、击中帧、反应帧中，都必须参考标准道具图，或者参考已经验证稳定的上一帧。
```

### 7.4 当前视觉焦点补充引用规则

如果某个人物在上一帧中只是小比例背景人物，但当前帧变成中景、近景或表情焦点，则应重新补充该人物的标准资源图。

```text
If a character becomes the visual focus after being small, blurred, occluded, or backgrounded in the previous frame, include the character reference again.
```

### 7.5 状态切换资源规则

如果人物状态发生变化，应引用对应状态资源，而不是只引用通用人物图。

示例：

| 状态 | 推荐资源 |
|---|---|
| 男孩首次出现但不拿水枪 | `case_char_01_clean.png` |
| 男孩开始拿水枪 | `case_char_01_with_prop_01.png` 或 `case_prop_01.png` |
| 水枪商品特写 | `case_prop_01.png` |
| 父亲表情反应特写 | `case_char_02.png` + 上一帧 |

### 7.6 参考图预算规则

如果模型支持的参考图数量有限，默认优先级如下：

```text
1. previous verified frame
2. newly appearing character or prop resource
3. hero product resource
4. current focus character resource
5. scene reference
6. style reference
```

但需要注意：

- frame01 没有 previous frame，因此优先使用 scene reference + main character reference。
- 如果同一帧既有新人物又有新核心道具，且参考图数量不够，优先使用组合资源图。
- 如果没有组合资源图，应拆成两步生成：先让新人物稳定出现，再在下一帧或编辑阶段加入道具。
- 如果上一帧中的核心道具已经变形，则不能继续只参考上一帧，必须重新挂标准道具图纠偏。

### 7.7 Reference Resolver 输出格式

每帧生成前应输出：

```json
{
  "frame": "case_base_frame03.png",
  "story_state": "boy raises the shark water gun",
  "visible_entities": ["father", "boy", "shark_water_gun", "drink"],
  "new_entities": ["shark_water_gun"],
  "hero_product_visible": true,
  "focus_entities": ["boy", "shark_water_gun"],
  "reference_images": [
    "case_base_frame02.png",
    "case_prop_01.png"
  ],
  "reference_reason": {
    "case_base_frame02.png": "spatial continuity, boy position, father position, table layout, lighting direction",
    "case_prop_01.png": "first appearance and hero product identity lock"
  },
  "forbidden": [
    "do not show water spray yet",
    "do not morph the water gun into a generic toy gun"
  ]
}
```

## 8. Scene Core / Character / Camera Topology Rule

每帧先确定 **Scene Core**，即当前帧最重要的信息中心。

常见 Scene Core：

- 开场帧：场景核心家具、窗户光源、主要空间结构；
- 新人物进入帧：新人物与已有场景的相对位置；
- 核心商品出现帧：人物手部与商品道具；
- 产品动作帧：商品道具、喷射方向、动作轨迹；
- 反应帧：被影响人物的表情、身体反应、商品作用结果；
- 结果帧：互动结果、商品记忆点、情绪收束；
- 收束帧：人物关系、核心商品、余波或品牌化画面。

根据人物朝向确定三者拓扑：

| 人物朝向 | 推荐拓扑 | 用法 |
|---|---|---|
| front / three-quarter front | Camera → Scene Core → Character | 人物站在场景核心远侧或侧后方，场景核心位于人物与镜头之间 |
| back / three-quarter back | Camera → Character → Scene Core | 人物位于镜头与目标之间，适合观察或操作目标 |
| side / three-quarter side | Character beside Scene Core, both visible | 人物在目标侧边，适合走近、观察、伸手、触碰、发射水枪 |

核心提醒：

```text
人物面向目标物 ≠ 人物必须背对镜头。
```

人物面对桌子、道具或目标人物时，也可以站在远侧或侧边，让镜头同时看到脸、手和 Scene Core。

## 9. Camera-Side Continuity Track

基础帧阶段要优先保持相机侧连续。

如果第一帧采用三分之二正面开场，后续相邻帧不应无理由突然变成正背影。只有以下情况才允许明显切侧：

1. 人物剧情上发生转身；
2. 镜头意图明确需要换侧；
3. Scene Core 发生变化，必须重新组织构图；
4. 新人物出现，需要建立新人物与旧人物的空间关系；
5. 核心商品出现，需要展示手部与商品结构；
6. 收束或离开帧需要背影。

推荐 N=6 朝向节奏：

| 帧 | 剧情节点 | 推荐朝向 |
|---|---|---|
| frame01 | 开场建立人物与场景 | three-quarter front |
| frame02 | 新人物进入或接近目标 | three-quarter side / wide relation shot |
| frame03 | 核心道具出现或开始动作 | three-quarter front / three-quarter side |
| frame04 | 道具触发动作 | side view / trajectory-friendly view |
| frame05 | 结果显现或人物反应 | front / three-quarter front |
| frame06 | 情绪收束或商品记忆点 | wide / low-angle / foreground product composition |

## 10. Anchor Visibility Budget

基础帧不仅要使用真实锚点，还要让关键锚点可见。

如果 Scene Core 是桌面和道具，则至少要看到：

- 大部分桌面或核心区域；
- 一个桌角、桌腿或桌面边缘；
- 目标道具；
- 与目标相关的人物手部或视线；
- 主要光源方向。

如果 Scene Core 是核心商品，则至少要看到：

- 商品整体轮廓；
- 商品的主要颜色；
- 商品的关键识别结构；
- 商品与人物手部的关系；
- 商品的朝向或作用方向。

如果人物挡住 Scene Core，即使人物质量高，也不应选择为正式 base frame。

如果核心商品道具严重变形，即使动作效果好，也不应选择为正式 base frame。

## 11. 第一阶段 Base Frame 规则

基础帧用于锁定剧情骨架，不追求复杂镜头。

基础帧只使用：

```text
wide shot
medium shot
```

禁止在基础帧阶段主动使用 close-up、insert shot、overhead、over-the-shoulder、extreme low-angle 或 complex camera rotation。

每个 base frame prompt 必须包含：

1. Reference Resolver 输出的真实参考文件名；
2. 一个确定的基础镜头；
3. 当前 Scene Core；
4. 人物与 Scene Core 的拓扑关系；
5. Subject–Object Relation；
6. Subject–Camera Relation；
7. 关键锚点可见性；
8. 当前帧必须保持的人物和道具身份；
9. 当前帧禁止项。

基础帧 prompt 应控制在 5–8 句，避免复制资源审查全文。

### 11.1 Base Frame Prompt 模板

```text
Generate case_base_frame0x.png: Use [previous frame] as the source for the exact story continuity, scene layout, character positions, object positions, and lighting direction. Use [required resource image] as the strict reference for [new or hero entity], preserving [key identity traits]. Camera setup: [wide shot / medium shot] with [subject-camera relation], clearly showing [Scene Core and anchor details]. Place [subject] [spatial relation to Scene Core], while keeping [continuity elements] unchanged. Do not [forbidden entity leakage], do not [identity drift], do not [camera violation], and do not [scene invention]. [Target style].
```

### 11.2 新人物首次出现模板

```text
Generate case_base_frame02.png: Use case_base_frame01.png as the source for the exact backyard deck layout, father position, round patio table, drink glass, lounge chair, and sunlight direction. Use case_char_01_clean.png as the strict identity reference for the newly appearing boy, including his age, face, hairstyle, yellow T-shirt, shorts, body proportions, and full-body appearance. Place the boy crouching at the left grass/deck edge, looking toward the father while sneaking into the scene. Keep the father seated and relaxed in the background, and keep the table and drink clearly visible. Do not show any water gun yet, do not invent a different boy, do not change the father's identity, and do not alter the backyard layout. Commercial photography style, bright summer lighting.
```

### 11.3 核心道具首次出现模板

```text
Generate case_base_frame03.png: Use case_base_frame02.png as the source for the exact scene layout, boy position, father position, round table, drink glass, and sunlight direction. Use case_prop_01.png as the strict reference for the blue shark-shaped water gun, preserving its blue shark body, white belly, orange nozzle, yellow circular detail, shark eye graphic, and toy-like plastic shape. Place the water gun naturally in the boy's hands, held with both hands and aimed toward the father. Keep the boy crouching at the grass/deck edge and keep the father seated without reacting yet. Do not change the water gun into another toy gun, do not remove the shark shape, do not show water spray yet, and do not change the scene layout. Commercial photography style, bright summer lighting.
```

### 11.4 核心道具持续出现模板

```text
Generate case_base_frame04.png: Use case_base_frame03.png as the source for the exact boy position, father position, table, drink glass, backyard deck layout, and sunlight direction. Use case_prop_01.png to keep the blue shark-shaped water gun consistent, especially the orange nozzle, yellow circular side detail, white shark belly, and shark eye graphic. Show a strong stream of water spraying from the gun's nozzle toward the father, with the water trajectory clearly connected to the correct nozzle. Keep the boy crouching and gripping the same water gun with both hands, and show the father beginning to react while still seated. Do not morph the water gun, do not add a second gun, do not change the father into another person, and do not alter the deck layout. Commercial photography style, bright summer lighting, dynamic water spray.
```

## 12. 基础帧候选选择优先级

v6.8 的基础帧候选选择优先级调整为：

1. **Reference Dependency Correctness**：是否正确使用了本帧所需参考图；
2. **New Entity Consistency**：新人物或新道具是否与资源图一致；
3. **Hero Product Consistency**：核心商品道具是否与标准道具图一致；
4. **Story State Accuracy**：剧情节点是否正确；
5. **Scene Composition Accuracy**：场景结构和锚点是否正确；
6. **Subject–Object Relation**：人物与目标、人物与商品、人物与场景核心的关系是否正确；
7. **Subject–Camera Relation**：视角是否符合要求；
8. **Anchor Visibility**：关键锚点是否清楚可见；
9. **Visual Quality**：清晰度、比例、手部、光影是否稳定。

新增两个硬性否决项：

### 12.1 新人物一致性否决

```text
If the frame introduces a new character but the generated character does not match the assigned character reference, reject the candidate even if the composition is good.
```

中文规则：

```text
如果当前帧引入新人物，但生成的人物不像指定人物资源图，则直接淘汰，即使构图和动作很好也不能选。
```

### 12.2 核心商品道具否决

```text
If the hero product is visible but its shape, color layout, nozzle, key graphic elements, or silhouette do not match the prop reference, reject the candidate even if the action looks correct.
```

中文规则：

```text
如果核心商品可见，但形状、颜色布局、喷嘴、关键图案或整体轮廓与道具参考图不一致，则直接淘汰，即使动作效果看起来正确也不能选。
```

商品广告中，商品形象优先级高于普通动作效果。

## 13. 第二阶段：全帧镜头再设计

第二阶段不是“轻微再编辑”，而是 **基于 base frame 的镜头再设计**。

v6.8 保留 v6.7 的核心要求：

```text
Camera transformation is the primary goal. Cleanup is only secondary.
```

### 13.1 主目标

第二阶段的主目标是：

- 景别变化；
- 机位变化；
- 镜头侧变化；
- 构图重点变化；
- 视觉叙事重点变化；
- 镜头节奏变化。

附带目标才是：补光、修手、修衣摆、清理背景、统一色调。

### 13.2 Edit Frame 默认只使用 Base Frame 作为实际参考

v6.11 对编辑阶段的 Reference Resolver 做出重要修正：编辑帧仍然要进行资源一致性审查，但**不默认把人物资源图、道具资源图再次输入给图像编辑模型**。

实测发现，对于再编辑阶段，`case_base_frame0x.png` 已经包含当前帧的人物状态、道具状态、场景结构、光照、构图和动作结果。此时如果额外输入人物资源图或道具资源图，模型可能会重新解释角色身份和道具形态，使当前画面状态被“设定图”覆盖，反而降低画面连续性。

因此，编辑阶段默认采用：

```text
actual_reference_images = [case_base_frame0x.png]
```

而不是：

```text
actual_reference_images = [case_base_frame0x.png, case_char_xx.png, case_prop_xx.png]
```

Reference Resolver 在编辑阶段的角色从“参考图调度器”改为“内部一致性审查器”。它需要判断人物、道具和场景是否应被保留，但这些约束不应全部写进最终 prompt，也不应默认转化为额外图像参考。

推荐 JSON：

```json
{
  "frame": "case_edit_frame03.png",
  "source_base_frame": "case_base_frame03.png",
  "actual_reference_images": ["case_base_frame03.png"],
  "internal_preserve": ["Nezha identity already present in base frame", "Universe Ring already present in base frame", "glowing lotus and altar layout"],
  "surface_prompt_policy": "describe the desired screen content and camera transformation only",
  "extra_resource_images": [],
  "extra_resource_allowed_only_if": [
    "base frame identity is already wrong",
    "base frame prop shape is already wrong",
    "the edit target is pure identity restoration rather than cinematic reframe"
  ]
}
```

只有以下情况才允许在编辑阶段额外引用人物图或道具图：

1. base frame 中人物或道具本身已经明显错误；
2. 本轮编辑目标是身份或道具纠偏，而不是镜头再设计；
3. 需要局部重构某个已经崩坏的核心对象；
4. 用户明确要求以某张资源图重新校正角色或道具。

除此之外，编辑帧应优先继承 base frame，并通过文字描述“画面要展示什么”，而不是通过多图参考重新生成设定。

硬规则：

```text
For edit frames, base frame is the default and usually the only image reference.
Resource constraints may guide planning, but should not overload the final generation prompt.
```

中文概括：

```text
再编辑阶段默认只参考对应 base frame。人物图和道具图用于内部审查，不默认输入模型；最终 prompt 只写画面表现和镜头设计。
```

### 13.3 Camera Delta Requirement

每个 `case_edit_frame0x.png` 相比对应 `case_base_frame0x.png`，默认必须产生明确镜头差异。

至少满足以下一项：

1. **Shot scale delta**：wide → medium close-up / medium → close-up / medium → insert；
2. **Camera angle delta**：eye-level → high-angle / low-angle / overhead；
3. **Camera side delta**：front → side / side → over-the-shoulder / back-side view；
4. **Composition delta**：主体从居中变为前景遮挡、框景、桌面前景、人物后景；
5. **Focus delta**：从人物整体转为手部、道具、眼神、商品、动作轨迹；
6. **Depth delta**：加入明确前景、中景、背景层次。

如果 edited frame 与 base frame 只是补光、锐化、清理背景，判定为失败。

### 13.4 允许保留基础构图的例外

每组分镜最多允许 1 帧只做轻微重构或保持基础构图，通常用于开场全景、收束全景或需要完整空间关系的关键帧。

即使保留基础景别，也必须有轻微镜头设计变化，例如更低或更高的机位、前景桌面更明确、人物更偏画面一侧、纵深层次更强。

不推荐纯粹写：

```text
cinematic polish
cleanup
improve lighting
```

作为主要编辑策略。

## 14. 第二阶段镜头多样性预算

### N=5

至少 3 帧有明确 camera delta：

- 1 帧 wide / establishing reframe；
- 1 帧 medium close-up；
- 1 帧 insert / close-up / over-the-shoulder / low-angle。

### N=6

至少 4 帧有明确 camera delta：

- 1–2 帧 wide 或 stronger wide shot；
- 1–2 帧 medium / medium close-up；
- 1 帧 insert / close-up；
- 1 帧 overhead / over-the-shoulder / low-angle。

最多 1 帧仅做轻微 polish。

### N=9

至少 6 帧有明确 camera delta：

- 2–3 帧 wide / stronger wide；
- 2–3 帧 medium / medium close-up；
- 1–2 帧 insert / close-up；
- 1 帧 overhead / high-angle；
- 1 帧 low-angle / over-the-shoulder。

禁止：

- 全部 edited frames 与 base frames 基本一致；
- 全部只是补光或统一色调；
- 全部使用同一种镜头变换；
- 为了镜头多样性改变剧情状态；
- 为了镜头多样性牺牲新人物身份或核心商品形象。

## 16. 第二阶段图像生成 Prompt 模板（v6.11 表层 Prompt 简化版）

v6.11 不再把编辑阶段 prompt 写成“资源约束清单”。最终传给图像编辑模型的 prompt 应当更接近一段画面描述：

```text
source base frame + inherited story state + camera transformation + style
```

它不是越短越好，而是**只写会直接影响当前画面的内容**。人物设定、道具设定、资源文件名、过多否定句、`Keep` 句和内部审查项，不应默认进入最终 prompt。

### 16.1 v6.11 推荐模板

```text
Generate case_edit_frame0x.png: Use case_base_frame0x.png as the direct source for the same story state of [brief story state]. Camera transformation: create [specific cinematic shot type] with [one primary visual focus] as the visual center, using [optional context relation only when needed]. [Target visual style].
```

如果需要避免中景回退，可只加一句轻量约束：

```text
Avoid a neutral eye-level medium shot.
```

不要把以下内容默认写入编辑阶段表层 prompt：

```text
Use case_char_01.png to preserve...
Use case_prop_01.png as the strict reference...
preserve every costume detail...
preserve every prop texture...
do not change A, do not change B, do not change C, do not change D...
```

原因是：这些内容可以作为内部审查项，但进入表层 prompt 后会分散模型注意力，让模型从“编辑当前画面”变成“重新综合多个设定图”。

---

### 16.2 画面表现优先模板

对于再编辑阶段，推荐先写“画面要表现什么”，再写镜头：

```text
Generate case_edit_frame03.png: Use case_base_frame03.png as the direct source for the same moment of Nezha lying on the glowing lotus and touching the floating Universe Ring. Camera transformation: create a single-character close-up detail shot focused on Nezha's right index finger meeting the lower edge of the ring, with a small magical spark at the contact point and the glowing lotus softly visible behind the hand. Cinematic Chinese fantasy 3D animation style.
```

这个模板的重点是：

- 只引用实际输入的 `case_base_frame03.png`；
- 不再提 `case_char_01.png` 和 `case_prop_01.png`，除非它们真的作为参考图输入；
- 先描述当前画面表现，再描述镜头；
- 保留一个视觉焦点和一个上下文锚点；
- 不使用长串身份、服饰、道具纹理约束。

---

### 16.3 再编辑阶段 Prompt 四句结构

对于多数模型，编辑阶段 prompt 控制在 2 到 4 句最稳定。

推荐结构：

```text
Sentence 1: Use case_base_frame0x.png as the direct source for the same story state of [brief inherited state].
Sentence 2: Camera transformation: create the intended cinematic shot with one visual focus and any necessary context relation.
Sentence 3: Optional anti-medium cue.
Sentence 4: Target style.
```

示例：

```text
Generate case_edit_frame05.png: Use case_base_frame05.png as the direct source for the same story state of Nezha lying on the glowing lotus after the Universe Ring has fitted onto his right wrist. Camera transformation: create a single-character face close-up with strong focus on Nezha's awakened eyes and calm expression, with the glowing lotus and wrist ring softly visible as context. Cinematic Chinese fantasy 3D animation style.
```

---

### 16.4 不同模型能力下的 Prompt 策略

v6.11 的核心不是“所有 prompt 都必须极简”，而是区分**规划层约束**和**表层生成 prompt**。

对于 GPT-5.5 这类强模型，可以直接根据分镜逻辑输出较自然的画面描述。对于能力稍弱的大模型，不建议把所有约束塞进最终 prompt，而应使用固定的结构化编译流程：

```json
{
  "source_base": "case_base_frame05.png",
  "story_state": "Nezha lies on the glowing lotus after the Universe Ring has fitted onto his right wrist",
  "desired_screen_content": "Nezha's awakened eyes and calm expression; glowing lotus and ring softly visible",
  "camera_type": "single-character face close-up",
  "primary_visual_focus": "Nezha's awakened eyes",
  "continuity_anchors": ["glowing lotus", "Universe Ring on wrist"],
  "style": "Cinematic Chinese fantasy 3D animation style",
  "surface_prompt": "Generate case_edit_frame05.png: Use case_base_frame05.png as the direct source for the same story state of Nezha lying on the glowing lotus after the Universe Ring has fitted onto his right wrist. Camera transformation: create a single-character face close-up with strong focus on Nezha's awakened eyes and calm expression, with the glowing lotus and wrist ring softly visible as context. Cinematic Chinese fantasy 3D animation style."
}
```

低性能模型需要更多约束，但这些约束应放在 JSON 字段中，让模型按字段编译 prompt；最终输出仍应克制。

错误做法：

```text
为了让低性能模型稳，就把所有身份、道具、场景、禁止项全部写进最终 prompt。
```

正确做法：

```text
用结构化字段限制低性能模型的思考路径，再把字段压缩成一段画面表现 prompt。
```

---

### 16.5 表层 Prompt 中的文件名规则

编辑阶段 prompt 只应提到实际输入模型的图像文件。

如果实际参考图只有：

```text
case_base_frame03.png
```

最终 prompt 就只写：

```text
Use case_base_frame03.png as the direct source...
```

不要写：

```text
Use case_char_01.png...
Use case_prop_01.png...
```

除非这些图片真的作为本轮编辑输入。否则模型会在文本层面尝试服从不存在的图片约束，造成“参考来源不一致”。

---

### 16.6 v6.11 哪吒再编辑 Prompt 参考组

## 17. 再编辑候选选择优先级

选择 `case_edit_frame0x.png` 时，优先级调整为：

1. **Camera Transformation Accuracy**：是否相对 base frame 产生明确镜头变化；
2. **Story State Preservation**：是否保留基础帧剧情状态；
3. **Reference Dependency Preservation**：是否保留 Reference Resolver 要求的人物和道具身份；
4. **Hero Product Consistency**：核心商品是否继续正确；
5. **Camera Diversity Value**：是否为最终分镜提供新的镜头类型或构图价值；
6. **Subject/Object Continuity**：人物、道具、场景是否保持一致；
7. **Visible Detail Quality**：新镜头要强调的细节是否清楚；
8. **Anchor Preservation**：关键锚点是否仍可识别；
9. **Visual Quality**：是否清晰、无明显畸形。

如果候选图与 base frame 基本一样，即使画面更干净，也不应优先选择。

如果候选图实现了镜头变化，但新人物或核心商品变形，也不应选择。

## 18. 重生成判定

### 18.1 人物资源图需要重生成

出现以下情况，应重生成人物参考图：

- 一张图中出现多个同一人物；
- 出现多视角并排展示；
- 出现多个姿势；
- 出现背景场景或特效；
- 武器或道具位置与设定不一致；
- prompt 中写了 `front view and three-quarter front view` 这类双视角表达；
- 角色图中携带了后续不应提前出现的关键道具，但没有 clean 版本。

### 18.2 道具资源图需要重生成

出现以下情况，应重生成道具参考图：

- 道具不是单独展示；
- 道具形状不清楚；
- 核心识别点缺失；
- 颜色布局不稳定；
- 道具朝向不利于后续引用；
- 作为 hero product 时没有足够清楚的商品轮廓。

### 18.3 基础帧需要重生成

出现以下情况，应重生成 base frame：

- Reference Resolver 要求的资源图没有被引用；
- 新人物首次出现但身份不像人物资源图；
- 新道具首次出现但形态不像道具资源图；
- 核心商品可见但形状、颜色、轮廓错误；
- 使用了 scene reference 中不存在的锚点；
- 人物遮挡 Scene Core；
- 相机侧无理由跳变；
- 道具状态提前或滞后；
- 人物与目标物关系错误；
- 镜头不是指定的 wide / medium。

### 18.4 编辑帧需要重生成

出现以下情况，应重生成 edit frame：

- 与 base frame 几乎同景别、同机位、同构图；
- 只做了补光、锐化、清理背景；
- 没有实现规划中的 camera delta；
- 改变了剧情状态；
- 改变了人物位置或道具状态；
- 场景变成另一个地方；
- 新增无关人物或道具；
- 人物身份因为镜头变化而漂移；
- 核心商品因为镜头变化而变形。

## 21. v6.9 镜头多样性与九宫格回退补丁

### 21.1 问题定位

当前 v6.8 已经规定第二阶段不是轻微再编辑，而是基于 base frame 的镜头再设计；同时也规定 edited frame 必须相对 base frame 产生 camera delta。但是在实际执行中，如果模型或调度器没有把“剧情功能”显式映射为“镜头功能”，就容易出现一种退化结果：

```text
base frame 是中景叙事，edit frame 仍然是中景叙事，只是补光、锐化或微调构图。
```

这类结果必须判定为编辑阶段失败。v6.9 增加三个强约束：

```text
1. Base frames may be ordinary; edit frames must be cinematic.
2. A nine-grid storyboard must not collapse into nine neutral medium shots.
3. Fallback must search for another special camera, not fall back to the base medium shot.
```

中文概括：

```text
基础帧可以普通，编辑帧必须有镜头设计；九宫格不能退化成九张中景叙事图；失败回退时不能回退到普通中景，而要回退到另一个特殊镜头方案。
```

---

### 21.2 Story Function to Camera Resolver

第二阶段生成 edit frame 前，必须先根据当前剧情功能选择镜头类型。不能只写“cinematic reframe”或“more dramatic shot”。

| Story Function | 推荐 Edit Camera | 主要视觉焦点 | 禁止退化 |
|---|---|---|---|
| 开场交代环境 | stronger establishing wide / high-angle wide / foreground-depth wide | 场景结构、主体位置、环境压迫感 | 普通中景人物居中 |
| 觉醒、苏醒、意识恢复 | face close-up / extreme close-up of eyes | 眼皮、瞳孔、呼吸、面部微光 | 全身中景继续躺着 |
| 手部动作、拿起道具、法术起手 | hand insert / prop insert / wrist close-up | 手指、道具、能量起点 | 人物半身中景 |
| 能量爆发、攻击、喷射、冲刺 | side trajectory shot / low-angle action shot / dynamic diagonal composition | 轨迹、方向、速度、冲击 | 正面平视中景 |
| 人物反应 | reaction close-up / over-the-shoulder reaction | 表情、眼神、身体局部反应 | 双人中景平铺 |
| 空间变化、仪式阵法、范围效果 | overhead shot / high-angle composition | 阵法、火焰范围、空间关系 | 人物站立中景 |
| 英雄显现、复活完成、产品记忆点 | low-angle hero shot / silhouette shot / foreground object shot | 主体气势、标志物、商品或武器 | 普通全身中景 |
| 收束、余波、离开 | wide aftermath / symbolic close-up / foreground-background composition | 结果、余波、情绪落点 | 无设计的远景 |

执行规则：

```text
For each edit frame, first decide the story function, then select the camera type. Do not select a camera type only from shot scale labels such as medium shot or wide shot.
```

---

### 21.3 Edit Stage Medium Shot Suppression Rule

第二阶段要显式压制普通中景。

```text
Neutral Medium Shot Suppression Rule:
In the edit stage, a neutral eye-level medium shot is considered a fallback failure, not a valid cinematic redesign, unless it contains a strong additional camera property such as low angle, over-the-shoulder framing, foreground occlusion, extreme depth layering, or product-focused composition.
```

中文规则：

```text
编辑阶段中，普通平视中景默认视为回退失败，而不是有效镜头再设计。只有当中景同时具备低角度、过肩、前景遮挡、强纵深、商品前景等明确镜头属性时，才允许保留。
```

九宫格中推荐硬限制：

```text
N=9 edit frames:
- neutral medium shot <= 1
- medium close-up with strong camera design <= 2
- close-up / insert / overhead / high-angle / low-angle / over-the-shoulder / foreground-depth shots >= 6
- at least 5 distinct camera labels across the final 9 frames
```

如果用户明确要求“后续分镜尽量不使用中景表现”，则采用更严格版本：

```text
After the first establishing frame, do not use a neutral medium shot. Use close-up, insert, high-angle, overhead, low-angle, side trajectory, over-the-shoulder, silhouette, or foreground-depth composition instead.
```

---

### 21.4 Nine-Grid Camera Coverage Budget

9 宫格不是 9 个剧情点的普通截图，而是 9 个具有节奏变化的电影镜头。默认镜头覆盖如下：

| Edit Frame | 推荐镜头功能 | 推荐镜头类型 | 说明 |
|---|---|---|---|
| E1 | Establish | high-angle wide / stronger wide / foreground-depth wide | 交代场景，但要比 base 更有纵深或压迫感 |
| E2 | Awakening / realization | face close-up / eye extreme close-up | 用面部或眼睛承接剧情变化 |
| E3 | Detail activation | hand insert / prop insert / symbol close-up | 展示手部、道具、符号、能量起点 |
| E4 | Motion begins | side trajectory / diagonal action shot | 展示动作方向和速度 |
| E5 | Reaction / impact | reaction close-up / over-the-shoulder | 展示人物反应或冲击结果 |
| E6 | Spatial escalation | overhead / high-angle / top-down relation shot | 展示范围变化、阵法、环境关系 |
| E7 | Climax | low-angle hero shot / silhouette shot | 展示主体气势或关键姿态 |
| E8 | Result processing | foreground-background composition / over-the-shoulder | 用前景和后景组织结果与关系 |
| E9 | Closure | wide aftermath / symbolic close-up / hero-object foreground | 收束余波、留记忆点 |

注意：E1 和 E9 可以是 wide，但不能是“没有设计的普通远景”。E2–E8 默认禁止普通中景。

---

### 21.5 Nine-Grid Fallback Logic

原有回退逻辑如果直接退回 base frame 或普通中景，会导致最终九宫格平淡。v6.9 将回退逻辑改为“特殊镜头优先回退”。

```text
Nine-Grid Fallback Order:
1. Try the planned special camera.
2. If it fails, keep the same story function and try an alternative special camera.
3. If identity or prop consistency fails, add required resource references and retry the same special camera.
4. If the full-body special camera fails, move closer: close-up or insert.
5. If the close-up fails, switch angle: high-angle, low-angle, side, over-the-shoulder, or foreground-depth.
6. Only if all cinematic retries fail, keep the base frame as a temporary placeholder and mark it as must-regenerate.
```

中文规则：

```text
回退不是退回中景，而是在同一剧情功能下换一个特殊镜头。只有所有特殊镜头都失败时，base frame 才能作为临时占位，不能直接进入最终九宫格。
```

推荐 JSON 字段：

```json
{
  "edit_fallback": {
    "case_edit_frame02.png": {
      "planned_camera": "face close-up",
      "fallback_camera_candidates": [
        "extreme close-up of eyes",
        "side close-up of face with flame foreground",
        "overhead close-up of face inside the lotus flame",
        "low-angle close-up from the lotus edge"
      ],
      "fallback_rule": "do not fall back to neutral medium shot",
      "base_frame_allowed_as_final": false,
      "temporary_placeholder_only": true
    }
  }
}
```

### 21.6 Camera Diversity Score

候选 edit frame 选择前，必须为镜头变化打分。只要画面漂亮但镜头没有变化，仍然应淘汰。

推荐字段：

```json
{
  "camera_diversity_score": {
    "shot_scale_delta": 1,
    "angle_delta": 1,
    "camera_side_delta": 0,
    "focus_delta": 1,
    "composition_delta": 1,
    "depth_delta": 0,
    "special_camera_label": "face close-up",
    "neutral_medium_risk": false,
    "accepted": true
  }
}
```

打分规则：

| 项目 | 分值 | 说明 |
|---|---:|---|
| shot_scale_delta | 1 | 景别从 base 明显改变 |
| angle_delta | 1 | 平视改为高角度、俯视、低角度等 |
| camera_side_delta | 1 | 镜头侧发生变化 |
| focus_delta | 1 | 焦点从整体转为眼睛、手部、道具、轨迹、反应等 |
| composition_delta | 1 | 构图从居中平铺变为前景遮挡、斜线构图、框景等 |
| depth_delta | 1 | 明确前景、中景、背景层次 |

接受标准：

```text
A valid edit frame should score at least 2, or use a clearly special camera label such as close-up, insert, overhead, low-angle, over-the-shoulder, or foreground-depth shot.
```

9 宫格整体标准：

```text
- accepted special-camera edit frames >= 7 / 9
- neutral_medium_risk frames <= 1 / 9
- distinct special_camera_label count >= 5
- close-up or insert frames >= 2
- overhead/high-angle/low-angle/over-the-shoulder frames >= 3
```

### 21.7 Prompt-Level Anti-Medium Clauses

编辑帧 prompt 必须显式禁止普通中景回退。

通用模板：

```text
Generate case_edit_frame0x.png: Use case_base_frame0x.png as the source for the exact story state, character identity, object state, scene layout, lighting direction, and spatial continuity. Camera transformation: change the base ordinary wide/medium composition into [specific special camera], focusing on [specific visual detail]. Reframe the same moment without changing the story beat or character state. Do not keep the same neutral eye-level medium shot, do not preserve the base composition, do not place the full character plainly in the center, and do not use simple cinematic polish as the main edit. Preserve [identity-sensitive entities and hero props]. [Target style].
```

如果是觉醒镜头：

```text
Camera transformation: cut from the base altar view into an extreme close-up of the character's face and eyelids, with flame reflections on the cheeks and eyelashes. The eyes are the visual center of the frame. Do not show the full body, do not keep the lotus altar as a medium-wide composition, and do not use a neutral medium shot.
```

如果是手部或道具镜头：

```text
Camera transformation: cut into a hand insert shot, with the fingers, wrist accessory, prop surface, or energy source occupying the foreground. Do not show a normal half-body medium shot, and do not center the whole character plainly in the frame.
```

下一帧应优先这样设计：

```text
Generate case_edit_frame02.png: Use case_base_frame01.png as the source for Nezha's exact identity, red outfit, hair buns, flame lotus, circular stone altar, red storm sky, and lightning-lit atmosphere. Camera transformation: cut from the base medium/wide altar view into an extreme close-up of Nezha's face and closed eyelids, with warm orange flame reflections on the cheeks, eyelashes, forehead mark, and collar edge. Show one eye just beginning to open as the visual center of the frame, while the flame lotus appears only as soft glowing foreground and background blur. Do not show the full body, do not keep the original altar-wide composition, do not use a neutral eye-level medium shot, and do not change Nezha's face, outfit, or 3D animated style.
```

这个例子体现的核心原则是：

```text
When the story beat changes from setting introduction to awakening, the camera must move from environment-centered framing to face-centered close-up.
```

### 21.9 编辑阶段候选否决新增项

在 v6.8 的编辑帧重生成条件基础上，v6.9 增加以下硬性否决项：

1. edit frame 仍然是普通平视中景；
2. edit frame 只是在 base frame 上补光、锐化、清理背景；
3. story function 已经进入觉醒、反应、手部动作或道具动作，但镜头仍然展示人物全身或半身平铺；
4. 九宫格中已有多个中景，当前候选仍然是中景；
5. fallback 结果直接回到 base frame，并被错误标记为 final frame；
6. 特殊镜头变成了随机炫技镜头，导致剧情状态不连贯；
7. close-up 镜头没有明确可见的焦点细节，例如眼睛、手指、道具喷嘴、表情或能量源。

硬规则：

```text
A flat medium shot is not a safe fallback. It is a failed edit candidate.
```

中文概括：

```text
普通中景不是安全回退，而是失败候选。
```

生成 edit frame 前额外检查：

1. 当前剧情功能是什么，是环境交代、觉醒、手部动作、道具动作、反应、空间升级、高潮还是收束？
2. 这个剧情功能最适合哪类特殊镜头？
3. 当前镜头是否仍然是普通中景？
4. 如果是中景，它是否带有低角度、过肩、前景遮挡、强纵深、商品前景等强镜头属性？
5. 九宫格中已经有多少个中景？
6. 该帧是否提供了九宫格中尚未出现的镜头类型？
7. 如果计划镜头失败，备用特殊镜头是什么？
8. 回退是否错误地回到了 base frame？
9. 当前候选是否应作为 temporary placeholder，而不是 final frame？
10. 最终九宫格是否至少包含 7 张具有明确特殊镜头属性的 edited frames？



## 22. v6.10 Balanced Cinematic Prompting 补丁：镜头强约束与细节弱约束

### 22.1 问题定位

v6.9 解决了编辑帧回退到普通中景的问题，但在实际执行中容易出现新的退化：为了避免中景，prompt 会不断增加局部描述，例如指纹纹理、道具纹路、能量火花、接触点、虚化背景等。模型虽然会生成明显的 close-up 或 insert shot，但画面可能变成“局部展示图”，导致人物状态、环境氛围和前后帧叙事连续性被弱化。

v6.10 的核心修正是：

```text
Use local detail to guide visual focus, not to create a microscopic detail checklist.
```

中文概括：

```text
局部细节用于引导镜头焦点，而不是把画面写成微观细节清单。
```

因此，v6.10 不削弱 v6.9 的镜头多样性要求，而是在其基础上增加“叙事可读性”和“细节预算”约束：

```text
Camera diversity is required.
Detail overfitting is forbidden.
Narrative readability must be preserved.
```

---

### 22.2 视觉焦点约束替代细节清单

编辑帧 prompt 不应把所有局部元素都写成必须清楚展示的检查项。推荐从“多个细节并列”改为“一个视觉焦点 + 少量支持性细节”。

不推荐：

```text
Clearly show the fingerprint texture, the ring's engraved surface, and the glowing energy bridge between skin and metal.
```

推荐：

```text
Use the fingertip touching the ring as the visual focus, with natural skin detail and a small spark at the contact point.
```

核心差异：

- `fingerprint texture` 容易诱导模型过度绘制指纹；
- `engraved surface` 容易让道具纹理抢走画面权重；
- `glowing energy bridge` 容易生成过强、过粗或不自然的特效；
- `visual focus` 更适合引导镜头关注点，同时保留画面整体叙事。

执行规则：

```text
For each edit frame, define one primary visual focus. Supporting details may exist, but they must not compete with the story beat.
```

中文规则：

```text
每个编辑帧只定义一个主视觉焦点。支持性细节可以存在，但不能与当前剧情节点争夺画面主导权。
```

---

### 22.3 Detail Budget Rule

每个 edit frame prompt 应控制细节数量，避免模型把所有被点名的局部都强化成画面主体。

推荐预算：

```text
1 camera type
1 primary visual focus
2 continuity anchors
2-3 local supporting details
2-3 negative constraints
```

字段含义：

| 项目 | 说明 | 示例 |
|---|---|---|
| camera type | 本帧的电影镜头类型 | close-up detail shot, low-angle hero shot |
| primary visual focus | 本帧唯一主视觉焦点 | fingertip touching the ring |
| continuity anchors | 保持前后帧可读的场景或人物锚点 | flame lotus, circular stone altar |
| local supporting details | 辅助镜头焦点的少量细节 | small spark, warm glow, natural skin detail |
| negative constraints | 只保留关键禁止项 | no neutral medium shot, no identity drift |

禁止把以下内容全部堆进同一帧：

```text
fingerprint texture + engraved surface + tiny spark + energy bridge + exact finger pose + ring position + blurred altar + blurred sky + glow intensity + lighting direction + body visibility constraints
```

如果需要多个细节，应按优先级选 2 到 3 个，而不是全部写入 prompt。

---

### 22.4 Insert Shot 强度分级

`insert shot` 对图像模型通常是强驱动词，容易把画面压缩成极端局部特写。v6.10 将 insert 类镜头分为三档，避免误用。

| 强度 | 推荐名称 | 适用场景 | 风险 |
|---|---|---|---|
| Level 1 | foreground-detail composition | 手部或道具在前景，但仍需要人物和场景可读 | 镜头变化较温和 |
| Level 2 | close-up detail shot | 局部为主，但人物或环境锚点仍可识别 | 适合大多数剧情细节帧 |
| Level 3 | macro insert shot | 真正需要微距展示，如商品纹理、按钮、符文、伤口 | 容易牺牲叙事连续性 |

默认规则：

```text
Use Level 1 or Level 2 for narrative storyboards. Use Level 3 only when the user explicitly needs a microscopic product or texture detail.
```

中文规则：

```text
叙事分镜默认使用 Level 1 或 Level 2。只有明确需要商品纹理、按钮、符文、伤口等微观细节时，才使用 Level 3。
```

示例替换：

不推荐：

```text
Camera transformation: cut into a hand insert shot, magnifying the contact point between the fingertip and the ring surface.
```

推荐：

```text
Camera transformation: change the base medium view into a close-up detail shot, with the hand in the foreground touching the ring while the character's face and the flame lotus remain recognizable behind it.
```

---

### 22.5 Narrative Readability Rule

特殊镜头不仅要有 camera delta，还必须能让观众读懂当前剧情节点。

硬规则：

```text
A special camera frame is invalid if the visual detail becomes so dominant that the story beat is no longer readable.
```

中文规则：

```text
如果特殊镜头中的局部细节过度放大，导致观众看不出当前剧情节点，那么该编辑帧也应判为失败。
```

新增候选评估字段：

```json
{
  "camera_delta": "pass",
  "narrative_readability": "pass / weak / fail",
  "context_anchor_preservation": "pass / weak / fail",
  "detail_overfit_risk": "low / medium / high",
  "accepted": true
}
```

接受标准：

```text
A valid edit frame must pass camera_delta and should not have weak narrative_readability or high detail_overfit_risk.
```

中文标准：

```text
有效编辑帧必须通过镜头变化检查，同时不能出现剧情可读性弱或细节过拟合风险高的问题。
```

---

### 22.6 Context Anchor Preservation Rule

特殊镜头不等于删除上下文。Close-up、insert、low-angle、overhead 等镜头都应保留必要的场景或人物锚点，使其能够被放回原分镜序列中。

规则：

```text
Special camera does not mean context removal.
```

每个特殊镜头至少保留以下一种上下文信息：

1. 角色身份锚点，例如脸、发型、服装边缘、标志性配饰；
2. 场景锚点，例如祭坛边缘、桌面、地面纹理、窗框、门框、建筑轮廓；
3. 动作锚点，例如手部与道具关系、视线方向、喷射轨迹、能量来源；
4. 氛围锚点，例如火焰光、雷暴天空、阳光方向、烟尘、环境反光。

对于 close-up 或 insert shot，推荐写法：

```text
The hand and ring occupy the foreground, but the character's face, the flame lotus, and part of the circular altar remain recognizable in the softened background.
```

不推荐写法：

```text
Blur the background altar and sky to isolate the tactile detail.
```

---

### 22.7 Background Softening Rule

背景虚化应被克制使用。只写 `blur the background` 会让模型把背景连续性降级，甚至重构环境。

推荐规则：

```text
When using blur or shallow depth of field, always specify which background anchors must remain recognizable.
```

中文规则：

```text
只要写背景虚化，就必须同时写明哪些背景锚点仍然需要可识别。
```

不推荐：

```text
Blur the background altar and sky.
```

推荐：

```text
Slightly soften the background while keeping the flame lotus, circular altar edge, and storm lighting recognizable.
```

进一步推荐：

```text
Use shallow depth of field, but keep the main story anchors readable.
```

---

### 22.8 Negative Constraint Compression Rule

编辑帧 prompt 中的负面约束不宜过多。过多 `do not` 会压缩正向构图信息，并可能诱导模型把某些元素直接删除。

推荐只保留三类禁止项：

```text
1. Do not return to a neutral medium shot.
2. Do not change the story beat or action state.
3. Do not alter identity-sensitive characters, props, or hero products.
```

合并写法：

```text
Do not return to a neutral medium shot, do not change the touch moment, and do not alter Nezha's identity or the ring shape.
```

谨慎使用以下否定句：

```text
Do not show the entire character body clearly.
```

原因：这类句子容易让模型把角色整体叙事权重降得过低，使人物只剩背景碎片。若确实不想展示全身，建议改写为正向构图：

```text
Frame the shot around the hand and face rather than the full body.
```

---

### 22.9 Balanced Edit Prompt Template

v6.10 推荐的编辑帧模板如下：

```text
Generate case_edit_frame0x.png: Use case_base_frame0x.png as the direct source for the same story state of [brief inherited story state]. Camera transformation: change the base [ordinary wide/medium view] into [Level 1 foreground-detail composition / Level 2 close-up detail shot / other special camera], using [one primary visual focus] as the visual center, with [optional context relation] only when necessary for readability. Avoid a neutral eye-level medium shot. [Target style].
```

该模板中的关键点：

- v6.13 中该模板已取消独立 `Keep` 句；
- `one primary visual focus` 只允许一个主焦点；
- `two continuity anchors` 防止特殊镜头删除上下文；
- `subtle supporting detail` 明确局部细节是辅助，不是主体；
- 负面约束压缩为三项。

---

### 22.10 哪吒触碰乾坤圈示例

原始问题帧：哪吒躺在火焰莲花中，伸手触碰漂浮的金色乾坤圈。该帧需要镜头变化，但不应变成过度微距的“手指纹理展示图”。

不推荐的方向：

```text
hand insert shot + magnifying the contact point + fingerprint texture + engraved surface + glowing energy bridge + blurred background
```

推荐的 v6.10 写法：

```text
Generate case_edit_frame03.png: Use case_base_frame03.png as the source for the same moment of Nezha lying on the flame lotus and reaching toward the floating golden Universe Ring. Use case_prop_01.png to keep the ring's circular shape, golden metal surface, cloud engravings, and warm orange glow consistent. Camera transformation: change the base medium side view into a close-up detail shot, with Nezha's right hand in the foreground touching the ring while his face, the flame lotus, and part of the circular altar remain recognizable in the softened background. The visual focus is the small spark at the fingertip-ring contact point, with natural skin detail and warm light reflecting on the hand. Do not return to a neutral medium shot, do not change the touch moment, and do not alter Nezha's identity or the ring shape. Cinematic Chinese fantasy 3D animation style.
```

这个版本的变化：

- `hand insert shot` 降级为 `close-up detail shot`；
- 删除 `magnifying the contact point`；
- 删除 `fingerprint texture`；
- 删除 `glowing energy bridge`；
- 将 `blurred background` 改为 `softened background with recognizable anchors`；
- 增加人物脸、火焰莲花、祭坛边缘的上下文保留；
- 保留镜头变化，但避免局部过拟合。

### 22.11 v6.10 候选否决新增项

在 v6.9 的编辑帧否决项基础上，v6.10 增加以下失败判定：

1. 局部细节过度放大，导致剧情节点不可读；
2. close-up 或 insert shot 只剩局部物体，缺少角色、场景或动作锚点；
3. prompt 中多个局部细节互相抢主角，导致主体权重混乱；
4. 背景被完全虚化或重构，无法识别为同一场景；
5. 手部、道具或纹理细节明显过拟合，例如指纹、纹路、能量火花被画成装饰性主元素；
6. 负面约束导致人物主体被过度删除或边缘化；
7. 特殊镜头虽然成立，但无法作为前后帧之间的自然叙事连接。

硬规则：

```text
A cinematic edit frame must be special enough to avoid neutral medium shots, but readable enough to preserve the story beat.
```

中文概括：

```text
编辑帧既要足够特殊，避免退回普通中景；也要足够可读，不能牺牲剧情节点和场景连续性。
```

### 22.12 v6.10 执行口令

生成 edit frame 前额外检查：

1. 当前帧的主视觉焦点是否只有一个？
2. 局部支持性细节是否控制在 2 到 3 个以内？
3. 是否误用了 `macro insert shot`、`magnifying`、`fingerprint texture`、`energy bridge` 等强局部词？
4. 该帧是否保留至少两个上下文锚点？
5. 如果使用背景虚化，是否明确写出仍需可识别的背景锚点？
6. 负面约束是否压缩到 2 到 3 条？
7. 特殊镜头是否仍能读出当前剧情节点？
8. 局部细节是否抢走了人物、动作或场景的叙事权重？
9. 该候选是否只是一个漂亮的局部展示图，而不是有效分镜？
10. 当前 edit frame 是否同时满足 camera diversity 和 narrative readability？


## 23. v6.11 Re-edit Surface Prompt Optimization 补丁：再编辑阶段表层 Prompt 简化

### 23.1 问题定位

v6.10 已经解决了“特殊镜头细节过拟合”的问题，但再编辑阶段还有一个更具体的问题：prompt 中仍可能保留大量资源引用和身份约束。例如测试记录中的前几帧 prompt 写了 `case_char_01.png` 和 `case_prop_01.png`，但实际生成时只输入了 base frame；同时，使用 `{base frame, character frame, prop frame}` 三图参考时，效果反而不稳定。测试记录中较稳定的共同结构是：先用对应 base frame 继承当前剧情状态，再描述画面要展示的内容和镜头类型。

因此，v6.11 将再编辑阶段 prompt 的目标改为：

```text
Describe what the edited frame should show, not every constraint it must preserve.
```

中文概括：

```text
再编辑阶段只需要描述当前画面要展示什么，而不是把所有人物、道具、资源、禁止项都写进 prompt。
```

---

### 23.2 Base-only Edit Reference Rule

再编辑阶段默认只把对应 base frame 作为实际图像参考：

```text
actual_reference_images = [case_base_frame0x.png]
```

人物资源图、道具资源图、场景资源图仍然重要，但它们主要用于：

1. base frame 生成；
2. 分镜规划；
3. 内部一致性审查；
4. 候选图筛选；
5. 异常情况下的纠偏重生成。

它们不应默认进入 edit frame 的实际图像参考，也不应默认写进表层 prompt。

硬规则：

```text
Mention only the images that are actually provided to the image editing model.
```

中文规则：

```text
最终 prompt 里只写本轮实际输入模型的参考图文件名。
```

---

### 23.3 Two-layer Prompt Strategy for Weaker LLMs

对于能力较弱的大模型，不应通过“增加表层 prompt 约束”来弥补理解能力，而应采用两层策略：

```text
Planning Layer: rich structured constraints for the LLM.
Surface Prompt Layer: compact visual description for the image model.
```

规划层可以很详细，例如：

```json
{
  "frame": "case_edit_frame06.png",
  "source_base": "case_base_frame06.png",
  "story_state": "Nezha sitting upright on the glowing lotus while the red sash begins to flow outward",
  "desired_screen_content": "upright seated posture and flowing red sash",
  "camera_type": "single-character seated close-up",
  "primary_visual_focus": "Nezha's upright posture and red sash movement",
  "continuity_anchors": ["glowing lotus", "Universe Ring on wrist"],
  "actual_reference_images": ["case_base_frame06.png"],
  "do_not_surface": ["full character resource traits", "prop resource checklist", "long negative constraints"]
}
```

表层 prompt 则应编译为：

```text
Generate case_edit_frame06.png: Use case_base_frame06.png as the direct source for the same story state of Nezha sitting upright on the glowing lotus while the red sash begins to flow outward. Camera transformation: create a single-character seated close-up centered on the upright seated posture and the red sash starting to move outward, with the glowing lotus and wrist ring used only as light context. Cinematic Chinese fantasy 3D animation style.
```

这可以让低性能模型“内部有约束，输出不啰嗦”。

---

### 23.4 Re-edit Prompt Compiler

v6.11 推荐在工作流中新增 `Edit Prompt Compiler`。它的输入是结构化规划字段，输出是一段表层 prompt。

输入字段：

| Field | 作用 |
|---|---|
| source_base | 实际输入的 base frame |
| story_state | 从 base frame 继承的剧情状态 |
| desired_screen_content | 当前画面要展示的内容 |
| camera_type | 镜头类型 |
| primary_visual_focus | 唯一主视觉焦点 |
| continuity_anchors | 1 到 2 个连续性锚点 |
| style | 风格 |
| actual_reference_images | 实际输入模型的参考图 |
| internal_preserve | 仅用于审查，不默认写进 prompt |
| internal_forbidden | 仅用于审查，不默认写进 prompt |

输出规则：

```text
surface_prompt = source_base + story_state + desired_screen_content + camera_type + primary_visual_focus + continuity_anchors + style
```

不输出：

```text
full identity checklist
strict prop reference checklist
unused file names
long negative constraint chain
resource dependency reasoning
candidate evaluation criteria
surface Keep / preserve / clearly show sentences
```

---

### 23.5 表层 Prompt 质量标准

一个合格的再编辑 prompt 应满足：

1. 只提到实际输入的 base frame；
2. 先描述画面内容，再描述镜头设计；
3. 至少包含一个明确视觉焦点；
4. 如需连续性锚点，只在 Camera transformation 中作为构图上下文轻量出现；
5. 不输出独立 `Keep ... present in the frame` 句；
6. 不把资源审查项写成生成约束；
6. 不把 prompt 写成否定句堆叠；
7. 不为了保一致性而牺牲镜头变化；
8. 不为了镜头变化而删除剧情可读性。

推荐长度：

```text
2-4 sentences for most edit prompts.
```

### 23.6 再编辑候选评估调整

候选图评估仍然要检查身份、道具和场景一致性，但评估项不等于 prompt 必须明写的内容。

新增区分：

```text
Prompt Constraint ≠ Evaluation Criterion
```

中文规则：

```text
候选图需要检查的内容，不一定都要写进生成 prompt。
```

例如，哪吒身份、乾坤圈形状、火焰莲花、祭坛结构都需要在候选选择时检查；但如果 base frame 已经包含这些元素，就不必在 edit prompt 中逐条写成“preserve”。

### 23.7 与 v6.8-v6.10 的关系

v6.11 不取消 v6.8 的资源依赖调度。资源依赖调度仍然用于 base frame 阶段，尤其适用于新人物、新道具和核心商品的首次出现。

v6.11 也不取消 v6.9 的镜头多样性要求。编辑帧仍然不能回退为平淡中景，九宫格仍然需要多样化镜头。

v6.11 也不取消 v6.10 的细节过拟合抑制。局部细节仍然要克制，特殊镜头仍然要保持剧情可读性。

v6.11 只修正一点：

```text
In edit frames, do not transfer all planning constraints into the final surface prompt.
```

中文概括：

```text
再编辑阶段不要把规划层的所有约束都搬进最终 prompt。
```

## 24. v6.12 Edit Prompt Layer Separation 补丁：再编辑阶段 Prompt 分层解耦

### 24.1 问题定位

v6.11 已经把再编辑阶段的参考图策略修正为 **base-only**，并要求最终 prompt 不再堆叠人物资源图、道具资源图和长串保持项。但是在实际生成中，仍然可能出现一个新的表层 prompt 问题：

```text
画面描述块提前描述了镜头焦点，Camera transformation 块又再次描述同一个镜头焦点。
```

例如：

```text
Show the right hand and golden ring in close proximity, capturing the tension of imminent contact with subtle light reflection on the skin and metal surface.
Camera transformation: create a close-up detail shot focused on the hand and ring...
```

这类写法会把“手和乾坤圈”这个视觉重点重复强化两次。模型容易把手部、金环、光影和局部关系推到过高权重，导致前景物体过大、手部结构异常、道具压迫画面、背景叙事锚点被削弱，甚至生成额外饰物或不必要的细节。

v6.12 的核心修正是：

```text
Content block describes what exists and what is happening.
Camera block describes how the image is viewed.
Do not let the content block perform camera work.
```

中文概括：

```text
画面描述块只描述“有什么、发生什么”；镜头描述块才描述“怎么拍、看哪里”。不要让画面描述块承担镜头设计职责。
```

---

### 24.2 Edit Prompt Layer Separation Rule

再编辑阶段 prompt 必须分为两个职责清晰的层：

| Prompt Layer | 负责内容 | 不负责内容 |
|---|---|---|
| Content Block | 当前剧情状态、画面中应出现的关键元素、基础连续性锚点 | 特写、焦点、近距离、前景、背景、虚化、景深、局部细节、镜头情绪 |
| Camera Transformation Block | 镜头类型、视觉中心、构图关系、前后景、景深处理、少量局部支持细节 | 新增剧情、改变人物状态、改变道具状态、重复罗列画面元素 |

硬规则：

```text
In the edit-stage prompt, the content block must describe only story state and visible scene elements. It must not describe shot scale, focal emphasis, foreground-background arrangement, depth-of-field behavior, close proximity, lighting detail, or local framing intention. All camera-related descriptions belong only to the Camera transformation block.
```

中文规则：

```text
在再编辑阶段，画面描述块只负责剧情状态和可见元素；不得描述景别、焦点、前后景关系、景深、近距离、光影细节或局部取景意图。所有镜头相关信息只能放入 Camera transformation 块。
```

---

### 24.3 Content Block Whitelist：画面描述块白名单

画面描述块只允许写三类信息。

#### A. 当前剧情状态

例如：

```text
Nezha lies on the glowing flame lotus.
His right hand is raised toward the floating Universe Ring.
The Universe Ring is not yet fitted onto his wrist.
```

#### B. 当前动作状态中的关键对象

例如：

```text
His right hand is raised toward the floating Universe Ring.
The red sash begins to flow outward.
The Universe Ring has fitted onto his raised right wrist.
```

#### C. 基础连续性锚点

例如：

```text
The glowing flame lotus and circular altar are part of the inherited scene state.
```

注意：画面描述块可以通过剧情状态自然带出对象，但不应额外增加独立的 `Keep ... present in the frame` 元素清单。

---

### 24.4 Content Block Blacklist：画面描述块禁用项

以下内容不应出现在画面描述块中，因为它们属于镜头块职责。

| 禁用表达类型 | 示例 | 问题 |
|---|---|---|
| 焦点表达 | `focused on the hand and ring` | 提前侵入镜头块 |
| 景别表达 | `close-up`, `insert shot`, `wide shot` | 属于镜头设计 |
| 距离关系强化 | `in close proximity`, `magnifying the contact point` | 容易过度放大局部 |
| 前后景关系 | `foreground`, `background`, `behind it` | 属于构图和景深 |
| 虚化表达 | `softly visible`, `blurred`, `shallow depth of field` | 属于镜头处理 |
| 细节渲染 | `subtle light reflection on the skin and metal surface` | 容易变成局部细节过拟合 |
| 镜头情绪 | `capturing the tension`, `isolating the tactile detail` | 容易重复强化焦点 |
| 视觉中心 | `as the visual center`, `occupying the frame` | 属于 Camera transformation |
| 显式保持句 | `Keep A, B, and C present in the frame` | 会把内部审查项变成画面塞入项 |
| 保持/纠偏链 | `preserve...`, `without altering...`, `clearly show...` | 容易形成多目标约束并干扰镜头变化 |

不推荐：

```text
Show the right hand and golden ring in close proximity, capturing the tension of imminent contact with subtle light reflection on the skin and metal surface.
```

推荐改为：

```text
Use case_base_frame03.png as the direct source for the same story state of Nezha lying on the glowing flame lotus with his right hand raised toward the floating Universe Ring.
```

前者在画面描述块中同时描述了距离、情绪、光影和局部视觉重点；后者只继承剧情状态，不额外罗列元素。

---

### 24.5 Camera Block Ownership Rule：镜头块拥有视觉焦点

`Camera transformation` 是再编辑 prompt 中唯一负责镜头设计的部分。它可以描述：

1. 镜头类型，例如 `close-up detail shot`、`low-angle hero shot`、`overhead shot`；
2. 主视觉焦点，例如 `the raised hand and the Universe Ring as the visual center`；
3. 前后景关系，例如 `Nezha's face remains softly recognizable in the background`；
4. 背景保留，例如 `the flame lotus edge remains readable`；
5. 少量局部支持细节，例如 `warm glow on the hand`。

推荐写法：

```text
Camera transformation: create a close-up detail shot with the raised right hand and the Universe Ring as the visual center, while Nezha's face and the edge of the flame lotus remain softly recognizable in the background.
```

这句话已经完整承担了“怎么拍、看哪里、保留什么背景锚点”的职责。因此，画面描述块不需要再提前写 `close proximity`、`tension`、`subtle light reflection` 等内容。

---

### 24.6 Duplicate Emphasis Rejection Rule：重复焦点否决

如果同一视觉重点在 Content Block 和 Camera Transformation Block 中被重复描述，应判定为冗余风险 prompt，需要重写。

判定规则：

```text
If the same focal relationship is described in both the content block and the camera block, remove it from the content block and keep it only in the camera block.
```

中文规则：

```text
如果同一个镜头焦点或局部关系同时出现在画面描述块和镜头描述块中，应从画面描述块删除，只保留在镜头描述块中。
```

示例：

| 原始内容块 | 是否重复 | 修正方式 |
|---|---|---|
| `Show the right hand and ring in close proximity` | 与 `close-up focused on hand and ring` 重复 | 从画面块删除，由 story state 自然继承 |
| `Capture the tension of imminent contact` | 与镜头焦点和动作状态重复 | 删除，或放入镜头块作为 `the hand is about to touch the ring` |
| `with subtle reflection on skin and metal` | 与 close-up 细节重复 | 只在镜头块保留 `warm glow on the hand and ring` |
| `the ring softly visible in the background` | 属于前后景安排 | 移入 Camera transformation |

### 24.7 v6.12 Re-edit Prompt Template

## 25. v6.13 No-Keep Surface Prompt 补丁：再编辑阶段不输出显式保持句

### 25.1 问题定位

v6.12 已经要求画面描述块与镜头描述块分层，但仍保留了一个表层 prompt 风险：

```text
Keep [visible element 1], [visible element 2], and [continuity anchor] present in the frame.
```

这类句子看似只是要求保留元素，实际会产生两个副作用：

1. 将规划层和评估层的 `keep` 项重新塞回最终生成 prompt；
2. 让模型尝试同时维护所有被点名元素，导致主体、道具、背景、姿态和前景物体互相抢画面权重。

在再编辑阶段，base frame 已经包含当前角色、道具、姿态、环境和光照状态。只要 prompt 写明 `Use case_base_frame0x.png as the direct source for the same story state of ...`，模型就已经获得了继承状态的入口。额外写 `Keep ... present in the frame` 往往不是增强连续性，而是制造显式干扰。

核心修正：

```text
Do not surface Keep sentences in edit prompts.
Keep information belongs to planning and evaluation, not generation.
```

中文概括：

```text
再编辑 prompt 不输出 Keep 句。Keep 信息属于规划层和候选评估层，不属于最终生成 prompt。
```

---

### 25.2 No-Keep Surface Rule

硬规则：

```text
In edit-stage surface prompts, do not output standalone sentences starting with Keep, Preserve, Clearly show, Reframe the same moment without altering, or similar preservation commands. These constraints should stay in internal planning fields and candidate evaluation criteria.
```

中文规则：

```text
再编辑阶段的表层 prompt 中，不输出以 Keep、Preserve、Clearly show、Reframe the same moment without altering 等形式出现的独立保持句。这些约束应保留在内部规划字段和候选评估标准中。
```

不推荐：

```text
Keep Nezha's upright posture, fists, red sash, the floating ring, and the edge of the flame lotus present in the frame.
```

不推荐：

```text
Keep Nezha's seated posture, face, red sash, right arm with the Universe Ring, and the edge of the flame lotus present in the frame.
```

推荐改为仅在 story state 中自然继承：

```text
Use case_base_frame06.png as the direct source for the same story state of Nezha sitting upright on the glowing lotus while the red sash begins to flow outward.
```

然后由镜头块处理观看方式：

```text
Camera transformation: create a single-character seated close-up centered on Nezha's upright seated posture and the flowing red sash.
```

### 25.3 Internal Keep vs Surface Prompt

`keep` 字段仍然可以存在，但只用于内部，不直接进入 prompt。

推荐结构：

```json
{
  "source_base": "case_base_frame06.png",
  "story_state": "Nezha sitting upright on the glowing lotus while the red sash begins to flow outward",
  "camera_type": "single-character seated close-up",
  "primary_visual_focus": "upright seated posture and flowing red sash",
  "internal_keep_for_evaluation_only": [
    "seated posture",
    "face identity",
    "red sash",
    "right arm with Universe Ring",
    "flame lotus edge"
  ],
  "surface_prompt_policy": "do not surface keep list"
}
```

编译输出：

```text
Generate case_edit_frame06.png: Use case_base_frame06.png as the direct source for the same story state of Nezha sitting upright on the glowing lotus while the red sash begins to flow outward. Camera transformation: create a single-character seated close-up centered on Nezha's upright seated posture and the flowing red sash. Cinematic Chinese fantasy 3D animation style.
```

候选图选择时再检查：

```text
Does the candidate preserve seated posture, face identity, red sash, wrist ring, and lotus context?
```

也就是说：

```text
Keep is checked after generation, not instructed before generation.
```

### 25.4 Updated Edit Prompt Compiler

v6.13 的表层 prompt 编译器输入仍可丰富，但输出必须克制。

输入字段：

| Field | 是否进入表层 prompt | 说明 |
|---|---|---|
| source_base | yes | 实际输入的 base frame |
| story_state | yes | 用一句话继承当前画面状态 |
| camera_type | yes | 镜头类型 |
| primary_visual_focus | yes | 镜头块中的唯一焦点 |
| context_relation | optional | 只在镜头可读性需要时写入 |
| style | yes | 风格 |
| internal_keep | no | 仅用于候选评估 |
| internal_forbidden | no by default | 仅异常时转为最小负面约束 |
| visible_elements | no by default | 不转为 Keep 句 |
| resource_traits | no | 不转为身份或道具清单 |

输出公式：

```text
surface_prompt = source_base + story_state + camera_transformation + optional_minimal_anti_medium + style
```

不输出：

```text
Keep A, B, and C present in the frame.
Preserve A, B, C, D...
Clearly show A, B, C...
Reframe the same moment without altering A, B, C...
Do not change A, do not remove B, do not alter C...
```

### 25.6 When Context Relation Is Allowed

有时完全不写上下文会让特殊镜头变成局部漂浮图。v6.13 允许在 Camera transformation 中加入一个轻量 context relation，但不能写成 Keep 句。

允许：

```text
with the glowing lotus softly visible as context
```

允许：

```text
with the circular altar edge readable in the background
```

不推荐：

```text
Keep the glowing lotus and circular altar edge present in the frame.
```

区别在于：前者是镜头关系，后者是元素清单。

### 25.7 v6.13 执行口令

生成 edit prompt 前额外检查：

1. 是否出现了独立的 `Keep ... present in the frame` 句？如果有，删除。
2. 是否出现了 `preserve...`、`clearly show...`、`reframe without altering...` 这类保持链？如果有，转入内部评估字段。
3. `story_state` 是否已经足够继承当前画面状态？
4. 需要保留的元素是否可以在候选评估时检查，而不是写进 prompt？
5. 镜头块是否已经说明本帧真正要看的内容？
6. prompt 是否因为列举元素而变成多目标约束？
7. 是否可以把 `Keep A, B, C` 改为一句 `Use case_base_frame0x.png as the direct source for the same story state of ...`？
8. 是否只在必要时使用一个 context relation？
9. 最终 prompt 是否仍然清楚但不啰嗦？
10. 最终 prompt 是否适合直接送入图像编辑模型？

### 25.8 一句话规则

```text
For edit prompts, describe the inherited state once, then describe the camera. Do not add a separate Keep sentence.
```

中文概括：

```text
再编辑 prompt 只需先继承当前状态，再描述镜头；不要额外加 Keep 句。
```
