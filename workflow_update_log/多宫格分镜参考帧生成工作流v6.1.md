# 多宫格分镜参考帧生成工作流（v6.1：先稳定九宫格，再镜头变换 + 基础帧朝向显式控制 + 最小参考原则）

## 0. 版本定位

本版本是在 v6.0 的基础上继续收紧第一阶段基础帧规则，用于解决“剧情连续性”“镜头多样性”和“人物朝向稳定性”之间相互干扰的问题。

v5.3 的核心逻辑是：在逐帧生成过程中同时控制剧情推进、角色一致、场景一致、位置锚点、朝向关系、可见内容和镜头变化。该方式能够直接得到具有电影感的多宫格分镜，但在复杂镜头中存在一个风险：如果某一帧为了获得镜头多样性而采用特写、俯视、过肩、背面、旋转视角等复杂构图，那么这张图可能不再适合作为下一帧的稳定参考，后续帧容易继承错误的人物比例、场景结构、位置关系或朝向关系。

v6.0 将原来的“一步式多样镜头分镜生成”拆分为两个阶段：

1. **第一阶段：稳定剧情九宫格生成**  
   先生成一组固定全景或固定中景的剧情参考帧，用来锁定人物、场景、道具状态、位置锚点和剧情节点。此阶段的目标是建立连续剧情骨架，而不是追求镜头多样性。

2. **第二阶段：镜头多样性变换**  
   在稳定九宫格生成完成后，由多模态大模型查看九张基础参考帧，选择适合做镜头变化的帧，再基于这些基础帧生成特写、俯视、低角度、过肩、背面、局部插入镜头等变换版本。镜头变换只影响当前派生帧，不反向影响其它剧情帧。

核心变化可以概括为：

```text
v5.3: 多样镜头帧直接进入下一帧参考链，镜头错误可能向后传播。
v6.0: 基础剧情帧负责连续性，派生镜头帧负责电影感，两者解耦。
v6.1: 基础剧情帧进一步显式控制人物与镜头的关系，并采用最小参考原则，避免重复引用角色图导致镜头拉近或人物转正。
```

v6.1 新增两条硬性规则：

1. **基础帧必须显式写明 Subject–Camera Relation**：不能只写人物面向桌子、玉简、石台、门口等目标物，还必须写人物相对镜头是背对、正对、侧对、三分之二背对还是三分之二正对。
2. **基础帧采用最小参考原则**：如果当前帧只是同一镜头尺度、同一人物可见面下的剧情推进，优先只参考上一张基础帧；不要机械地重复引用 `case_char_01.png`，避免模型重新展示角色正脸、拉近镜头或改变构图。

## 1. 核心目标

用于指导大模型基于用户 idea 生成 **N=4 / 9 / 16 / 25** 的多宫格参考帧，其中 9 宫格是默认推荐形态。

v6.1 的目标分为两层：

### 1.1 第一阶段目标：稳定剧情骨架

- 剧情连续：每一帧是一个明确的剧情状态节点；
- 状态清楚：人物动作、视线、道具状态、场景变化有明确承接；
- 角色稳定：人物身份、发型、服装、体型、配饰保持一致；
- 场景稳定：空间结构、光源、关键参考物、地面纹理保持一致；
- 位置稳定：人物和道具必须使用场景内可见锚点定位；
- 镜头稳定：每一帧只使用明确的全景或明确的中景；
- 朝向稳定：每一帧必须明确人物与目标物关系，以及人物与镜头关系；
- 参考稳定：每张基础帧都应适合作为后续剧情参考，而不是只适合作为视觉效果图；
- 最小参考：基础帧不默认重复引用角色图，只在视角、可见面、身份漂移或姿态大幅变化时重新引入角色参考。

### 1.2 第二阶段目标：镜头多样性增强

- 从基础九宫格中选择适合变换的帧；
- 对选中帧进行镜头重构，例如特写、局部、俯视、低角度、背面、过肩、构图旋转；
- 保持基础帧中的人物身份、剧情状态、道具状态、场景锚点和光源方向；
- 镜头变换结果只作为当前镜头表现，不再作为基础剧情链的核心参考；
- 最终输出既有连续剧情，又有电影镜头变化。

## 2. 总体流程

### Step 1：接收用户输入

用户通常输入：

- 一个简单 idea；
- 宫格数量 N，通常为 4 / 9 / 16 / 25；
- 可选：风格、人物数量、场景数量、关键道具、关键动作；
- 可选：每帧是否一次生成多张候选图；
- 可选：是否需要第二阶段镜头变换。

### Step 2：整体策划

首次响应时，模型输出：

1. 视频概述；
2. 最少人物、场景、道具数量；
3. 资源库构建 prompt；
4. 第一阶段基础剧情帧规划；
5. 只给出 `case_base_frame01.png` 的英文一段式 prompt。

不要一次性给出所有基础帧的详细 prompt。只给当前要生成的一帧。

### Step 3：第一阶段逐帧生成基础九宫格

逐帧生成 `case_base_frame01.png` 到 `case_base_frame09.png`。

每一帧必须先确定唯一镜头类型：

- `wide shot`
- `medium shot`

最终 prompt 里只能写已经确定的一个镜头类型，不能写 `wide shot or medium shot`，不能写 `wide / medium shot`，不能写 `either wide shot or medium shot`，也不能使用任何含糊的选择式表达。

基础帧阶段不主动使用：

- close-up
- insert shot
- overhead view
- over-the-shoulder view
- Dutch angle
- extreme low-angle view
- complex camera rotation
- heavy foreground blocking

除非用户明确要求第一阶段就使用特殊镜头，否则基础帧只承担剧情状态表达。

### Step 4：第一阶段候选图选择

如果用户一次上传同一基础帧的多张候选图，模型必须先选择最适合作为基础剧情帧的图，不得直接进入下一帧。

基础帧候选选择重点不是“画面最炫”，而是：

1. 是否符合当前剧情节点；
2. 是否稳定继承角色身份；
3. 是否稳定继承场景结构；
4. 是否准确使用位置锚点；
5. 是否清楚表现人物与目标物关系；
6. 是否清楚表现人物与镜头关系；
7. 是否没有复杂镜头导致的信息缺失；
8. 是否适合作为下一帧剧情参考。

### Step 5：完成基础九宫格后进行整体质检

当 `case_base_frame01.png` 到 `case_base_frame09.png` 全部完成后，模型需要进行整体检查：

- 九张图的人物是否一致；
- 场景是否一致；
- 关键道具是否连续；
- 位置推进是否清楚；
- 剧情是否能从第一帧读到第九帧；
- 是否存在某张基础帧因为镜头太复杂而无法作为参考；
- 是否需要重生成某一张基础帧。

只有基础九宫格通过后，才进入第二阶段。

### Step 6：第二阶段由多模态大模型选择镜头变换帧

第二阶段不由人工固定指定哪些帧变换，而是由多模态大模型查看完整基础九宫格后自行选择。

模型需要判断：

- 哪些帧具有关键动作或关键道具；
- 哪些帧适合做局部细节强化；
- 哪些帧适合做情绪或力量反应强化；
- 哪些帧适合改变机位以增强电影感；
- 哪些帧保持基础镜头即可，不需要变换。

不是每一帧都必须变换。若某些基础帧已经足够清楚稳定，且镜头变化会削弱连续性，则可以保留原基础帧作为最终帧。

### Step 7：生成镜头变换帧

对被选中的基础帧生成派生镜头，例如：

- `case_shot_frame03.png`
- `case_shot_frame04.png`
- `case_shot_frame06.png`

每个派生帧的 prompt 都必须明确引用对应基础帧，例如：

```text
Use case_base_frame04.png for the exact story state, character identity, object state, scene layout, lighting direction, and visible spatial anchors.
```

派生帧的重点是镜头重构，而不是改变剧情状态。不能让人物进入新的剧情动作，也不能改变道具状态。

### Step 8：最终分镜整理

最终分镜可以由两类帧组成：

- 未变换的基础帧；
- 变换后的派生镜头帧。

最终可以统一命名为：

- `case_final_frame01.png`
- `case_final_frame02.png`
- ...
- `case_final_frame09.png`

如果某一帧没有做镜头变换，则对应基础帧直接作为最终帧。  
如果某一帧做了镜头变换，则派生帧替代基础帧进入最终分镜。

## 3. 命名规则

### 3.1 资源库命名

- 人物参考图：`case_char_01.png`
- 多人物参考图：`case_char_02.png`、`case_char_03.png`
- 场景参考图：`case_scene_01.png`
- 多场景参考图：`case_scene_02.png`
- 道具参考图：`case_prop_01.png`

### 3.2 第一阶段基础帧命名

- 基础剧情帧：`case_base_frame01.png`、`case_base_frame02.png`、……、`case_base_frame09.png`
- 同一基础帧候选图：`case_base_frame03_A.png`、`case_base_frame03_B.png`、`case_base_frame03_C.png`
- 选中候选后必须重命名为正式基础帧，例如：`case_base_frame03_B.png` → `case_base_frame03.png`

### 3.3 第二阶段镜头变换帧命名

- 镜头变换帧：`case_shot_frame03.png`、`case_shot_frame04.png`、`case_shot_frame06.png`
- 同一镜头变换候选图：`case_shot_frame04_A.png`、`case_shot_frame04_B.png`
- 选中候选后必须重命名为正式派生帧，例如：`case_shot_frame04_B.png` → `case_shot_frame04.png`

### 3.4 最终分镜命名

- 最终分镜帧：`case_final_frame01.png`、`case_final_frame02.png`、……、`case_final_frame09.png`

最终 prompt 中禁止写：

```text
the previous image
Image 0
reference image
this image
last frame
the selected image
```

必须写真实文件名。

## 4. 资源库构建规则

资源库构建规则与 v5.3 保持一致，但在 v6.0 中更强调“后续基础九宫格可复用锚点”。

### 4.1 人物参考图

人物参考图用于锁定完整角色形象，不是只锁定脸部。

应包含：

- 全身入镜；
- 正面或 3/4 正面视角；
- 发型、发饰、脸型、服装轮廓、腰带、袖口、靴子、配饰清楚；
- 纯色或简洁背景；
- 不要场景、复杂特效、额外人物。

示例：

```text
Generate case_char_01.png: a full-body character reference sheet of Wang Lin, a young male Chinese fantasy cultivator with black hair tied in a high topknot, wearing a dark blue robe with silver embroidery, a waist belt, long sleeves, black boots, and small jade accessories, standing naturally from head to toe on a plain light background, front three-quarter view, clear facial structure, hairstyle, outfit silhouette, sleeve details, belt, boots, no scene, no magic effects, no extra characters, cinematic Chinese fantasy 3D animation style.
```

### 4.2 场景参考图

场景参考图不仅要锁定氛围，还要主动生成可复用视觉锚点。

应包含：

- 空间结构；
- 关键地标或家具；
- 地面纹理；
- 台阶、门框、窗户、石柱、桌角、桌面边缘、圆形纹路等可定位元素；
- 光源方向；
- 最好不要人物。

示例：

```text
Generate case_scene_01.png: an empty ancient lava cave interior, clearly showing the spatial layout with a central circular stone platform, multi-ringed circular texture on the platform surface, surrounding molten lava flows, platform edge stones, rocky walls, cave opening, stalactites, and dim orange ambient lighting from the lava, no characters, no props, pure environment reference, cinematic Chinese fantasy 3D animation style.
```

### 4.3 道具参考图

若剧情依赖关键道具，则单独生成道具图。

道具参考图应锁定：

- 外形；
- 材质；
- 大小比例；
- 纹理；
- 发光状态；
- 朝向；
- 纯色背景或简单台面。

## 5. 第一阶段：稳定剧情九宫格规划规则

第一阶段的九宫格不是电影镜头集合，而是剧情状态集合。

每一帧都要回答：

1. 当前剧情节点是什么？
2. 人物处于什么最终状态？
3. 人物和目标物的关系是什么？
4. 人物和镜头的关系是什么：正面、背面、侧面、三分之二正面还是三分之二背面？
5. 人物在场景中的落点是什么？
6. 关键道具处于什么状态？
7. 当前帧应该使用 `wide shot` 还是 `medium shot`？
8. 当前帧是否需要重新引用 `case_char_01.png`，还是只参考上一帧更稳定？
9. 这一帧是否适合作为下一帧参考？

### 5.1 基础帧镜头硬性规则

基础帧阶段每一帧必须先在规划表中确定唯一镜头类型：

```text
Base camera: wide shot
```

或：

```text
Base camera: medium shot
```

最终 prompt 中必须写一个确定的 camera layer，例如：

```text
Camera: wide shot, eye-level view, static composition, showing the full body of the character and the complete spatial relationship between the stone platform, the lava flow, and the cave wall.
```

或：

```text
Camera: medium shot, eye-level view, stable centered composition, showing the character from head to knees with the nearby table edge, scroll, and window frame still visible as spatial anchors.
```

禁止写：

```text
Camera: wide shot or medium shot.
```

```text
Camera: wide / medium shot.
```

```text
Camera: either a wide shot or a medium shot.
```

```text
Camera: use a suitable wide or medium view.
```

### 5.2 基础帧人物–镜头关系硬性规则

基础帧阶段不允许只通过剧情语义暗示人物朝向。每一帧 prompt 必须同时写明：

1. **Subject–Object Relation**：人物面向哪个目标物或正在与哪个目标物交互；
2. **Subject–Camera Relation**：镜头看到的是人物正面、背面、侧面、三分之二正面还是三分之二背面。

例如，人物站在桌前看玉简时，不能只写：

```text
facing the tabletop where the jade slip rests
```

因为这句话只能说明人物面对玉简，不能防止模型把镜头绕到人物正面。应写成：

```text
facing the tabletop where the jade slip rests, with his back facing the camera
```

或：

```text
full-body back view of the cultivator; the table is directly in front of him and his back faces the camera
```

如果当前帧应保持背影，还必须加入可见与不可见约束：

```text
Clearly show the back of his high ponytail, rear shoulder line, back-view robe folds, sash, sleeves, and boots. Do not show his face, do not rotate the camera to the front side of the character.
```

如果当前帧应为侧面，则应写：

```text
side view of the character, with his left shoulder closer to the camera and the tabletop directly in front of his hands
```

如果当前帧应为正面，则应写：

```text
front view of the character facing the camera, while the table remains behind his hands as a visible anchor
```

核心原则：

```text
人物面向目标物 ≠ 人物背对镜头。Subject–Object Relation 和 Subject–Camera Relation 必须分开判断，并且都写进 prompt。
```

### 5.3 全景与中景的选择标准

#### 使用 wide shot 的情况

当当前帧需要强调以下内容时，选择 `wide shot`：

- 人物与完整场景的空间关系；
- 人物从一个场景锚点移动到另一个场景锚点；
- 关键道具和人物距离关系；
- 多人物站位；
- 场景状态变化；
- 开场或收束；
- 需要为后续帧提供完整稳定参考。

#### 使用 medium shot 的情况

当当前帧需要强调以下内容时，选择 `medium shot`：

- 人物上半身动作；
- 手部动作但仍需看到身体和场景锚点；
- 人物与近处道具互动；
- 人物视线和姿态；
- 不需要完整场景，但仍需要保留关键空间锚点。

### 5.4 基础帧阶段不追求镜头多样性

基础帧之间可以有少量宽窄变化，但不以“每帧镜头不同”为目标。

允许：

- wide shot → wide shot；
- wide shot → medium shot；
- medium shot → medium shot；
- medium shot → wide shot。

不允许为了镜头多样性强行加入：

- 特写；
- 局部插入；
- 过肩；
- 俯视；
- 背面遮挡；
- 大幅旋转；
- 极端低角度；
- 大面积前景遮挡。

基础帧首先要稳定，其次才考虑基础层面的构图变化。

### 5.5 基础九宫格推荐节奏

9 宫格推荐结构：

| 帧 | 剧情功能 | 推荐基础镜头 | 说明 |
|---|---|---|---|
| case_base_frame01.png | 建立人物与场景 | wide shot | 显示人物、场景、主要锚点 |
| case_base_frame02.png | 人物进入行动位置 | wide shot | 显示人物新位置和落点 |
| case_base_frame03.png | 人物开始关键动作 | medium shot | 保留身体、手部、附近锚点 |
| case_base_frame04.png | 人物与道具或目标物接近 | medium shot | 显示接近后的最终状态 |
| case_base_frame05.png | 关键道具或环境发生变化 | medium shot | 显示人物、道具、变化状态 |
| case_base_frame06.png | 力量或剧情升级 | wide shot | 显示人物与环境变化关系 |
| case_base_frame07.png | 人物获得结果或完成动作 | medium shot | 显示人物和结果状态 |
| case_base_frame08.png | 人物离开或转向下一状态 | wide shot | 显示人物位置变化 |
| case_base_frame09.png | 收束或余波 | wide shot | 显示最终环境和人物状态 |

这个表只是推荐节奏，不是固定模板。实际镜头必须根据用户 idea 和场景内容决定，但每帧必须明确是 `wide shot` 或 `medium shot`。

## 6. 第一阶段 Prompt 规则

基础帧 prompt 必须是英文一段式，且必须包含：

1. 文件名；
2. 参考哪些真实文件名；
3. 每张图分别参考什么；
4. 确定的基础镜头类型；
5. 位置锚点；
6. 人物与目标物关系；
7. 人物与镜头关系；
8. 当前剧情状态；
8. 道具或环境状态；
9. 不改变角色和场景的约束；
10. 风格句。

### 6.1 基础帧最小参考原则（Base Frame Reference Minimization）

第一阶段基础帧生成不应机械地使用“上一帧 + 角色参考图”的固定组合。基础帧的目标是稳定继承剧情、场景、镜头尺度和人物可见面，因此参考图应尽量少、尽量直接。

#### 优先只参考上一张基础帧的情况

如果当前帧只是以下变化，优先只参考上一张基础帧：

- 人物从一个位置移动到另一个位置；
- 人物仍然是同一种可见面，例如上一帧是背影，当前帧仍然是背影；
- 镜头尺度没有显著变化，例如 wide shot 继续 wide shot，或 medium shot 继续 medium shot；
- 场景、光源、人物服装、人物比例基本稳定；
- 当前目标是继承上一帧的构图距离和人物朝向，而不是重新展示角色细节。

推荐写法：

```text
Use case_base_frame01.png for the cultivator's character identity, current back-view robe silhouette, black high ponytail, library layout, moonlight direction, stone floor texture, bookshelf positions, central table outline, and the overall shot distance.
```

这种写法让上一帧同时承担角色、场景、镜头距离和朝向继承，通常比再次引用 `case_char_01.png` 更稳定。

#### 需要重新引用 `case_char_01.png` 的情况

只有当当前帧发生以下变化时，才建议重新引入角色参考图：

- 从背影切到正面，或从正面切到背影；
- 人物可见面发生明显变化，需要重新确认脸部、发型或服装细节；
- 镜头从 wide shot 变为 medium shot，且人物细节明显放大；
- 上一帧人物身份、发型、服装已经漂移；
- 当前帧有显著姿态变化，上一帧不足以提供稳定人物信息；
- 当前帧需要清楚展示正脸、胸前服饰、手部细节或配饰。

#### 不推荐的默认写法

```text
Use case_char_01.png for the character identity, and use case_base_frame01.png for the scene layout...
```

这类写法并非永远错误，但不能成为基础帧默认模板。`case_char_01.png` 往往是角色展示图，容易诱导模型拉近镜头、展示正脸、改变人物比例，导致基础帧失去稳定构图。

核心原则：

```text
基础帧优先继承上一帧的剧情状态、镜头尺度、人物可见面和场景锚点；只有在身份校正或可见面显著变化时，才重新引用角色图。
```

## 7. 第一阶段候选选择规则

当用户上传同一基础帧的多个候选图时，模型必须先执行基础帧候选选择。

### 7.1 基础帧选择优先级

1. **Story State Accuracy**：是否准确表现当前剧情节点；
2. **Base Camera Accuracy**：是否符合指定的 `wide shot` 或 `medium shot`；
3. **Subject–Camera Accuracy**：人物相对镜头的正面、背面、侧面或三分之二视角是否正确；
4. **Subject–Object Accuracy**：人物是否正确面向、背向、侧对或接触目标物；
5. **Anchor Accuracy**：人物、道具是否落在指定场景锚点；
6. **Reference Stability**：候选图是否继承了上一帧的镜头尺度、人物比例和可见面，而没有被额外参考图诱导拉近或转正；
7. **Character Consistency**：人物身份、发型、服装、体型是否稳定；
8. **Scene Continuity**：场景结构、光源、关键物体是否继承；
9. **Object State Continuity**：道具或环境状态是否正确；
10. **Future Usability**：是否适合作为下一帧基础剧情参考；
11. **Visual Quality**：是否清晰、无畸形、无错误元素。

### 7.2 基础帧候选选择输出模板

```md
推荐选择：case_base_frame03_B.png，并将其命名为正式的 case_base_frame03.png。

理由：B 最适合作为基础剧情帧。它准确表现了当前剧情节点，人物仍然保持完整可见，镜头符合 medium shot，脚下位置对齐平台内圈纹理，角色服装、发型、场景光源和道具状态都比较稳定。A 的人物位置偏离场景锚点，C 的镜头过近，不适合作为后续剧情参考。

下一帧进入“……”。

Generate case_base_frame04.png: ...
```

### 7.3 全部不合格时

```md
这一组候选图都不建议选为 case_base_frame03.png。主要问题是人物没有落在指定场景锚点，且镜头过近，无法作为稳定基础剧情帧。建议重生成当前帧。

Regenerate case_base_frame03.png: ...
```

## 8. 第二阶段：镜头多样性变换选择规则

当基础九宫格全部完成后，模型需要查看完整九宫格，并自行决定哪些帧需要镜头变换。

### 8.1 由多模态模型选择，而不是人工固定

第二阶段必须由多模态大模型基于图像内容选择变换帧。

模型不能预设：

```text
第 3、5、7 帧一定要变换。
```

应根据实际图像判断：

- 哪些帧的剧情节点最重要；
- 哪些帧有适合特写的手、道具、表情或接触点；
- 哪些帧有适合俯视的空间关系；
- 哪些帧有适合低角度的力量展示；
- 哪些帧有适合过肩或背面镜头的主体与目标物关系；
- 哪些帧基础图已经足够好，不需要变换。

### 8.2 适合做镜头变换的帧

优先选择：

- 关键道具出现或状态变化的帧；
- 人物与道具发生接触的帧；
- 人物施法、攻击、拿取、打开、转身、凝视等动作明确的帧；
- 环境发生明显变化的帧；
- 适合用镜头强化力量感、压迫感、神秘感或结果感的帧；
- 基础帧人物和场景都稳定，适合进一步重构镜头的帧。

### 8.3 不适合做镜头变换的帧

不建议选择：

- 基础图本身角色或场景已经不稳定的帧；
- 当前帧主要承担空间交代功能，变成特写会丢失剧情信息的帧；
- 位置锚点不清楚的帧；
- 道具状态不明确的帧；
- 人物身份已经有明显偏差的帧；
- 变换后会破坏剧情阅读顺序的帧。

### 8.4 第二阶段选择输出表

基础九宫格通过后，模型应输出类似表格：

| 基础帧 | 是否变换 | 变换类型 | 选择理由 | 最终使用 |
|---|---|---|---|---|
| case_base_frame01.png | 否 | 保持基础 wide shot | 开场需要完整交代场景 | case_final_frame01.png |
| case_base_frame02.png | 否 | 保持基础 wide shot | 位置推进比镜头变化更重要 | case_final_frame02.png |
| case_base_frame03.png | 是 | medium close-up | 人物开始施法，适合强化手势和上半身 | case_shot_frame03.png |
| case_base_frame04.png | 是 | insert shot | 手与道具接触，是关键细节 | case_shot_frame04.png |
| case_base_frame05.png | 是 | overhead view | 环境能量扩散适合俯视展示 | case_shot_frame05.png |
| case_base_frame06.png | 是 | low-angle view | 高潮帧适合强化人物力量感 | case_shot_frame06.png |
| case_base_frame07.png | 否 | 保持基础 medium shot | 基础状态已清楚 | case_final_frame07.png |

## 11. 位置锚点定位规则

位置锚点规则在两个阶段都必须使用。

### 11.1 必须使用场景内可见锚点

当 prompt 描述人物或道具位置时，优先使用场景图或基础帧中已经存在、视觉明确的锚点。

推荐：

```text
The figure stands at the center of the multi-ringed circular texture on the stone platform.
```

```text
The character stands just behind the front edge stones of the circular platform, aligned with the center ring pattern.
```

```text
The jade scroll lies on the empty wooden surface between the brush holder and the red seal, above the front edge of the table.
```

不推荐：

```text
The character stands in the center of the platform.
```

```text
The object is on the right side of the table.
```

```text
The figure stands near the pillar.
```

### 11.2 参考图引用必须绑定具体锚点

推荐：

```text
Use case_base_frame02.png for the platform layout, circular ring texture, pillar location, character boot placement, lava glow direction, and lighting state.
```

不推荐：

```text
Use case_base_frame02.png for the character position and scene.
```

### 11.3 不用 distance，用可见关系

控制人物与目标物远近时，禁止只写：

```text
closer to the pillar
farther from the pillar
reduced distance
near the object
move two steps forward
```

应写最终画面中的可见关系：

```text
The front boot is on the narrow stone band immediately around the circular pillar base.
```

```text
The boot toe almost touches the outer edge of the pillar base.
```

```text
No complete cobblestone ring is visible between the front boot and the pillar base.
```

核心原则：

```text
不描述“距离变化”，而描述“脚、手、道具与场景锚点之间的可见关系”。
```

## 12. 朝向关系规则

写每一帧 prompt 前，必须先判断两个关系：

1. **Subject–Object Relation**：人物面向目标物、背向目标物、侧对目标物，还是正在接触目标物；
2. **Subject–Camera Relation**：人物面向镜头、背对镜头、侧对镜头，还是过肩、俯视或局部。

这两个关系决定 prompt 应描述哪些身体细节，不能混写。

### 12.1 人物面向镜头时

可以描述：

- facial structure；
- eyes；
- gaze；
- front robe pattern；
- collar；
- chest；
- belt；
- sleeves；
- hands in front of the body。

### 12.2 人物背对镜头时

必须避免：

- facial structure；
- facial expression；
- calm face；
- eyes closed；
- focused expression；
- handsome face；
- looking at the camera。

应描述：

- back of hairstyle；
- back of head；
- shoulder line；
- back-view robe folds；
- waist belt from behind；
- sleeves from behind；
- boots；
- stable stance；
- target object in front of him。

### 12.3 可见与不可见结构

不要写：

```text
side profile partially visible
```

推荐写：

```text
Clearly show the back of his head, high topknot, rear shoulder line, back-view robe folds, waist belt from behind, sleeve shape, and boots. The eyes, nose, mouth, and side face are not visible because the back of the head, hair, and shoulder block the face from the camera.
```

核心原则：

```text
不描述“露一点侧脸”，而描述“镜头能看到哪些背面细节，以及哪些脸部结构不能出现”。
```

---

## 13. Camera Layer 规则

每一帧 prompt 必须包含 camera layer。

### 13.1 第一阶段 Camera Layer

第一阶段只允许明确使用：

```text
Camera: wide shot, ...
```

或：

```text
Camera: medium shot, ...
```

第一阶段禁止使用不确定表达：

```text
wide shot or medium shot
wide / medium shot
suitable camera distance
appropriate shot size
```

### 13.2 第二阶段 Camera Layer

第二阶段允许使用：

```text
close-up
insert shot
eye-level view
low-angle view
high-angle view
overhead view
over-the-shoulder view
back view
medium close-up
dynamic low-angle shot
```

但不能只写镜头术语，必须写清楚当前镜头下的可见内容。

推荐：

```text
Camera: insert shot, slightly high-angle view, the fingertips, sleeve cuffs, and glowing object surface fill most of the frame.
```

不推荐：

```text
Camera: insert shot.
```

### 13.3 镜头变换不改变剧情

第二阶段可以改变视角、景别、构图重点，但不能改变：

- 人物身份；
- 人物最终位置；
- 人物动作结果；
- 道具状态；
- 场景结构；
- 光源方向；
- 已经建立的剧情节点。

---

## 14. 禁止误导词规则

以下词在两个阶段都应尽量避免。

### 14.1 抽象距离词

不推荐：

```text
closer
farther
near
reduced distance
increased distance
```

推荐：

```text
front boot on the narrow stone band around the pillar base
```

```text
boot toe almost touching the outer edge of the pillar base
```

```text
several full cobblestone rings visible between the boots and the pillar base
```

### 14.2 模糊程度词

不推荐：

```text
slightly
subtly
a little
partially visible
```

推荐：

```text
only the back of the head and right shoulder are visible
```

```text
the eyes, nose, mouth, and side face are not visible
```

### 14.3 第一阶段选择式镜头词

基础帧 prompt 中禁止：

```text
wide shot or medium shot
wide / medium shot
either wide shot or medium shot
a suitable full or medium view
```

必须改成：

```text
Camera: wide shot, ...
```

或：

```text
Camera: medium shot, ...
```

### 14.4 非强情绪帧避免表情词

如果只是过渡帧，不要写痛苦、惊恐、愤怒、微微痛苦、略微紧张等容易被放大的表情词。

推荐：

```text
without emphasizing any exaggerated facial expression
```

## 16. 两阶段质检规则

### 16.1 第一阶段基础帧质检

检查：

- 是否使用唯一确定的 `wide shot` 或 `medium shot`；
- prompt 是否出现 `or`、`either`、`/` 这类选择式镜头表达；
- prompt 是否显式写明人物与镜头关系，例如 back view、front view、side view 或 three-quarter view；
- prompt 是否只写了人物面向目标物，却没有写人物面向镜头还是背对镜头；
- 当前帧是否遵循最小参考原则，是否存在不必要地重复引用 `case_char_01.png` 导致镜头拉近或人物转正的风险；
- 人物是否落在指定场景锚点；
- 人物全身或主要身体结构是否足够清楚；
- 场景结构是否完整稳定；
- 角色身份是否一致；
- 道具状态是否承接；
- 当前帧是否适合作为下一帧参考。

### 16.2 第二阶段镜头变换质检

检查：

- 是否从正确的 `case_base_frame0x.png` 派生；
- 是否保留基础帧的剧情状态；
- 是否保留人物身份、服装、发型；
- 是否保留道具状态和环境状态；
- 是否实现指定镜头变化；
- 镜头下应该可见的细节是否清楚；
- 镜头下不应该出现的结构是否没有出现；
- 是否比基础帧更适合作为最终电影镜头。

## 17. 重生成判定

### 17.1 基础帧需要重生成的情况

出现以下情况，应重生成基础帧：

- prompt 中使用了不确定镜头表达；
- prompt 没有显式写明人物与镜头关系；
- 候选图中人物应背对镜头却变成正对镜头，或应侧对镜头却变成正面展示；
- 当前帧只是连续移动，却不必要地引用 `case_char_01.png` 并导致镜头拉近、人物转正或构图改变；
- 画面不是指定的 `wide shot` 或 `medium shot`；
- 人物位置没有对齐场景锚点；
- 人物身份、服装、发型明显变化；
- 场景结构被错误改变；
- 道具状态不符合剧情；
- 人物朝向与目标物关系错误；
- 当前帧镜头过于复杂，不适合作为下一帧参考；
- 基础帧人物与镜头关系错误，尤其是应为背影却露出正脸；
- 基础帧参考图选择不合理，导致本应继承上一帧的镜头尺度和朝向被破坏。

### 17.2 镜头变换帧需要重生成的情况

出现以下情况，应重生成派生帧：

- 镜头变换没有成功；
- 变换后改变了剧情状态；
- 变换后人物位置变化；
- 变换后道具状态变化；
- 变换后角色身份不一致；
- 特写或局部镜头没有展示该镜头应有的细节；
- 背面或过肩镜头错误露出正脸；
- 新增无关角色、武器、道具或环境效果。

## 18. 核心执行口令

### 18.1 第一阶段基础帧生成前必须先问

1. What is the story beat of this base frame?
2. Is this base frame a wide shot or a medium shot?
3. Is the selected shot type written as one confirmed camera choice?
4. What real filenames should be referenced?
5. What specific anchors should be inherited from each file?
6. What scene anchor locates the character or object?
7. What is the final visible position, not the movement process?
8. What is the subject-object relation?
9. What is the subject-camera relation?
10. What should remain visible for future reference?
11. Does this frame avoid close-up, insert shot, overhead view, over-the-shoulder view, and complex camera rotation?
12. Does this frame provide a stable reference for the next base frame?

### 18.2 第二阶段镜头变换前必须先问

1. Which base frames are visually stable enough for transformation?
2. Which base frames contain key actions, key objects, or key emotional moments?
3. Which base frames should remain unchanged because they need to preserve spatial clarity?
4. What camera transformation best strengthens this selected base frame?
5. What exact story state must be preserved from the base frame?
6. What visible details should the transformed shot emphasize?
7. What structures should not appear in this transformed shot?
8. Does the transformed shot improve the final storyboard without changing the story?

## 19. 一句话总结

v6.0 的核心不是让九宫格一开始就拥有复杂镜头，而是：

```text
First generate stable wide-shot or medium-shot base frames to lock story continuity, then let the multimodal model select suitable frames for independent camera transformation.
```

中文概括：

```text
先用明确全景或明确中景生成稳定剧情骨架，再由多模态模型选择关键帧做独立镜头变换；连续性由基础帧负责，电影感由派生帧负责。
```
